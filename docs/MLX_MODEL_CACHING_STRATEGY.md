# Стратегия кэширования моделей MLX API Server

**Дата:** 26.01.2026  
**Вопрос:** Если модель выгружена, будет ли она долго загружаться при следующем запросе?

---

## 🎯 Проблема

При нехватке памяти модели выгружаются из кэша. При следующем запросе модель нужно загрузить заново, что занимает время:

- **Малые модели (3-7B):** 5-15 секунд
- **Средние модели (32B):** 20-40 секунд
- **Большие модели (70B+):** 60-120+ секунд

---

## ✅ Решение: LRU (Least Recently Used) стратегия

### Что изменилось:

1. **Отслеживание использования моделей**
   - `use_count` — сколько раз модель использовалась
   - `last_used` — время последнего использования
   - `loaded_at` — время загрузки
   - `load_time_seconds` — сколько времени заняла загрузка

2. **Умная очистка (LRU)**
   - При очистке оставляются **самые часто используемые** модели
   - Сортировка: сначала по `use_count` (по убыванию), затем по `last_used`
   - По умолчанию оставляется 1 модель (самая используемая)

3. **Информация о загрузке**
   - Логируется время загрузки каждой модели
   - В health check показывается статистика использования

---

## 📊 Как это работает

### Сценарий 1: Обычная очистка (85-95% памяти)

**До очистки:**

- `qwen2.5-coder-32b` — использована 50 раз
- `phi3.5-mini-4k` — использована 5 раз
- `deepseek-r1-70b` — использована 2 раза

**После очистки:**

- ✅ Остается: `qwen2.5-coder-32b` (самая используемая)
- 🗑️ Выгружены: `phi3.5-mini-4k`, `deepseek-r1-70b`

**При следующем запросе:**

- `qwen2.5-coder-32b` → **мгновенно** (уже в кэше)
- `phi3.5-mini-4k` → **20-30 секунд** (нужна загрузка)
- `deepseek-r1-70b` → **60-120 секунд** (нужна загрузка)

### Сценарий 2: Экстренная очистка (>98% памяти)

**До очистки:**

- Все модели в кэше

**После очистки:**

- 🗑️ Выгружены **ВСЕ** модели

**При следующем запросе:**

- Любая модель → **нужна загрузка** (время зависит от размера)

## ⚡ Оптимизация времени загрузки

### 1. **Предзагрузка популярных моделей**

Можно добавить предзагрузку при старте сервера:

```python
# В __main__ после запуска uvicorn
async def preload_popular_models():
    popular_models = ["default", "coding", "fast"]  # Самые используемые
    for model_key in popular_models:
        try:
            get_model(model_key)
            logger.info(f"✅ Предзагружена модель: {model_key}")
        except Exception as e:
            logger.warning(f"⚠️ Не удалось предзагрузить {model_key}: {e}")
```

### 2. **Асинхронная загрузка в фоне**

Можно загружать модель асинхронно, пока обрабатывается другой запрос:

```python
# При запросе модели, которая не в кэше
if model_key not in _models_cache:
    # Загружаем в фоне (если есть свободная память)
    if memory_info["used_percent"] < 0.7:  # 70% - есть запас
        asyncio.create_task(load_model_async(model_key))
```

### 3. **Кэширование на диске (если возможно)**

MLX модели уже оптимизированы, но можно добавить:

- Кэширование tokenizer отдельно
- Предзагрузка весов в память GPU (если доступно)

## 📈 Рекомендации

### Для минимального времени загрузки:

1. **Используйте одну основную модель**
   - Если основная задача — кодинг, используйте только `qwen2.5-coder-32b`
   - Она останется в кэше при очистке памяти

2. **Мониторьте использование**

   ```bash
   # Проверяйте, какие модели используются чаще
   curl http://localhost:11435/ | jq '.cached_models | sort_by(.use_count) | reverse'
   ```

3. **Настройте пороги памяти**
   - Если у вас много RAM, можно увеличить `_memory_warning_threshold`
   - Это позволит держать больше моделей в кэше

4. **Предзагрузка при старте**
   - Добавьте предзагрузку 1-2 самых популярных моделей
   - Они будут готовы к использованию сразу

---

## 🎯 Итог

**Да, модель будет загружаться заново**, но:

✅ **Плюсы:**

- Самые используемые модели остаются в кэше
- Время загрузки логируется для анализа
- Можно оптимизировать, предзагружая популярные модели

⚠️ **Минусы:**

- Первый запрос после выгрузки займет время (5-120 секунд)
- Большие модели загружаются долго

💡 **Решение:**

- Используйте одну основную модель для большинства задач
- Предзагружайте популярные модели при старте
- Мониторьте использование через health check
