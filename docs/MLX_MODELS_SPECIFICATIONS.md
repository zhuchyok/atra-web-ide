## 📋 Детальное описание

### 1. **command-r-plus:104b** (~65GB)

**Характеристики:**

- **Размер на диске:** ~65GB
- **RAM при загрузке:** ~70-75GB (с учетом tokenizer и буферов)
- **Время загрузки:** 90-150 секунд (1.5-2.5 минуты)

- **Автовыбор:** ✅ `complex`, `enterprise`

**Особенности:**

- Самая большая модель в коллекции
- Требует много памяти (почти вся доступная RAM на 128GB системе)

- Используется редко, только для критических задач

**Рекомендации:**

- Загружать только при необходимости
- Не держать в памяти постоянно
- Использовать для сложных enterprise задач

## 🔄 Стратегия загрузки

### ✅ Реализовано: Предзагрузка основных моделей

**Модели, которые загружаются автоматически при старте:**

1. **`qwen2.5-coder:32b`** (default) — ~25GB RAM, 25-40с загрузка
   - ⭐ Основная модель, используется чаще всего
   - Для кодинга и общих задач высокого качества

2. **`phi3.5:3.8b`** (fast) — ~4GB RAM, 5-10с загрузка
   - ⚡ Быстрая модель для общих задач
   - Хорошее качество при малом размере

3. **`tinyllama:1.1b-chat`** (tiny) — ~1.5GB RAM, 2-5с загрузка
   - 🚀 Очень быстрая модель для простых задач
   - Можно использовать параллельно с другими

**Итого предзагрузка:** ~30.5GB RAM (24% от 128GB)

### Настройка предзагрузки

**Переменная окружения:** `MLX_PRELOAD_MODELS`

**По умолчанию:** `default,fast,tiny`

**Примеры:**

```bash
# Только default модель
export MLX_PRELOAD_MODELS="default"

# Default + fast
export MLX_PRELOAD_MODELS="default,fast"

# Отключить предзагрузку
export MLX_PRELOAD_MODELS=""

# Кастомный набор
export MLX_PRELOAD_MODELS="default,coding,fast"
```

### Логика предзагрузки

- ✅ Проверка памяти перед загрузкой (не загружает, если >70%)
- ✅ Остановка при достижении 75% использования памяти
- ✅ Пропуск уже загруженных моделей
- ✅ Асинхронная загрузка (не блокирует запуск сервера)
- ✅ Логирование процесса предзагрузки

### Дополнительные модели (по требованию)

**Загружаются при первом запросе:**

- Большие модели (70B, 104B) — только при необходимости
- Специализированные модели (reasoning) — по требованию

## 💾 Использование памяти

### Максимальная нагрузка

**Если загрузить все модели одновременно:**

- Общий размер: ~65 + 40 + 40 + 20 + 2.5 + 2 + 2 + 0.7 = **~172GB**
- С учетом overhead: **~180-190GB**
- ❌ **Невозможно на 128GB системе!**

### Реалистичная нагрузка

**Типичный сценарий:**

- `qwen2.5-coder:32b` (default): ~25GB
- `phi3.5:3.8b` (fast): ~4GB
- `tinyllama:1.1b-chat` (ultra-fast): ~1.5GB
- **Итого:** ~30.5GB (24% от 128GB)

**Максимальный сценарий:**

- `qwen2.5-coder:32b`: ~25GB
- `deepseek-r1-70b`: ~50GB
- `phi3.5:3.8b`: ~4GB
- **Итого:** ~79GB (62% от 128GB)

## 🎯 Рекомендации по использованию

### Для минимального времени отклика:

1. **Предзагрузить при старте:**
   - `qwen2.5-coder:32b` (default, используется чаще всего)
   - `phi3.5:3.8b` или `tinyllama:1.1b-chat` (быстрые модели)

2. **Держать в памяти:**
   - Малые модели (<5GB) можно держать постоянно
   - Средние модели (20-32GB) — по необходимости
   - Большие модели (70B+) — только при использовании

3. **Мониторинг:**
   - Использовать health check для отслеживания загруженных моделей
   - Следить за использованием памяти
   - Автоматическая очистка при нехватке памяти
