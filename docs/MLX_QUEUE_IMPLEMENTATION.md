## 📊 Как это работает

### Приоритеты:

1. **HIGH** - Чат с Викторией
   - Обрабатывается первым
   - Не блокируется Task Distribution
   - Источник: Extended Thinking, Local Router (для чатов)

2. **MEDIUM** - Task Distribution
   - Обрабатывается после HIGH
   - Может подождать, если все слоты заняты
   - Источник: ReActAgent (сотрудники)

3. **LOW** - Фоновые задачи
   - Обрабатывается последним
   - Для будущего использования

### Логика работы:

```
Запрос → MLX API Server
  ↓
Проверка приоритета (X-Request-Priority)
  ↓
Добавление в очередь с приоритетом
  ↓
Обработка по приоритету:
  - HIGH обрабатываются первыми
  - MEDIUM обрабатываются после HIGH
  - LOW обрабатываются последними
  ↓
Выполнение (max_concurrent = 5)
```

## 🔧 Настройка

### Переменные окружения:

```bash
MLX_MAX_CONCURRENT=5        # Максимум параллельных запросов
MLX_MAX_QUEUE_SIZE=50      # Максимум запросов в очереди
```

### Заголовки запросов:

```http
X-Request-Priority: high    # Для чатов с Викторией
X-Request-Priority: medium  # Для Task Distribution (по умолчанию)
X-Request-Priority: low     # Для фоновых задач
```

## ❓ Ответ на вопрос: Чат с Викторией в очереди?

**ДА, но с приоритетом HIGH:**

1. **Чат с Викторией** попадает в очередь с приоритетом HIGH
2. **Обрабатывается первым** при освобождении слота
3. **Task Distribution** (MEDIUM) ждет, если все слоты заняты чатом
4. **Не блокируется** Task Distribution - чат всегда получает приоритет

### Пример работы:

```
Сценарий: 3 чата + 5 задач Task Distribution

Очередь:
1. Чат 1 (HIGH) → выполняется сразу
2. Чат 2 (HIGH) → выполняется сразу
3. Чат 3 (HIGH) → выполняется сразу
4. Задача 1 (MEDIUM) → выполняется сразу (есть свободный слот)
5. Задача 2 (MEDIUM) → выполняется сразу (есть свободный слот)
6. Задача 3 (MEDIUM) → в очереди (все слоты заняты)
7. Задача 4 (MEDIUM) → в очереди
8. Задача 5 (MEDIUM) → в очереди

Когда освобождается слот:
- Сначала обрабатываются HIGH (чаты)
- Затем MEDIUM (Task Distribution)
```
