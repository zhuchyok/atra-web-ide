# Стратегия предзагрузки моделей MLX API Server

**Дата:** 26.01.2026  
**Цель:** Минимизировать задержки при запросах к моделям

---

## 🎯 Выбранные модели для предзагрузки

### ✅ Модели, которые предзагружаются автоматически:

1. **`qwen2.5-coder:32b`** (default)
   - **RAM:** ~25GB
   - **Загрузка:** 25-40 секунд
   - **Причина:** Основная модель, используется чаще всего (default, coding)

2. **`phi3.5:3.8b`** (fast)
   - **RAM:** ~4GB
   - **Загрузка:** 5-10 секунд
   - **Причина:** Быстрая модель для общих задач, хорошее качество

3. **`tinyllama:1.1b-chat`** (tiny)
   - **RAM:** ~1.5GB
   - **Загрузка:** 2-5 секунд
   - **Причина:** Очень быстрая модель для простых задач, минимум памяти

**Итого:** ~30.5GB RAM (24% от 128GB)

---

## 📊 Обоснование выбора

### Почему эти модели?

1. **`qwen2.5-coder:32b`** — используется как default
   - Большинство запросов идут на эту модель
   - 25-40 секунд загрузки — заметная задержка
   - 20GB на диске, но используется постоянно

2. **`phi3.5:3.8b`** — баланс скорости и качества
   - Быстрая загрузка (5-10 сек)
   - Хорошее качество для общих задач
   - Мало памяти (4GB)

3. **`tinyllama:1.1b-chat`** — для параллельной работы
   - Очень быстрая (2-5 сек)
   - Минимум памяти (1.5GB)
   - Можно использовать параллельно с другими

### Почему НЕ предзагружаем большие модели?

- **`command-r-plus:104b`** (65GB) — слишком большая, используется редко
- **`deepseek-r1-70b`** (40GB) — используется только для reasoning
- **`llama3.3:70b`** (40GB) — используется только для complex задач

**Причина:** Эти модели занимают много памяти и используются редко. Лучше загружать по требованию.

## ⚙️ Настройка предзагрузки

### Переменная окружения: `MLX_PRELOAD_MODELS`

**Формат:** `категория1,категория2,категория3`

**Доступные категории:**

- `default` → `qwen2.5-coder:32b`
- `fast` → `phi3.5:3.8b`
- `tiny` → `tinyllama:1.1b-chat`
- `coding` → `qwen2.5-coder:32b`

**По умолчанию:** `default,fast,tiny`

### Примеры настройки

```bash
# Только default модель (экономия памяти)
export MLX_PRELOAD_MODELS="default"

# Default + fast (рекомендуется)
export MLX_PRELOAD_MODELS="default,fast"

# Все три модели (по умолчанию)
export MLX_PRELOAD_MODELS="default,fast,tiny"

# Отключить предзагрузку
export MLX_PRELOAD_MODELS=""

# Кастомный набор
export MLX_PRELOAD_MODELS="default,coding"
```

### В docker-compose или .env

```env
# .env файл
MLX_PRELOAD_MODELS=default,fast,tiny
```

## 🔄 Как это работает

### При старте сервера:

1. **Проверка памяти**
   - Если использование >70% → предзагрузка отменяется
   - Защита от перегрузки при старте

2. **Последовательная загрузка**
   - Загружаются модели по очереди
   - После каждой загрузки проверяется память
   - Если память >75% → останавливается

3. **Асинхронная загрузка**
   - Предзагрузка не блокирует запуск сервера
   - Сервер готов к запросам сразу
   - Модели загружаются в фоне

4. **Логирование**
   - Все этапы логируются
   - Видно, какие модели загружены
   - Видно использование памяти

### Пример логов:


## 📈 Преимущества

### ✅ До предзагрузки:

- Первый запрос: **25-40 секунд** ожидания (загрузка default модели)
- Быстрые запросы: **5-10 секунд** ожидания (загрузка fast модели)

### ✅ После предзагрузки:

- Первый запрос: **мгновенно** (модель уже в памяти)
- Быстрые запросы: **мгновенно** (модель уже в памяти)
- Большие модели: **60-150 секунд** (загружаются по требованию)

### 💾 Использование памяти:

**До предзагрузки:** ~0GB (модели не загружены)  
**После предзагрузки:** ~30.5GB (3 модели)  
**Доступно:** ~97.5GB (76% свободно)

**Вывод:** Предзагрузка использует только 24% памяти, но убирает задержки для 80%+ запросов.

## 🎯 Рекомендации

### Для минимальных задержек:

1. **Оставить предзагрузку по умолчанию** (`default,fast,tiny`)
   - Покрывает большинство запросов
   - Использует разумное количество памяти

2. **Мониторить использование**

   ```bash
   curl http://localhost:11435/health | jq '.cached_models'
   ```

3. **Настроить под нагрузку**
   - Если много coding задач → добавить `coding` в предзагрузку
   - Если мало памяти → оставить только `default`

### Для экономии памяти:

```bash
# Только самая важная модель
export MLX_PRELOAD_MODELS="default"
```

### Для максимальной скорости:

```bash
# Все быстрые модели
export MLX_PRELOAD_MODELS="default,fast,tiny,coding"
```

## ⚠️ Ограничения

1. **Память**
   - Предзагрузка использует ~30GB
   - На 128GB системе это нормально
   - На системах с меньшей памятью нужно уменьшить набор

2. **Время старта**
   - Предзагрузка занимает ~40-50 секунд
   - Но не блокирует запуск сервера
   - Сервер готов к запросам сразу

3. **Большие модели**
   - 70B и 104B модели не предзагружаются
   - Загружаются по требованию
   - Это правильно — они используются редко
