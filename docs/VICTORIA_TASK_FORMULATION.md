# Постановка задачи Victoria Agent: SEO-анализ setki21.ru

## 📝 Формулирование задачи (Goal)

### Структура хорошей задачи:

```
1. ЧТО делать (главная цель)
2. ГДЕ/НАД ЧЕМ (объект анализа)
3. КАК (методология, что проверять)
4. ЧТО НА ВЫХОДЕ (формат результата)
```

### Пример для SEO-анализа:

```json
{
  "goal": "Проведи полный SEO-анализ сайта www.setki21.ru.

  Учти, что были внесены изменения после предыдущего аудита.

  ПРОВЕРЬ:
  1. Метатеги (title, description, keywords)
  2. Open Graph и социальные сети
  3. Структуру URL
  4. Sitemap.xml и robots.txt
  5. Schema.org разметку (Organization, Product, FAQPage, etc.)
  6. Alt-теги для изображений
  7. Заголовки H1-H6
  8. Качество контента и внутреннюю перелинковку

  СРАВНИ с предыдущим аудитом:
  - Прочитай docs/audits/2026-03-06-setki21-seo-audit.md
  - Отметь, что изменилось (улучшилось/ухудшилось)
  - Укажи новые проблемы, если есть

  СОЗДАЙ ОТЧЁТ:
  - Файл: docs/audits/2026-03-06-setki21-seo-audit-v2.md
  - Формат: Markdown с таблицами и примерами кода
  - Структура: Изменения → Текущее состояние → Рекомендации",

  "project_context": "setki-21",
  "max_steps": 50
}
```

## 🔧 Параметры запроса

### Обязательные параметры:

**1. `goal` (string)** — Текст задачи

- **Минимум:** 1 предложение ("Проверь статус backend")
- **Оптимум:** Структурированная задача с пунктами
- **Максимум:** Нет жёсткого лимита, но >2000 символов — разбить на подзадачи

**2. `max_steps` (integer)** — Ограничение шагов ReAct цикла

- **Простая задача:** 5-10 шагов (приветствие, статус)
- **Средняя задача:** 20-30 шагов (анализ файла, поиск информации)
- **Сложная задача:** 50-100 шагов (рефакторинг, SEO-анализ)
- **Дефолт:** 500 (если не указано)

### Опциональные параметры:

**3. `project_context` (string)** — Контекст проекта

- Примеры: `"atra-web-ide"`, `"setki-21"`, `"atra"`
- Помогает Victoria понять, в каком проекте работать
- Влияет на RAG поиск (приоритет документам этого проекта)

**4. `session_id` (string)** — ID сессии для Long-Term Memory

- Используется для сохранения истории диалога
- Если не указан — генерируется автоматически
- Полезно для многошаговых диалогов

**5. `chat_history` (array)** — История предыдущих сообщений

- Формат: `[{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]`
- Даёт Victoria контекст беседы

**6. `verbose` (boolean)** — Подробный вывод шагов

- `true` — вернёт все шаги агента (thought, tool, observation)
- `false` (дефолт) — только итоговый результат
- Полезно для отладки

**7. `use_enhanced` (boolean)** — Принудительно использовать Victoria Enhanced

- `true` — всегда через Enhanced Orchestrator (86 экспертов)
- `false` — только базовый агент
- `null` (дефолт) — автоматический выбор по задаче

**8. `return_execution_plan` (boolean)** — Вернуть execution plan

- `true` — Victoria вернёт план действий для выполнения в IDE
- `false` (дефолт) — обычный ответ
- Используется для делегирования "рук" в IDE

## 🌊 Выбор endpoint'а

### POST /run (синхронный)

```bash
curl -X POST http://localhost:8010/run \
  -H "Content-Type: application/json" \
  -d '{
    "goal": "...",
    "max_steps": 20
  }'
```

**Когда использовать:**

- Простые запросы (до 1-2 минут)
- Не важно видеть прогресс
- Нужен только финальный результат

**Плюсы:** Простой JSON ответ  
**Минусы:** Нет промежуточных обновлений, может показаться "зависшим"

---

### POST /stream (SSE streaming)

```bash
curl -N -X POST http://localhost:8010/stream \
  -H "Content-Type: application/json" \
  -d '{
    "goal": "...",
    "max_steps": 50
  }'
```

**Когда использовать:**

- Сложные задачи (более 2 минут)
- Хочу видеть прогресс
- Важна отзывчивость (heartbeat каждые 10 сек)

**Плюсы:**

- Видны промежуточные шаги
- Heartbeat предотвращает обрывы
- Можно прервать при необходимости

**Минусы:** Нужно парсить SSE события

**Формат SSE событий:**

```
data: {"type": "start", "expert": "Виктория"}
data: {"type": "step", "stepType": "thought", "title": "Анализ задачи", "content": "..."}
data: {"type": "step", "stepType": "action", "title": "Чтение файла", "content": "..."}
data: {"type": "progress", "step": 5, "total": 10}
data: {"type": "done", "result": "..."}
```

---

### POST /orchestrate (с execution plan)

```bash
curl -X POST http://localhost:8010/orchestrate \
  -H "Content-Type: application/json" \
  -d '{
    "goal": "...",
    "return_execution_plan": true
  }'
```

**Когда использовать:**

- Задачи, требующие изменения файлов
- Victoria планирует, IDE выполняет
- "Мозг и руки" разделены

**Плюсы:** Victoria не нужен доступ к файловой системе  
**Минусы:** Требуется исполнитель плана (MCP или скрипт)

## 🎯 Для SEO-анализа выбираю /stream

**Почему:**

1. ✅ Задача сложная (10-15 минут)
2. ✅ Хочу видеть прогресс (какие шаги выполняются)
3. ✅ SSE heartbeat предотвратит обрывы (исправленные таймауты)
4. ✅ Можно мониторить в реальном времени

## ⚡ Оптимизация запроса

### ❌ Плохая постановка задачи:

```json
{
  "goal": "Проверь сайт",
  "max_steps": 500
}
```

**Проблемы:**

- Непонятно, какой сайт
- Непонятно, что проверять
- Слишком много шагов (Victoria будет искать дополнительный контекст)

### ✅ Хорошая постановка задачи:

```json
{
  "goal": "Проведи SEO-анализ www.setki21.ru. Проверь метатеги, Schema.org, alt-теги. Сравни с docs/audits/2026-03-06-setki21-seo-audit.md. Создай отчёт в docs/audits/2026-03-06-setki21-seo-audit-v2.md",
  "project_context": "setki-21",
  "max_steps": 50
}
```

**Преимущества:**

- Конкретный сайт (www.setki21.ru)
- Чёткий список проверок
- Указан файл для сравнения
- Указан путь для отчёта
- Ограничение шагов (50 — достаточно, но не избыточно)
- Контекст проекта (RAG найдёт релевантные документы)
