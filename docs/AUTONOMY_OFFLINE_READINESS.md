# Оценка готовности к автономности и работе без интернета

**Дата:** 2026-02-23  
**Цель:** Понять, насколько проект готов к полностью автономной работе и работе без доступа в интернет (закрытые сети, конфиденциальные данные, «цифровая крепость»).

Связанные документы: **MASTER_REFERENCE.md** (STRICT_LOCAL), **AUTONOMY_VERIFICATION.md**, **CHANGES_FROM_OTHER_CHATS.md** §43, §53–61, **INVENTORY_VICTORIA_CAPABILITIES_2026.md**.

## 1. Краткий вердикт

| Аспект                                          | Готовность                   | Комментарий                                                                                                             |
| ----------------------------------------------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **Ядро чата / LLM**                             | ✅ Готово                    | STRICT_LOCAL + MLX + Ollama; без облака и cursor-agent.                                                                 |
| **Эмбеддинги (RAG, кэш)**                       | ⚠️ Частично                  | Ollama (semantic_cache) — локально; VectorCore (8001) и main.py — при недоступности 8001 RAG в части эндпоинтов падает. |

| **Зависимости (pip/npm)**                       | ✅ Без интернета после setup | Установка — из requirements.txt при развёртывании; в рантайме pip install только в force_worker (asyncpg) — исключение. |

## 2. Что уже работает без интернета

### 2.1 Режим STRICT_LOCAL

- **Включение:** `STRICT_LOCAL=true` в `.env` для victoria-agent (см. MASTER_REFERENCE, раздел STRICT_LOCAL).
- **Поведение:** Все запросы обслуживаются только локальными моделями (MLX 11435, Ollama 11434). Нет fallback на cursor-agent или облачные API. При недоступности локальных моделей — явная ошибка с подсказкой про Recovery (9099).
- **Модули:** ai_core, safety_checker, quality_assurance, intelligence_consensus, disaster_recovery — при STRICT_LOCAL блокируют облако и повторяют попытки локально с улучшенным промптом; при неудаче — reject.

### 2.2 Локальный стек

- **MLX** (11435), **Ollama** (11434) — инференс и эмбеддинги (Ollama: nomic-embed-text в semantic_cache).
- **PostgreSQL** (5432) + **Redis** — состояние, кэш, knowledge_nodes, RAG.
- **Victoria Agent** (8010), **Veronica** (8011) — в Docker, общаются с MLX/Ollama и БД.
- **Recovery Listener** (9099) на хосте — по webhook запускает system_auto_recovery.sh (в т.ч. проверка Ollama после sleep, блок «без интернета» в скрипте).
- **Rust Gateway** (8081) — чат через Ollama/Victoria, RAG по БД; см. AUTONOMY_VERIFICATION.md.

### 2.3 Эмбеддинги (локальный путь)

- **semantic_cache** — эмбеддинги через Ollama (`OLLAMA_EMBED_URL`, nomic-embed-text). Используется во многих модулях (experience_retriever, model_enhancer, graphrag, corporation_complete_knowledge и др.). **Работает без интернета**, если Ollama доступен.

### 2.4 Зависимости

- Установка пакетов — по требованиям проекта: `requirements.txt`, скрипты setup (например `knowledge_os/scripts/setup_knowledge_os.sh`). В рантайме установка пакетов не предполагается (по .cursorrules). **Исключение:** `knowledge_os/app/force_worker.py` — при старте вызывает `pip install asyncpg`; в полностью офлайн среде это нужно заменить на проверку наличия пакета и явную ошибку или предустановленный asyncpg.

## 3. Что тянется в облако или требует интернет

### 3.1 Веб-поиск

- **web_search_fallback.py:** провайдеры по умолчанию `duckduckgo,ollama`. DuckDuckGo — интернет. «Ollama» здесь — вызов **https://ollama.com/api/web_search** (облачный API Ollama), не локальный инстанс. При полном офлайн веб-поиск недоступен.
- **Рекомендация:** Для офлайн либо отключить веб-поиск (не вызывать его при STRICT_LOCAL / флаге offline), либо добавить режим «только локальный RAG» без внешних провайдеров.

### 3.2 VectorCore (порт 8001)

- **knowledge_os/app/main.py:** `get_embedding()` ходит в `http://localhost:8001` (VectorCore). Используется для поиска по эмбеддингам и при добавлении контента в БД. Если VectorCore не поднят или недоступен — эти эндпоинты падают по ошибке запроса.
- **Рекомендация:** Либо поднимать VectorCore локально в офлайн-контуре, либо добавить fallback на `semantic_cache.get_embedding` (Ollama), когда 8001 недоступен, чтобы RAG и поиск работали без интернета.

### 3.3 Дополнение ответов (GitHub, Stack Overflow)

- **external_api_integration.py:** `enhance_response_with_external_data` — запросы к GitHub/Stack Overflow. Вызов в ai_core обёрнут в try/except; при недоступности ответ пользователю не ломается, просто не дополняется. Для офлайн допустимо оставить как есть (опциональное улучшение).

### 3.4 Telegram и SSH

- **external_integrations.py, telegram_gateway:** отправка алертов в Telegram, удалённые команды по SSH. Требуют интернет/сеть к серверам. Не входят в ядро чата/RAG; при офлайн алерты и удалённые команды просто недоступны.

### 3.5 Проверка доступности интернета

- **network_resilience.py:** проверка интернета через DNS (8.8.8.8 и др.) и http://www.google.com. Используется для декоратора и retry; при офлайн проверка будет отрицательной, что корректно для режима «без интернета».

## 4. Pre-flight чеклист для работы без интернета

Перед включением полностью автономного/офлайн режима:

1. **STRICT_LOCAL=true** в окружении victoria-agent.
2. **MLX:** `curl -s http://localhost:11435/health` → 200.
3. **Ollama:** `curl -s http://localhost:11434/api/tags` → 200, нужные модели (в т.ч. для эмбеддингов) присутствуют.
4. **Recovery Listener:** `curl -s http://localhost:9099/recover` → 200 (критично при STRICT_LOCAL; см. MASTER_REFERENCE и INVENTORY §6).
5. **PostgreSQL и Redis** доступны (порты 5432, 6379).
6. **Эмбеддинги:** либо поднят VectorCore (8001), либо в коде предусмотрен fallback на Ollama (semantic_cache) для всех путей, использующих get_embedding в main.py.
7. **Веб-поиск:** отключён или не вызывается в офлайн-режиме (конфиг/флаг).
8. **force_worker:** при необходимости офлайн — убрать или заменить runtime `pip install asyncpg` на проверку и явную ошибку.

## 5. Рекомендации для полной офлайн-готовности

| Приоритет | Задача                                                                                                                                                                                | Ожидаемый результат                                                            |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 1         | В main.py (и при необходимости в telegram_gateway, search_ml_trading и т.д.) при недоступности VectorCore (8001) использовать **semantic_cache.get_embedding** (Ollama) как fallback. | RAG и поиск работают без интернета при работающем Ollama, даже без VectorCore. |
| 2         | Ввести флаг **OFFLINE_MODE** или при **STRICT_LOCAL** не вызывать веб-поиск (duckduckgo/ollama.com); при необходимости подставлять только локальный RAG.                              | Нет обращений к интернету из веб-поиска.                                       |
| 3         | В **force_worker.py** убрать вызов `pip install asyncpg` при старте; проверять импорт и при отсутствии — логировать ошибку и не запускать воркер или падать с понятным сообщением.    | Нет запросов к PyPI в рантайме.                                                |
| 4         | Задокументировать в MASTER_REFERENCE и runbook: «офлайн-режим» = STRICT_LOCAL + чеклист из §4 + отключённый веб-поиск + fallback эмбеддингов на Ollama.                               | Воспроизводимая настройка для закрытых сетей.                                  |

## 6. Итоговая шкала готовности

- **Только чат + планирование (Victoria/Veronica, MLX/Ollama, без RAG в main):** **9/10** — готово при STRICT_LOCAL и работающих MLX/Ollama/Recovery.
- **Чат + RAG по knowledge_nodes (при fallback эмбеддингов на Ollama или при работающем VectorCore):** **8/10** — после внедрения fallback эмбеддингов или запуска VectorCore локально.
- **Полная автономность (включая отключение веб-поиска и отсутствие pip в рантайме):** **7/10** — достижимо после выполнения рекомендаций §5.

Обновления этой оценки фиксировать в CHANGES_FROM_OTHER_CHATS.md (раздел «Автономность / офлайн»).
