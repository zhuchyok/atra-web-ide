## 🔄 КАК СЕЙЧАС РАБОТАЕТ ОРКЕСТРАЦИЯ

### **Процесс распределения задач:**

```
1. Задача создается
   ↓
2. Enhanced Orchestrator находит задачу без исполнителя
   ↓
3. Определяет domain_id (домен знаний)
   ↓
4. Ищет экспертов по домену:
   - Если domain_id → эксперты из этого домена
   - Если required_role → эксперты с этой ролью
   - Иначе → все эксперты
   ↓
5. Оценивает каждого эксперта:
   - Загрузка (workload_score)
   - Успешность (success_rate)
   - Время выполнения
   ↓
6. Выбирает лучшего эксперта
   ↓
7. Назначает задачу в БД
   ↓
8. Smart Worker обрабатывает задачу
   ↓
9. Эксперт выполняет изолированно
   ↓
10. Результат сохраняется
```

### **Как распределяется:**

1. **По домену (domain_id):**

   ```python
   # Если задача имеет domain_id
   candidates = await conn.fetch("""
       SELECT id, name, role, department
       FROM experts
       WHERE department = (SELECT name FROM domains WHERE id = $1)
   """, domain_id)
   ```

2. **По роли (required_role):**

   ```python
   # Если указана роль
   candidates = await conn.fetch("""
       SELECT id, name, role, department
       FROM experts
       WHERE role ILIKE $1
   """, f"%{required_role}%")
   ```

3. **Без ограничений:**
   ```python
   # Если нет ограничений - все эксперты
   candidates = await conn.fetch("""
       SELECT id, name, role, department
       FROM experts
   """)
   ```

### **Проблема:**

❌ **Нет иерархиии по департаментам:**

- Все эксперты на одном уровне
- Нет Department Heads
- Нет координации внутри отделов
- Victoria не участвует в распределении

## 🎯 КАК ДОЛЖНО БЫТЬ (ПРЕДЛАГАЕТСЯ)

### **Victoria как главный оркестратор:**

```
Задача → Victoria анализирует
         ↓
    Определяет отдел(ы)
         ↓
    Выбирает стратегию:
    - Simple → Один эксперт
    - Complex → Swarm (3-5 экспертов)
    - Multi-Dept → Иерархия отделов
         ↓
    Распределяет по департаментам:
    - Backend задача → Backend Department
    - ML задача → ML Department
    - Межотдельная → Несколько отделов
         ↓
    Собирает ответы
         ↓
    Синтезирует финальный результат
```

### **Иерархия по департаментам:**

```
Victoria (Team Lead)
│
├── Backend Department
│   ├── Игорь (Head/Backend Developer)
│   ├── Даниил (Principal Backend Architect)
│   └── Роман (Database Engineer)
│
├── ML Department
│   ├── Дмитрий (Head/ML Engineer)
│   ├── Александр Нейман (Principal AI Architect)
│   └── Максим (Data Analyst)
│
├── DevOps Department
│   ├── Сергей (Head/DevOps Engineer)
│   └── Елена (Monitor)
│
└── ...
```

### **Процесс:**

1. **Victoria получает задачу**
2. **Анализирует:** категория, сложность, отделы
3. **Определяет отдел(ы):**
   - "создай API" → Backend Department
   - "настрой ML модель" → ML Department
   - "комплексное решение" → Несколько отделов
4. **Выбирает стратегию:**
   - Простая → Один эксперт отдела
   - Сложная → Swarm экспертов отдела
   - Межотдельная → Координация через Department Heads
5. **Собирает ответы**
6. **Синтезирует финальный результат**

## 📊 ТЕКУЩАЯ СИТУАЦИЯ VS ПРЕДЛАГАЕМАЯ

### **Сейчас:**

```
Задача → Orchestrator → Выбор эксперта (по домену/роли)
                      → Назначение в БД
                      → Smart Worker → Эксперт (изолированно)
```

**Проблемы:**

- ❌ Нет учета департаментов при распределении
- ❌ Нет иерархии
- ❌ Victoria не участвует
- ❌ Нет сбора ответов

### **Предлагается:**

```
Задача → Victoria (анализ)
       → Определение отделов
       → Выбор стратегии
       → Распределение по департаментам
       → Сбор ответов
       → Синтез результата
```

**Преимущества:**

- ✅ Учет департаментов
- ✅ Иерархия (Victoria → Department Heads → Experts)
- ✅ Victoria координирует
- ✅ Сбор и синтез ответов
