## 1. #65 (P1, главный) — file-check ответы цитируют текст задачи вместо файла

**Симптом** (подтверждён самоаудитом Виктории 3 дня подряд, docs/curator_reports/self_audit_2026-11-1{1,2,3}.md):
- Задача «проверь файл X — есть ли pip install» → в ответе строки из ТЕКСТА ЗАДАЧИ как «найденный код» (например «L35: or "python -m pip install" in normalized» — это условие проверки, а не код).
- Инвертированная логика: `if "pip install" not in text` (защита, ИСКЛЮЧАЮЩАЯ pip) помечена как «признак проблемы».

**Где искать**: цепочка исполнения file-check задач — expert_worker (детекторы паттернов), executor/victoria_server (быстрые проверки файлов). Ключевой инвариант: **детектор обязан читать реальный файл и матчить по его содержимому, а не по тексту goal**. Вероятная механика бага: паттерн ищется в склеенном prompt+file_content, или файл не прочитан и fallback матчит по goal.

**Рецепт**:
1. Найти все места, где «проверь файл» детектится подстроками (pip install, eval, exec, subprocess, secrets) — grep по знаниям экспертов и коду.
2. Гарантировать read_file ДО детекции; пустой/несуществующий файл → честный отказ, не fallback.
3. Негативные условия (`not in`, «отсутствует») не считаются находкой.
4. В ответе цитировать `file:line` из РЕАЛЬНОГО файла — добавить тест: ответ на задачу-провокацию (паттерн только в тексте задачи, не в файле) обязан быть «ОК/не найдено».

**Верификация**: прогнать кураторский файл задач scripts/curator_tasks.txt — все «проверь файл X...pip install» должны отвечать ОК (в этих файлах pip в рантайме нет). Плюс юнит-тест на задачу-провокацию.
