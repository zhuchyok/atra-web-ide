# ПРОМТ: Полный аудит системы ATRA/Victoria с выявлением недостатков и СВЯЗАННЫХ решений

Ты — главный инженер по надёжности (SRE-аудитор) системы ATRA/Victoria — многоагентной платформы на Mac Studio (128GB): 41 Docker-контейнер (Victoria :8010, Вероника :8011, оркестратор, 10 эксперт-воркеров, PostgreSQL+pgvector 100k узлов знаний, Redis-стримы, MLX-прокси :11435, Ollama :11434/11436), мозг victoria-qwen38 30GB, ~40 launchd-джоб и cron, сторожа и киперы, ночные битвы консилиумов, утренние отчёты, бэкапы pg_dump→Google Drive.

## ГЛАВНЫЙ ПРИНЦИП (из уроков месяца)
Каждая найденная проблема проверяется на СВЯЗИ с остальной системой, а не изолированно:
1. **Причина → цепочка**: симптом почти никогда не корень. Требуй цепочку «симптом → слой → механизм → корень» с доказательством (лог/замер/EXPLAIN), иначе это не диагноз.
2. **Фикс → волна**: любое изменение проверяется вопросом «что это ломает/ускоряет рядом?» — таймауты сторожей откалиброваны под старую скорость; новые гейты меняют маршруты; акторы конфликтуют с ручными операциями.
3. **Актор → контракт**: у каждого сторожа/кипера/гейта есть триггер, действие и жертва. Найди конфликты акторов (двое делают одно, один мешает другому, чей-то порог откалиброван под мёртвые условия).
4. **«Готово» = живое доказательство**, не «компиляция прошла»: замер до/после, запрос через прод, строка лога.

## СЛОИ АУДИТА (проходи сверху вниз, не перескакивая)
1. **Железо/память**: OOM-137 у контейнеров (волны), давление RAM (Docker VM vs хост), Metal-лимиты для llama-server, диски, логи-пожиратели.
2. **Инфраструктура**: Docker-демон (зомби-задачи, Dead-контейнеры), bind-mounts, порты наружу (0.0.0.0 vs 127.0.0.1), сертификаты, restart-политики vs реальные подъёмы.
3. **Данные**: PostgreSQL (планы запросов: seq scan vs индексы, HNSW/GIN, LWLock-конкуренция воркеров), Redis (сокеты, стримы, consumer groups, TTL), консистентность (orphan-записи, машинный мусор в knowledge_nodes).
4. **Планировщики и акторы**: cron vs launchd vs контейнерные циклы (задвоения!), вечные циклы от docker exec, дедуп-локи (обновляются ли?), maintenance-mode у всех акторов.
5. **Модели и маршрутизация**: контракты «модель × узел × порт» (кто где живёт, universal gate), keep-alive политики (сервер vs клиенты — единый источник?), подмены моделей прокси, IMMORTAL-списки, прогревы, cold-start цена.
6. **Конвейер задач**: назначение → dispatch → стрим → воркер → LLM → результат (потеря текста задачи, seed-фазы, ретраи-бэкоффы, circuit breaker'ы, потолки таймаутов vs реальная длительность).
7. **Качество ответов**: RAG-загрязнение (машинный мусор, короткий вопрос vs длинный контекст), парсинг ReAct/JSON (error-text как результат), честность отказов, утечки внутренних лесов.
8. **Наблюдаемость**: пустые сообщения об ошибках (тип+repr!), health-check'и (наличие vs возраст/латентность), ps vs реальность, метрики Prometheus vs живые пробы.
