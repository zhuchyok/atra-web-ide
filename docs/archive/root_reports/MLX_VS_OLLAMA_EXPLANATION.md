# Почему используется Ollama вместо MLX?

**Дата:** 2026-01-26  
**Вопрос:** Почему система использует Ollama вместо MLX?

## 🔍 Причина

**MLX API Server не запущен на хосте.**

Система правильно настроена для использования MLX с приоритетом:

1. **MLX напрямую** (если доступен в контейнере) - ❌ Недоступен (требует Apple Silicon)
2. **MLX API Server** (порт 11435) - ❌ Не запущен
3. **Ollama** (порт 11434) - ✅ Используется как fallback

## 📊 Текущая конфигурация

**Приоритет источников:**

1. MLX напрямую (через mlx_router) - **недоступен в Docker**
2. MLX API Server (http://host.docker.internal:11435) - **не запущен**
3. Ollama (http://host.docker.internal:11434) - **используется**

## ✅ Что сделано

1. **Правильный URL для Docker:**
   - В контейнере используется `host.docker.internal:11435` для MLX API Server
   - В контейнере используется `host.docker.internal:11434` для Ollama

2. **Приоритет MLX:**
   - Система пробует MLX API Server сначала
   - Fallback на Ollama только если MLX недоступен

3. **Логирование:**
   - Логи показывают какой источник используется
   - Видно попытки подключения к MLX

## 🚀 Как использовать MLX

### Вариант 1: Запустить MLX API Server на хосте

```bash
# Запустить MLX API Server на порту 11435
python3 knowledge_os/app/mlx_api_server.py
# или
bash scripts/start_mlx_api_server.sh
```

### Вариант 2: Использовать Ollama (текущее состояние)

Ollama работает и используется как fallback. Для лучшего качества нужно загрузить более мощные модели:

```bash
ollama pull phi3.5:3.8b
ollama pull qwen2.5:3b
```
