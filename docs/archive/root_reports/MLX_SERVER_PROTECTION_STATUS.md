# 🛡️ Статус защиты MLX Server от падений

## ✅ ЗАЩИТА 1: Перегрузка при параллельных запросах

### Проблема:

- 2+ запроса от сотрудников одновременно
- Синтез результатов Victoria добавляет еще запросы
- Превышение лимита параллельных запросов (5)

### ✅ Реализованные защиты:

1. **Лимит параллельных запросов: 5**
   - Middleware проверяет `_active_requests >= _max_concurrent_requests`
   - При превышении возвращает HTTP 503 "Server overloaded"
   - Защищает от перегрузки сервера

2. **Rate Limiting: 30 запросов/60 секунд на IP**
   - Middleware отслеживает количество запросов от каждого IP
   - При превышении возвращает HTTP 429 "Rate limit exceeded"
   - Защищает от DDoS и злоупотреблений

3. **Connection Pooling**
   - `timeout_keep_alive=120` для переиспользования соединений
   - `limit_concurrency=_max_concurrent_requests + 5` в uvicorn
   - Оптимизирует использование ресурсов

### 📊 Код защиты:

```python
# mlx_api_server.py:332-337
if _active_requests >= _max_concurrent_requests:
    return JSONResponse(
        status_code=503,
        content={"error": f"Server overloaded. Max {_max_concurrent_requests} concurrent requests"}
    )
```

### ✅ Статус: **ЗАЩИЩЕНО**

## ✅ ЗАЩИТА 2: Нехватка памяти (OOM)

### Проблема:

- Предзагрузка моделей: ~30GB RAM
- При параллельных запросах возможна нехватка памяти

### ✅ Реализованные защиты:

1. **Мониторинг памяти**
   - Функция `check_memory()` проверяет использование памяти
   - Проверка перед загрузкой каждой модели
   - Проверка в health check endpoint

2. **Автоматическая очистка моделей (LRU)**
   - Функция `cleanup_unused_models()` с LRU стратегией
   - При >85% памяти: предупреждение
   - При >95% памяти: автоматическая очистка
   - При >98% памяти: экстренная очистка

3. **Защита активных моделей**
   - `_active_model_requests` - отслеживание используемых моделей
   - `_loading_models` - защита моделей во время загрузки
   - НЕ выгружает модели, которые используются прямо сейчас

4. **Блокировка загрузки при критической нехватке**
   - Проверка памяти перед загрузкой новой модели
   - Блокировка загрузки при >95% памяти
   - Обработка `MemoryError` с экстренной очисткой

## ✅ ЗАЩИТА 3: Отсутствие supervision

### Проблема:

- Нет автоматического перезапуска
- Нет мониторинга состояния
- Нет защиты от каскадных сбоев

### ✅ Реализованные защиты:

1. **MLXServerSupervisor - автоматический перезапуск**
   - Отслеживание состояния процесса
   - Автоматический перезапуск при обнаружении падения
   - Rate limiting: максимум 5 перезапусков за 5 минут

2. **Health Monitoring**
   - Проверка здоровья каждые 10 секунд
   - Проверка `/health` endpoint
   - После 3 неудачных проверок → сервер считается упавшим

3. **Circuit Breaker Pattern**
   - Интеграция с `CircuitBreaker`
   - После 5 неудачных перезапусков → Circuit OPEN
   - Блокировка перезапусков на 60 секунд
   - Автоматический переход в HALF_OPEN для тестирования

4. **Exponential Backoff**
   - Начальная задержка: 2 секунды
   - Максимальная задержка: 60 секунд
   - Формула: `delay = min(2 * 2^n, 60)`

5. **Graceful Shutdown**
   - Отправка SIGTERM для graceful shutdown
   - Ожидание завершения (до 10 секунд)
   - Принудительная остановка при таймауте

6. **Интеграция с ServiceMonitor**
   - Автоматический запуск Supervisor при обнаружении падения
   - Публикация событий в Event Bus
   - Интеграция с Victoria для опционального запуска
