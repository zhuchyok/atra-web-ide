# Защита моделей от выгрузки во время использования

**Дата:** 26.01.2026  
**Проблема:** Модель может быть выгружена, пока другой сотрудник ее использует

---

## 🎯 Проблема

**Сценарий:**

1. Сотрудник А запрашивает модель `qwen2.5-coder-32b`
2. В это время система обнаруживает нехватку памяти
3. Система выгружает модель `qwen2.5-coder-32b` (потому что она не самая используемая)
4. Сотрудник А получает ошибку или долгое ожидание загрузки

---

## ✅ Решение: Защита активных моделей

### Что реализовано:

1. **Отслеживание активных запросов**
   - `_active_model_requests` — счетчик активных запросов для каждой модели
   - `_loading_models` — модели, которые сейчас загружаются
   - `_model_locks` — блокировки для каждой модели

2. **Защита от выгрузки**
   - Модели с активными запросами **НЕ выгружаются**
   - Модели, которые загружаются, **НЕ выгружаются**
   - Экстренная очистка пропускает защищенные модели

3. **Блокировки при загрузке**
   - Каждая модель имеет свою блокировку
   - Загрузка модели защищена от параллельных попыток
   - Модель помечается как "загружается" до завершения

---

## 🔒 Как это работает

### Сценарий 1: Модель используется

**До очистки:**

- `qwen2.5-coder-32b` — 2 активных запроса
- `phi3.5-mini-4k` — 0 активных запросов
- `deepseek-r1-70b` — 0 активных запросов

**При очистке памяти:**

- ✅ **Защищена:** `qwen2.5-coder-32b` (2 активных запроса)
- 🗑️ Выгружены: `phi3.5-mini-4k`, `deepseek-r1-70b`

**Результат:**

- Сотрудники, использующие `qwen2.5-coder-32b`, продолжают работу без задержек
- Другие модели выгружены для освобождения памяти

### Сценарий 2: Модель загружается

**До очистки:**

- `qwen2.5-coder-32b` — загружается (в `_loading_models`)
- `phi3.5-mini-4k` — в кэше, не используется

**При очистке памяти:**

- ✅ **Защищена:** `qwen2.5-coder-32b` (загружается)
- 🗑️ Выгружена: `phi3.5-mini-4k`

**Результат:**

- Загрузка `qwen2.5-coder-32b` не прерывается
- После загрузки модель готова к использованию

### Сценарий 3: Все модели используются

**До очистки:**

- `qwen2.5-coder-32b` — 1 активный запрос
- `phi3.5-mini-4k` — 1 активный запрос
- `deepseek-r1-70b` — 1 активный запрос

**При очистке памяти:**

- ✅ **Все модели защищены** (все используются)
- ⚠️ Очистка **не выполняется** (нечего выгружать)

**Результат:**

- Система логирует предупреждение
- Все модели остаются в памяти
- Возможна нехватка памяти (но модели не прерываются)

## 📊 Мониторинг

### Проверка активных запросов

```bash
# Health check с информацией о защищенных моделях
curl http://localhost:11435/health | jq '.cached_models[] | select(.active_requests > 0)'

# Пример ответа:
{
  "name": "qwen2.5-coder-32b",
  "use_count": 50,
  "active_requests": 2,  # ← 2 активных запроса
  "is_loading": false
}
```

### Информация о загружающихся моделях

```bash
curl http://localhost:11435/health | jq '.loading_models'

# Пример:
["qwen2.5-coder-32b"]  # Модель сейчас загружается
```

### Активные запросы к моделям

```bash
curl http://localhost:11435/health | jq '.active_model_requests'

# Пример:
{
  "qwen2.5-coder-32b": 2,  # 2 активных запроса
  "phi3.5-mini-4k": 1      # 1 активный запрос
}
```

## ⚙️ Технические детали

### Структура данных

```python
# Активные запросы к моделям
_active_model_requests = {
    "qwen2.5-coder-32b": 2,  # 2 активных запроса
    "phi3.5-mini-4k": 1      # 1 активный запрос
}

# Модели, которые загружаются
_loading_models = {"qwen2.5-coder-32b"}

# Блокировки для каждой модели
_model_locks = {
    "qwen2.5-coder-32b": threading.Lock(),
    "phi3.5-mini-4k": threading.Lock()
}
```

### Жизненный цикл запроса

1. **Начало запроса:**

   ```python
   _active_model_requests[model_key] += 1  # Увеличиваем счетчик
   ```

2. **Загрузка модели (если нужно):**

   ```python
   _loading_models.add(model_key)  # Помечаем как загружающуюся
   try:
       model = load(model_path)
   finally:
       _loading_models.discard(model_key)  # Убираем
   ```

3. **Обработка запроса:**
   - Модель используется для генерации
   - Модель защищена от выгрузки

4. **Завершение запроса:**
   ```python
   _active_model_requests[model_key] -= 1  # Уменьшаем счетчик
   if _active_model_requests[model_key] == 0:
       _active_model_requests.pop(model_key)  # Удаляем, если 0
   ```

## 🎯 Итог

✅ **Плюсы:**

- Модели, которые используются, **никогда не выгружаются**
- Модели, которые загружаются, **защищены от прерывания**
- Сотрудники не получают ошибки из-за выгрузки моделей
- Система автоматически определяет, какие модели защищать

⚠️ **Ограничения:**

- Если все модели используются, очистка не выполняется
- Возможна нехватка памяти, если все модели активны
- Но это лучше, чем прерывать работу сотрудников

💡 **Рекомендации:**

- Мониторьте активные запросы через health check
- Если все модели используются постоянно, рассмотрите увеличение RAM
- Используйте меньшие модели для параллельной работы
