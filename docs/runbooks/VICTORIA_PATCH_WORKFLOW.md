# Runbook: Victoria пишет патч → Куратор проверяет → Apply

**Версия:** 1.0 · 2026-03-21  
**Автор:** Виктория (Team Lead) + Куратор  
**Статус:** ACTIVE

---

## Зачем этот workflow

Вместо того чтобы Cursor-агент (куратор) сам писал патчи — задача ставится Виктории.
Цель:

1. **Обучение Виктории** — каждая задача через `/run` = один опыт в MLX-мозге
2. **Экономия токенов** — Виктория локальная, бесплатная, 7–20 сек на задачу
3. **Автономность** — при блокировке Cursor/Claude работа не останавливается

---

## Схема

```
Куратор ставит задачу
        ↓
POST /run → Victoria (MLX или Ollama)
        ↓
Victoria возвращает: анализ + diff/патч
        ↓
Куратор проверяет:
  ✅ Патч верный → apply (StrReplace / patch)
  ⚠️ Патч неполный → усилить и apply
  ❌ Патч неверный → дать feedback, Victoria переделывает
        ↓
Обновить CHANGES_FROM_OTHER_CHATS.md
```

## Шаг 1 — Поставить задачу Victoria

### Шаблон задачи на анализ + патч

````bash
curl -s -X POST http://localhost:8010/run \
  -H "Content-Type: application/json" \
  -d '{
    "goal": "Проанализируй файл <ПУТЬ К ФАЙЛУ>.\n\nЧЕКЛИСТ:\n1. <Что проверить пункт 1>\n2. <Что проверить пункт 2>\n3. Если нашёл проблему — дай точный diff в формате:\n```diff\n- старая строка\n+ новая строка\n```\n\nИтог: одна строка — ОК / ПАТЧ НУЖЕН + файл:строка",
    "project_context": "atra-web-ide",
    "max_steps": 15
  }' --max-time 60 | python3 -c "
import sys, json
d = json.load(sys.stdin)
print(d.get('result', d.get('output', d.get('response', str(d))))[:3000])
"
````

### Правила постановки задачи (12-Factor Victoria)

| Правило                       | Почему                                                                      |
| ----------------------------- | --------------------------------------------------------------------------- |
| Один файл за раз              | Широкий аудит → таймаут (>120 сек)                                          |
| `max_steps: 10-20`            | Достаточно для анализа файла; больше — риск loop                            |
| Просить diff, не описание     | Victoria умеет читать файлы через tools; diff применяется без интерпретации |
| `--max-time 60`               | Hard timeout; если 60 сек — задача слишком широкая, дробить                 |
| Заканчивать «ОК / ПАТЧ НУЖЕН» | Легко парсить, куратор видит итог сразу                                     |

## Шаг 2 — Оценка ответа Victoria (checklist куратора)

```
□ Статус получен (не таймаут, не 503)
□ Victoria прочитала нужный файл (не галлюцинирует строки)
□ Diff синтаксически корректен
□ Логика патча правильная (не просто синтаксис)
□ Нет security регрессий (не убрала guard, не добавила secrets)
□ Побочные эффекты учтены (если меняет интерфейс — проверить callers)
```

### Сигналы что Victoria ошиблась

- Ответила «ПАТЧ НУЖЕН» но пакет уже есть → не прочитала файл до конца
- Diff содержит строки которых нет в файле → галлюцинация
- Предложила дефолт с паролем в коде → не учла security принцип

**При ошибке:** дать feedback-запрос (см. пример ниже) — не применять патч.

## Шаг 3 — Apply (3 варианта)

### A) FAST_PATCH_PATH — Victoria применяет сама (< 200 мс, без LLM) ✅ РЕКОМЕНДУЕТСЯ

```bash
curl -s -X POST http://localhost:8010/run \
  -H "Content-Type: application/json" \
  -d '{
    "goal": "{\"action\":\"apply_patch\",\"file_path\":\"path/to/file.py\",\"old_text\":\"старая строка\",\"new_text\":\"новая строка\"}",
    "project_context": "atra-web-ide"
  }'
# Ответ: {"result": "Successfully patched ...", "knowledge": {"strategy": "fast_patch"}}
```

Работает без LLM — прямой вызов `SystemTools.apply_patch`.
**Когда использовать:** TRUSTED патчи (1 строка, 1 файл, нет изменений логики).

### B) Курсор применяет напрямую (StrReplace)

Когда diff маленький и куратор сам видит правку.

### C) Patch через терминал

```bash
echo '...' | patch -p1
```

## Шаг 4 — Feedback loop (если патч неверный)

```bash
curl -s -X POST http://localhost:8010/run \
  -H "Content-Type: application/json" \
  -d '{
    "goal": "Коррекция по предыдущей задаче.\n\nКуратор обнаружил: <ФАКТ ПОЧЕМУ НЕВЕРНО>.\n\nПроверь ещё раз:\n1. Прочитай <файл> строки <N-M>\n2. <Уточнение>\nДай исправленный ответ.",
    "project_context": "atra-web-ide",
    "max_steps": 10
  }' --max-time 45 | python3 -c "
import sys, json
d = json.load(sys.stdin)
print(d.get('result', d.get('output', str(d)))[:2000])
"
```

**Результат Victoria:** ПАТЧ НУЖЕН (ошибка — не прочитала корневой requirements.txt).  
**Действие куратора:** feedback с фактом → Victoria скорректировалась → ОК.

## Когда НЕ использовать Victoria для патча

| Ситуация                                | Почему                                                    |
| --------------------------------------- | --------------------------------------------------------- |
| Аудит всего репо (src/ + knowledge_os/) | Таймаут >120 сек; дробить на файлы                        |
| Рефакторинг интерфейса (меняет API)     | Нужен архитектурный контекст; ставить через Cursor        |
| Security-critical код (JWT, пароли)     | Двойная проверка куратором обязательна                    |
| Задачи >3 файлов одновременно           | Дробить; Victoria теряет контекст при большом числе reads |

---

## Метрики успеха

- Время ответа Victoria: **< 30 сек** (MLX) — задача сформулирована правильно
- Точность с первой попытки: **~70%** (текущий базовый уровень)
- После feedback: **~95%**
- Таймаут (>60 сек): задача слишком широкая — дробить
