## ⚙️ УСТАНОВКА МОДЕЛЕЙ

### **Вариант 1: MLX (рекомендуется для Apple Silicon)**

```bash
# Установка MLX
pip install mlx mlx-lm

# Конвертация моделей из HuggingFace
mlx_lm.convert --hf-path Qwen/Qwen2.5-Coder-7B
mlx_lm.convert --hf-path meta-llama/Llama-3.2-11B

# Использование в Python
from mlx_lm import load, generate

model, tokenizer = load("qwen2.5-coder-7b")
response = generate(model, tokenizer, prompt="Write Python code...")
```

### **Вариант 2: Ollama (универсальный)**

```bash
# Установка Ollama
brew install ollama

# Установка моделей
ollama pull qwen2.5-coder:7b
ollama pull llama3.2:11b
ollama pull deepseek-coder:33b

# Использование через API
curl http://localhost:11434/api/generate -d '{
  "model": "qwen2.5-coder:7b",
  "prompt": "Write Python code..."
}'
```

## 🎯 Стратегия «быстрый + умный» для 128 GB (Victoria и корпорация)

Для стабильной работы «умной и быстрой» системы на 128 GB рекомендуется явно разделять модели по типу запроса и держать 2–3 модели в памяти, чтобы избежать холодного старта.

**Рекомендуемый набор для 128 GB:**

| Роль                  | Модель (пример)                  | Размер (ориентир) | Когда использовать                                                           |
| --------------------- | -------------------------------- | ----------------- | ---------------------------------------------------------------------------- |
| **Быстрая**           | Phi-3.5 3.8B, TinyLlama 1.1B     | 2–8 GB            | Простые запросы: привет, статус, короткие ответы, быстрая классификация.     |
| **Код и план**        | Qwen2.5 Coder 32B, Llama 3.2 11B | 20–22 GB          | Программирование, план задачи, understand_goal для средних формулировок.     |
| **Умная / стратегия** | 70B (квантизация Q4 ~35–40 GB)   | ~40 GB            | Сложный план, неоднозначные цели («сделай как вчера»), стратегия, консенсус. |

**Порядок загрузки:** сначала быстрая (чтобы простые запросы не ждали), затем код/план, при необходимости 70B. В Victoria выбор модели по категории уже реализован ([available_models_scanner](knowledge_os/app/available_models_scanner.py), [victoria_enhanced](knowledge_os/app/victoria_enhanced.py)); при 128 GB можно задать в Ollama/MLX предзагрузку 2–3 моделей (или держать keep_alive достаточно большим), чтобы не было холодного старта на каждый тип запроса.

**Контекст 64k–128k:** при 128 GB и моделях с длинным контекстом (64k–128k токенов) можно передавать в Victoria более длинную историю чата. В [victoria_server](src/agents/bridge/victoria_server.py) задаются переменные окружения:

- **VICTORIA_CHAT_HISTORY_MAX_MESSAGES** — макс. число сообщений в истории (по умолчанию 30; для длинного контекста можно 50–100).
- **VICTORIA_HISTORY_MAX_CHARS** — макс. символов истории (0 = не обрезать; для 64k токенов ~65536 символов, для 128k ~131072).
- **VICTORIA_GOAL_MAX_CHARS** — макс. символов цели (0 = не обрезать).

Рекомендация для 64k: `VICTORIA_HISTORY_MAX_CHARS=65536` (или 0), `VICTORIA_CHAT_HISTORY_MAX_MESSAGES=50`. Для 128k: `VICTORIA_HISTORY_MAX_CHARS=131072`. Настройка Context length в Ollama/MLX — отдельно (параметр контекста модели). См. также [MAC_STUDIO_LOAD_AND_VICTORIA.md](MAC_STUDIO_LOAD_AND_VICTORIA.md).
