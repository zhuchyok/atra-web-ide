# Loss Ledger: 2026-05-10 -> 2026-07-13

## Incident Scope

- Incident: Docker VM/volumes loss after OOM-related breakage and VM deletion.
- Critical data plane affected: PostgreSQL Docker volume, Redis runtime state.
- Confirmed restore baseline: `knowledge_postgres_2026-05-10_03-00-00.dump`.
- Time gap between baseline backup and incident: about 64 days (~1556.8 hours).

## What Is Recovered

- Core DB restored and running.
- Current DB counts (post-restore + new runtime activity):
  - `tasks`: 2604
  - `knowledge_nodes`: 100676
  - `experts`: 90
- Runtime stack is operational (Victoria/backend/orchestrator/workers/redis/postgres).
- Fresh post-restore backup created and present locally:
  - `knowledge_postgres_2026-07-13_23-49-49_post_restore.dump`

## What Was Likely Lost

- Non-backed-up task/event history created after 2026-05-10 and before incident.
- Redis transient runtime context (pending/consumer delivery state, ephemeral stream history).
- Part of mutation/evolution intermediate artifacts that were only in Docker volumes.
- Fine-grained chronology of retries/reassignments where no secondary evidence exists.

## Recoverability Assessment

- Rebuildable at high confidence (85-95%):
  - Incident timeline and major decisions from audit logs/transcripts.
  - Architecture/runtime policy changes from repo history and docs.
  - High-level task outcomes where mirrored in summaries/reports.
- Rebuildable at medium confidence (70-85%):
  - Task-level chronology in the gap window via audits + transcript replay.
- Not fully reconstructable:
  - Exact Redis ephemeral state at arbitrary historical timestamps.
  - Any DB rows never included in backup and never mirrored in logs/transcripts.
