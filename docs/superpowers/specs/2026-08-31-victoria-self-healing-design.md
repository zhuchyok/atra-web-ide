# Victoria Self-Healing: контур самовосстановления корпорации

**Дата:** 2026-08-31
**Статус:** утверждено (полная автономия, фокус на Виктории, врач — Вероника)

## Проблема

Виктория не может чинить себя сама: сломан именно тот LLM-конвейер (deep/enhanced режим),
который нужен для сложного рассуждения (инцидент 2026-08-31: `No module named 'ai_pipeline'`,
зависание в `enhanced.solve` >5 мин). Инфраструктура мониторинга есть, но контур не замкнут:
ошибки детектятся, но никто не чинит.

## Решение: `victoria-medic` (Вариант C — гибрид)

Новый лёгкий контейнер в `knowledge_os/docker-compose.agents.yml`.
Детерминированная лестница ремонта для известных сбоев + Вероника для неизвестных.

### Компоненты (пакет `knowledge_os/app/medic/`)

| Модуль | Задача |
|---|---|
| `watchdog.py` | Health-зонд (15с), стрим логов victoria-agent по docker SDK, canary `/run` (раз в 5 мин, лимит 60с) |
| `repair.py` | Ступени L1/L2, снапшоты, canary-верификация, откат |
| `main.py` | Цикл, классификатор, дедупликация, L3 через Веронику, журнал, Telegram |

### Детект

- `GET victoria-agent:8000/health` каждые 15с; 3 провала → `SERVICE_DOWN`
- Сигнатуры в логах: `LLM call failed: No module named` → `BROKEN_IMPORT`; `soft-timeout` → `LLM_TIMEOUT`; `Ошибка вызова LLM` → `LLM_ERROR`; canary завис >60с → `SERVICE_HUNG`
- Дедупликация: 1 инцидент на сигнатуру в 10 минут; журнал `logs/victoria_incidents.jsonl`

### Лестница ремонта

| Инцидент | Действия |
|---|---|
| `SERVICE_DOWN` / `SERVICE_HUNG` | L1 рестарт контейнера |
| `BROKEN_IMPORT` | сразу L2 откат файлов |
| `LLM_TIMEOUT` / `LLM_ERROR` | L1 → при повторе ≤10 мин → L2 |
| `UNKNOWN_ERROR` / провал L1+L2 | L3: Вероника предлагает JSON-план, тулкит применяет |

- **L1:** `docker restart victoria-agent`
- **L2:** откат `ai_core.py`, `ai_pipeline.py`, `victoria_enhanced.py` из `last_good/` снапшота + рестарт
- **L3:** Вероника получает контекст (ошибка, логи, файлы), возвращает `{"action": "restart"|"rollback"|"patch", ...}`; патч применяется только через тулкит, никогда напрямую

### Предохранители

- Снапшот ПЕРЕД любым изменением; `last_good/` обновляется только после успешного canary
- Canary после каждой ступени: `/health` + тривиальный `/run` (60с)
- Провал canary → откат действия, следующая ступень
- Лимит: 3 попытки на инцидент, cooldown 10 мин между ремонтами
- Исчерпано → Telegram-эскалация человеку, инцидент `ESCALATED`

### Верификация

- Юнит: классификатор сигнатур, дедупликация
- Интеграция: остановить victoria-agent → медик детектит и рестартует; испортить ai_pipeline.py → откат

### Не делаем (YAGNI)

- Не трогаем EventBus оркестратора
- Не даём Веронике прямой доступ к docker
- Не чиним другие сервисы (потом расширим)

## Сосуществование с существующими механизмами (найдено при деплое)

- `com.atra.auto-recovery` (launchd, каждые 5 мин): `docker-compose up -d` — поднимает мёртвые
  контейнеры. Грубо, но работает → кейс `SERVICE_DOWN` частично прикрыт уже им.
- `watch_victoria_rebuild.py`: force-recreate при изменении 3 ключевых файлов.
- `cloud_watchdog.py`: переключение STRICT_LOCAL при потере интернета.
- **Медик добавляет то, что они не могут:** детект по сигнатурам ошибок в логах,
  откат файлов (L2), диагностику через Веронику (L3), журнал инцидентов.
