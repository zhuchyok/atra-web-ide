Документ сопоставляет детальный план улучшений с текущей реализацией: что уже есть, что не нужно или низкий приоритет, что стоит внедрить.

**Вывод:** Кэширование уже есть на ключевых путях. При желании можно добавить кэш по хэшу (prompt + category) в LocalAIRouter для повторяющихся запросов — быстрая победа.

## 3. Что не нужно или низкий приоритет

- **Мультимодальность (изображения/аудио)** — в плане помечено «если актуально». Сейчас фокус на коде и задачах; добавлять только при появлении требований.
- **Отдельный «умный роутер» с ML-моделью** — уже есть intelligent_model_router и ML-роутер в local_router; дублировать не нужно.
- **Полноценный MultiLayerCache в одном классе** — текущего набора кэшей достаточно; унификация — по желанию для единообразия кода.
- **Jaeger/Prometheus/Grafana** — при необходимости подключаются к существующему OpenTelemetry; отдельно не обязательно, если логи и метрики уже достаточны.

## 4. Что внедрить в первую очередь

### 4.1 Быстрые победы (1–2 недели)

1. **Correlation ID по всей цепочке**
   - В `victoria_server`: принять опциональный `correlation_id` в теле запроса (или сгенерировать), передавать его в understand_goal, plan, executor, вызовы Veronica и в ответ.
   - Пробросить в observability (атрибут span) и в логи.
   - Эффект: проще отлаживать и анализировать запросы.

2. **Кэш по (prompt, category) в LocalAIRouter**
   - Небольшой in-memory LRU (например, 500–1000 записей, TTL 1 час) для результата run_local_llm.
   - Ключ: hash(prompt + category + model).
   - Эффект: ускорение повторяющихся запросов без изменения контрактов.

3. **Уточняющие вопросы при неясной задаче**
   - После understand_goal: если category == "multi_step" и длина/эвристика указывают на неоднозначность — один вызов LLM «сгенерировать 1–3 уточняющих вопроса» и ответ с `needs_clarification: true` и списком вопросов, без выполнения.
   - Эффект: меньше ложных выполнений и переделок.

### 4.2 Средний срок (3–4 недели)

4. **Подмешивание контекста сессии в Victoria**
   - При наличии user_id/session_id вызывать session_context_manager.get_session_context и добавлять в системный/пользовательский промпт краткий контекст (последние 2–3 пары вопрос–ответ).
   - Эффект: более связный диалог без смены архитектуры.

5. **WebSocket для прогресса длинных задач**
   - После появления чата с Victoria: эндпоинт WebSocket, в оркестраторе/Victoria при смене шага отправлять событие progress.
   - Эффект: лучший UX при долгих сценариях.

### 4.3 По мере необходимости

6. **Ретривал по успешным решениям** — когда накопится достаточно успешных кейсов в БД/кэше.
7. **Автообучение промптов по валидатору** — фоновый джоб по отклонённым результатам и обновлению шаблонов.
8. **Пакетная обработка** — только при реальной нагрузке множеством мелких однотипных задач.

## 6. Реализовано (быстрые победы)

- **Correlation ID**: в `victoria_server.py` — заголовок `X-Correlation-ID`, поле в `TaskResponse`, в `_run_task_store` и ответе 202/GET status. Логи содержат короткий префикс correlation_id.
- **Кэш в LocalAIRouter**: в `knowledge_os/app/local_router.py` — кэш по ключу (prompt, category, model), TTL 30 мин, max 500 записей, возвращается кортеж (result, routing_source). Статистика: `_prompt_cache_hits` / `_prompt_cache_misses`.
- **Уточняющие вопросы**: в `victoria_server.py` — `_check_ambiguity`, `_generate_clarification_questions`, `_understand_goal_with_clarification`; при неоднозначности возвращается `status: needs_clarification` и список вопросов, выполнение не запускается. Для выполнения используется переформулированная цель (`restated_goal`) и в Enhanced, и в стандартном режиме.
- **Исправлен баг отступа** в `_ensure_best_available_models` (блок `if best:`).
