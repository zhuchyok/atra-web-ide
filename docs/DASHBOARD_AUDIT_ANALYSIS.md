## ✅ ЧТО РЕАЛЬНО ИСПОЛЬЗУЕТСЯ В СИСТЕМЕ

### 1. **Векторная база данных:**

- **PostgreSQL + pgvector** ✅ (используется)
  - Расширение: `CREATE EXTENSION IF NOT EXISTS vector;`
  - Таблица: `knowledge_nodes` с полем `embedding vector(768)`
  - Поиск: `(1 - (embedding <=> $1::vector)) as similarity`
  - **НЕ Qdrant** ❌

### 2. **Сервис эмбеддингов:**

- **VectorCore** ✅ (используется)
  - Контейнер: `knowledge_vector_core` (порт 8001)
  - Модель: `all-MiniLM-L6-v2` (SentenceTransformer)
  - API: `POST /encode` → возвращает embedding
  - **НЕ KServe** ❌
  - **НЕ Triton** ❌

### 3. **Где используется:**

- **Дашборд:** `knowledge_os/dashboard/app.py` → `VECTOR_CORE_URL = "http://localhost:8001"`
- **Поиск знаний:** `knowledge_os/app/main.py` → векторный поиск через pgvector
- **Семантический кэш:** `knowledge_os/app/semantic_cache.py` → pgvector для кэширования

## ❌ ЧТО НЕ ИСПОЛЬЗУЕТСЯ

### 1. **Qdrant** ❌ (НЕ ИСПОЛЬЗУЕТСЯ)

- **Статус:** НЕТ в системе
- **Где упоминалось:** Только в логах orchestrator.log (гипотезы экспертов) и результатах задач dashboard_audit
- **Реальность:** Используется **pgvector** (PostgreSQL расширение) ✅
- **Примечание:** Qdrant - это векторная БД, но у нас используется pgvector, который лучше интегрирован с PostgreSQL

### 2. **KServe** ❌ (НЕ ИСПОЛЬЗУЕТСЯ)

- **Статус:** НЕТ в системе
- **Где упоминалось:** Только в результатах задач dashboard_audit
- **Реальность:** Используется **MLX API Server** (порт 11435) и **VectorCore** (FastAPI сервис) ✅
- **Примечание:** KServe - это Kubernetes-based model serving, но у нас используется MLX API Server для локальных моделей

### 3. **Triton** ❌ (НЕ ИСПОЛЬЗУЕТСЯ)

- **Статус:** НЕТ в системе
- **Где упоминалось:** Только в результатах задач dashboard_audit
- **Реальность:** Используется **MLX API Server** и **VectorCore** (SentenceTransformer) ✅
- **Примечание:** Triton - это NVIDIA inference server, но у нас используется MLX API Server для Mac Studio
