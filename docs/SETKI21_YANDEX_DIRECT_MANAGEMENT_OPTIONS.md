# Варианты управления рекламой в Яндекс.Директе (Git, API, инструменты)

Краткий обзор решений: версионирование в Git, API-клиенты, автоматизация. Для Setki21 уже есть выгрузка через API ([scripts/export_yandex_direct.py](../scripts/export_yandex_direct.py)); ниже — что можно добавить или использовать отдельно.

---

## 1. Управление кампаниями + Git

**[yandex-direct-campaign-manager](https://github.com/sander-raven/yandex-direct-campaign-manager)** (MIT, консольное приложение)

- Управление рекламными кампаниями в Яндекс.Директ из командной строки.
- Рассчитано на хранение конфигурации в **версионной системе (Git)** — изменения кампаний можно коммитить и откатывать.
- Подходит, если хочется держать структуру кампаний/объявлений в репозитории и применять изменения через один инструмент.

Минус: мало звёзд и форков, возможны устаревшие вызовы API — перед использованием стоит сверить с [актуальной документацией Директа](https://yandex.ru/dev/direct/doc/).

---

## 2. API-клиенты (программное управление)

| Репозиторий                                                                         | Язык | Назначение                                                                    |
| ----------------------------------------------------------------------------------- | ---- | ----------------------------------------------------------------------------- |
| [gladyshev/yandex-direct-client](https://github.com/gladyshev/yandex-direct-client) | —    | Лёгкий клиент к API Директа v5 (≈18 звёзд). Удобно встраивать в свои скрипты. |
| [perf2k2/direct](https://github.com/perf2k2/direct)                                 | PHP  | Обёртка над API v5.                                                           |
| [agentestudio/yandex-direct-api](https://github.com/agentestudio/yandex-direct-api) | —    | Интеграция с API v5.                                                          |

Для Python в этом репо уже используется «ручной» вызов API в [scripts/export_yandex_direct.py](../scripts/export_yandex_direct.py) (Bearer-токен, POST JSON). При желании можно заменить на **yandex-direct-client**, если он поддерживает нужные методы (кампании, объявления, отчёты).

---

## 3. Автокоррекция ставок

**[aspectolog/yads](https://github.com/aspectolog/yads)** (GPL-3.0)

- Автоматическая корректировка ставок под заданный объём трафика на поиске Директа.
- Не про версионирование в Git, а про оптимизацию ставок по правилам/целям.

---

## 4. Что уже есть в этом репо (atra-web-ide)

- **Учётные данные:** [scripts/setup_yandex_direct_env.py](../scripts/setup_yandex_direct_env.py) — интерактивное сохранение токена в `.env.direct`.
- **Выгрузка:** [scripts/export_yandex_direct.py](../scripts/export_yandex_direct.py) — кампании, группы, ключевые слова, объявления в `docs/direct_export/`.
- **Документация:** [docs/YANDEX_DIRECT_OAUTH_SETUP.md](YANDEX_DIRECT_OAUTH_SETUP.md), [docs/SETKI21_DIRECT_HEADLINES_REPLACEMENT.md](SETKI21_DIRECT_HEADLINES_REPLACEMENT.md).

Идея «управление в Git»: можно завести в репо YAML/JSON с желаемыми заголовками и текстами объявлений (по кампаниям/группам), а отдельным скриптом по API обновлять объявления в Директе из этих файлов — тогда изменения рекламы будут в истории Git и код-ревью.

**Итог:** для «управления в Git» ближе всего **yandex-direct-campaign-manager**; для своих скриптов на Python — либо текущий подход (прямые запросы к API), либо клиент **gladyshev/yandex-direct-client**. Расширение наших скриптов до «синхронизации заголовков/текстов из YAML в Директ» даст версионирование рекламных текстов прямо в этом репо.

## 6. Корпорация сама ведёт рекламные кампании

**Да.** При текущей архитектуре корпорация может сама вести рекламу в Яндекс.Директе (Setki21 и др.): эксперты принимают решения, агенты или скрипты выполняют действия.

| Кто                                                         | Роль                                                                                                                                    |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Эксперт (Дарья / Marketing или отдельный «контекстник»)** | Решает, что менять: заголовки, тексты, ставки, структура кампаний. Рекомендации и конфиги в репо (доки, YAML).                          |
| **Локальные агенты (Victoria, Veronica)**                   | Выполняют: либо через **браузер** (BrowserOperator), либо через **скрипты по API**.                                                     |
| **Скрипты в репо**                                          | Выгрузка из Директа (`export_yandex_direct.py`), при одобрении API — применение изменений из конфигов (заголовки/тексты из YAML → API). |

**Два пути исполнения:**

1. **По API (после одобрения заявки в Директе):** конфиги рекламы в Git (YAML/JSON) → скрипт читает конфиг и дергает API Директа (ads/update, campaigns и т.д.). Версионирование и код-ревью изменений рекламы.
2. **Через браузер (локальные агенты):** Veronica/Victoria с BrowserOperator открывают direct.yandex.ru, выполняют задачи («замени заголовок на …», «добавь объявление»). Чтобы не логиниться каждый раз, нужны: **BROWSER_USE_HEADLESS=false** и **постоянный профиль браузера** (**BROWSER_USER_DATA_DIR**), один раз залогиниться — дальше сессия сохраняется. Задача для агента собирается из конфига: `python3 scripts/build_setki21_direct_browser_goal.py` (см. **runbooks/SETKI21_DIRECT_VIA_BROWSER.md**). Код: `knowledge_os/app/browser_operator.py`, `knowledge_os/app/veronica_web_researcher.py` (control_browser).

**Итог:** корпорация сама ведёт кампании: эксперт даёт решения и конфиги, агенты/скрипты вносят изменения в Директ по API или через браузер.
