# Настройка OAuth-приложения для API Яндекс.Вебмастера

Краткая шпаргалка по заполнению формы «Создание приложения» на [oauth.yandex.ru](https://oauth.yandex.ru/client/new) для доступа к данным Вебмастера (в т.ч. для выгрузки и анализа через скрипты/Викторию).

## 1. Общие данные

| Поле                        | Что указать                                                                                                                            |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **Название вашего сервиса** | Любое понятное имя, например: `Atra Webmaster Export` или `Выгрузка Вебмастера для анализа`. Будет видно пользователю при авторизации. |
| **Почта для связи**         | Уже заполнено (zhuchyok@yandex.ru). Оставь как есть или замени на свою.                                                                |

## 2. Доступ к данным (критично)

В поле **«Название доступа»** нужно добавить **права (scope)** для API Вебмастера. Их указывают по одному; если нужно несколько — добавляй по очереди.

### Обязательно для чтения статистики и индексации

- **`webmaster:verify`**  
  Добавление сайтов в Вебмастер и **получение информации о статусе индексирования** (список сайтов, сводка, история индекса, запросы, диагностика и т.д.). Этого достаточно, чтобы выгружать данные для анализа.

### По желанию

- **`webmaster:hostinfo`**  
  Получение информации о **внешних ссылках** на сайт. Для полного анализа ссылочной массы — добавь этот доступ.
- **`webmaster:turbopages`**  
  Добавление Турбо-страниц. Для только чтения/анализа не нужен.

**Как ввести:** в поле «Название доступа» вводишь `webmaster:verify`, нажимаешь добавить; при необходимости добавляешь `webmaster:hostinfo`.

## 3. Redirect URI

Оставь как есть: **`https://oauth.yandex.ru/verification_code`** — это стандартный адрес для получения кода подтверждения (authorization code). После авторизации пользователь попадёт на страницу Яндекса с кодом, который потом обменивается на токен.

## 4. После создания приложения

1. В кабинете появятся **ID приложения** (`client_id`) и **Пароль приложения** (`client_secret`). Храни их в безопасном месте (env, секреты), не коммить в репозиторий.
2. Получить **токен доступа**:
   - Открыть в браузере ссылку авторизации с твоим `client_id` и scope (см. [документацию OAuth Яндекса](https://yandex.ru/dev/id/doc/ru/codes/auth)).
   - Войти под аккаунтом, у которого есть доступ к нужным сайтам в Вебмастере, и разрешить доступ.
   - На странице `oauth.yandex.ru/verification_code` получить **код** и обменять его на `access_token` (POST на `https://oauth.yandex.ru/token` с `grant_type=authorization_code`, `code=...`, `client_id`, `client_secret`).
3. Токен действует **до 1 года** (уточняй в ответе API при получении токена). Дальше можно вызывать API: `https://api.webmaster.yandex.net/v4/user/` и далее по [документации](https://yandex.ru/dev/webmaster/doc/dg/concepts/About-docpage).

## 5. Дальнейшие шаги для анализа «как в кабинете»

- Написать скрипт (Python/curl), который по токену запрашивает: список сайтов → для каждого сайта summary, indexing/history, search-queries, diagnostics и т.д. (см. [обзор ресурсов API](https://yandex.com/dev/webmaster/doc/en/concepts/getting-started)).
- Сохранять ответы в JSON/CSV и передавать их мне (или положить в репозиторий) — я проанализирую так же, как если бы смотрела кабинет.

См. также: [API Вебмастера](https://yandex.ru/dev/webmaster/api), [Условия использования](https://yandex.ru/legal/webmaster_api/).
