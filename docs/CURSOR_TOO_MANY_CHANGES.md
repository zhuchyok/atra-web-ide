# Cursor: «The git repository has too many active changes»

## Что это

Cursor (и VS Code) ограничивают работу с Git, когда в репозитории **слишком много некоммиченных изменений** (изменённые + неотслеживаемые файлы). Часть функций (например, полный список в Source Control, некоторые диффы) отключается, чтобы не подвисать.

## Почему у нас

В репозитории накопилось много правок: десятки изменённых файлов в `knowledge_os/`, `backend/`, `docs/`, плюс неотслеживаемые (новые скрипты, конфиги, отчёты). Итого — порядка 150+ «активных» изменений, порог Cursor превышен.

## Что делать

1. **Закоммитить изменения логичными группами** — тогда число «активных» изменений уменьшится и предупреждение пропадёт.
   - Пример групп: только доки, только бэкенд, только knowledge_os, только скрипты.
2. **Не трогать то, что не нужно в репозитории** — в `.gitignore` уже добавлены артефакты (`fused_model/`, `mirror/`, `frontend/test-results/`, `full_logs.txt`, `docs/curator_reports/*.md` и т.д.), чтобы они не считались.
3. **При необходимости** — временно спрятать часть правок через `git stash` (потом `git stash pop`), чтобы уменьшить число видимых изменений.

После коммитов (или после добавления лишних каталогов в `.gitignore`) предупреждение в Cursor исчезнет.
