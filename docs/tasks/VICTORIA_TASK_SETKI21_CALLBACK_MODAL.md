## Ожидаемый результат

- На сайте Setki 21 (главный и дилеры) по клику на «Заказать обратный звонок» открывается модальное окно.
- В модалке: поле «Имя», поле «Телефон» (маска/валидация как в форме заявки), чекбокс «Согласен с политикой конфиденциальности» (обязателен для отправки).
- Отправка: на главном сайте — на основной email (как в текущей отправке заявки); на сайтах дилеров — на email дилера из конфига тенанта.
- Безопасность: экранирование полей при подстановке в письмо (escapeHtml), валидация телефона на фронте и бэкенде (как в docs/audits/2026-02-23-setki21-full-audit.md §4).
- У дилеров модалка подхватывается автоматически (тот же компонент/страница), меняется только получатель письма в зависимости от тенанта (дилер или головной сайт).

## Контекст для Виктории

- Существующая форма заявки: фронт — компонент с полями заказа (аудит упоминает `OrderForm.vue`), бэкенд — `server/api/orders.post.ts` (escapeHtml, валидация телефона 11 цифр, чекбокс политики). Повторить тот же UX и валидацию для модалки обратного звонка.
- Дилеры: конфиг тенанта по текущему домену (Host) возвращает данные дилера, в т.ч. email. Нужен API-эндпоинт приёма заявки на обратный звонок (или расширение существующего), который по Host/tenant определяет получателя: если дилер — email дилера, иначе — основной email.
- Документация: docs/SETKI21_NPM_SOURCE_OF_TRUTH.md, docs/audits/2026-02-23-setki21-full-audit.md (§4 безопасность), docs/runbooks/SETKI21_WHITE_SCREEN.md.
