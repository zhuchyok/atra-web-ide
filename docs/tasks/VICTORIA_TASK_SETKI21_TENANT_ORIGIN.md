# Задача для Victoria Agent: конфиг тенанта с текущего origin (setki-21)

**Кому:** локальный агент Виктория (POST /run или MCP victoria_run)  
**Проект:** setki-21 (код в `/Users/bikos/Documents/dev/setki-21`)  
**Цель:** убрать мелькание логотипа «Сетки 21» на сайтах дилеров — фронт должен получать конфиг по текущему домену и дожидаться бэкенда.

---

## Формулировка цели (goal) для POST /run

Скопируй блок ниже в `goal` (или отправь как есть в чат Виктории):

```
Проект: setki-21. Путь к коду: /Users/bikos/Documents/dev/setki-21.

Задача: в stores/tenant.ts исправить запрос конфига тенанта так, чтобы он шёл на текущий origin (домен, с которого открыта страница), а не на запечённый apiUrl.

Причина: при открытии сайта дилера (другой домен) запрос сейчас уходит на apiUrl (www.setki21.ru). У запроса Host = www.setki21.ru, бэкенд возвращает конфиг головного сайта «Сетки 21», и на странице дилера мелькает чужой логотип. Бэкенд определяет дилера по заголовку Host; нужно, чтобы запрос к /api/v1/tenant/config шёл на тот же хост, что и страница (относительный URL или baseURL = текущий origin).

Что сделать:
1. В fetchConfig() для запроса к /api/v1/tenant/config не использовать baseURL из runtimeConfig.public.apiUrl (или использовать пустую строку / текущий origin на клиенте), чтобы запрос шёл на тот же домен, что открыт у пользователя. Остальные вызовы API в проекте оставить с apiUrl как есть.
2. После получения конфига: если branding.logo_url приходит относительным (начинается с /), собирать полный URL для отображения из текущего origin (например window.location.origin на клиенте), а не из apiUrl, чтобы картинка логотипа тоже грузилась с того же домена.
3. Проверить, что при открытии главного сайта (www.setki21.ru) конфиг по-прежнему запрашивается и отображается корректно.

Не менять: логику бэкенда (moskit-api), деплой, NPM. Только фронт в stores/tenant.ts.
```

## Критерий успеха

- В `stores/tenant.ts` запрос к `/api/v1/tenant/config` выполняется без `baseURL: apiBase` (или с baseURL = текущий origin на клиенте).
- Относительный `logo_url` из конфига превращается в полный URL через текущий origin.
- На сайте дилера после загрузки отображается логотип и название дилера, без мелькания «Сетки 21».
