# Design Document: Deep Expert Specialization (Singularity 21.17)

## 🎯 Цель

Трансформация «универсальных» ИИ-агентов в узкопрофильных мастеров с уникальной «цифровой ДНК», специфичными правилами (.mdc) и персонализированным опытом (Success Retrieval).

## 🏛 Архитектура (Двухуровневая специализация)

### 1. Уровень «Elite» (15+ ключевых экспертов)

- **Маппинг:** Прямая связь `Expert ID -> Specific Rule File` (например, Игорь -> `09_backend_developer.md`).
- **Контент:** Полные инструкции из `.cursor/rules/`, включая специфичные workflow и ограничения.
- **Опыт:** Приоритетный Success Retrieval только по задачам этого эксперта.

### 2. Уровень «Pro» (71 эксперт)

- **Маппинг:** Групповая связь `Expert Role -> Generic Rule File` (например, все аналитики -> `14_financial_analyst.md`).
- **Контент:** Базовые стандарты роли + индивидуальный `system_prompt` из БД.
- **Опыт:** Общий Success Retrieval по категории задач.

## 🛠 Техническая реализация

### 1. База данных (PostgreSQL)

Добавление колонок в таблицу `experts`:

- `specialization_level`: `VARCHAR` (ELITE/PRO).
- `rule_file`: `VARCHAR` (путь к `.mdc` файлу).
- `performance_score`: `FLOAT` (для адаптивного выбора).

### 2. Ядро (Victoria Server & AI Core)

- **DynamicRuleLoader:** Новый модуль для ленивой загрузки правил из файловой системы.
- **Context Injection:** Инъекция правил в системный промпт перед отправкой в LLM.
- **Expert-Aware RAG:** Модификация `SuccessRetriever` для фильтрации по `assignee_expert_id`.
