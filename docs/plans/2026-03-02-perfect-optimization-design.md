# Дизайн-документ: Smart Memory Bridge (Phase 22.0)

## 1. Архитектурная концепция

Внедрение **предиктивного менеджера памяти** в `LocalAIRouter` для интеллектуального управления моделями Ollama ("руки") при сохранении фиксированного пула памяти для MLX ("базис/стратег"). Цель: исключить использование Swap и обеспечить мгновенную готовность легких моделей после тяжелых задач.

## 2. Ключевые компоненты

### 2.1. Реестр «Золотого набора» (Golden Hands)

Список моделей Ollama, которые должны быть всегда готовы к работе или быстро восстанавливаться:

- `gemma3:4b` (основной исполнитель)
- `tinyllama:latest` (быстрые ответы)
- `nomic-embed-text:latest` (RAG/Embedding)

### 2.2. Предиктивный расчет (The Juggler)

Логика в `local_router.py` перед вызовом Ollama:

1. **Оценка веса:** Получение размера запрашиваемой модели в GB (через `available_models_scanner`).
2. **Проверка лимита:** `Available_RAM - MLX_RESERVE (табу) - System_Buffer (5GB)`.
3. **Shadow Unloading:** Если места недостаточно, отправка `keep_alive: 0` для всех моделей Ollama, кроме запрашиваемой.
4. **VIP-приоритет:** Для категорий `reasoning` или `vip` — немедленная полная очистка Ollama для выделения максимума ресурсов стратегу.

### 2.3. Механизм «Auto-Warmup»

После завершения тяжелой задачи (в блоке `finally`):

- Если `RAM_Available > 30%`, выполняется фоновый прогрев моделей из **Golden Hands** (пустой запрос с `keep_alive`).

## 3. Изменения в коде

### Секция: `local_router.py`

- Модификация `_get_keep_alive`: возвращать `0` для тяжелых моделей при `RAM_Available < 20%`.
- Внедрение `Memory Pre-flight Check` в `run_local_llm`.
- Добавление фоновой задачи `warmup_golden_hands`.

### Секция: `available_models_scanner.py`

- Обеспечение надежного кэширования размеров моделей (`ollama_sizes`) для использования роутером.

## 4. Метрики и контроль

- **Prometheus:** `ollama_forced_unloads_total` (счетчик принудительных выгрузок).
- **Grafana:** Аннотации на графике "RAM vs Swap" в моменты срабатывания `Memory Guard`.
