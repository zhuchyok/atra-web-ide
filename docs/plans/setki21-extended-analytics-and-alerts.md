# План: расширенная аналитика и уведомления (Сетки 21)

**Дата:** 2026-02-23  
**Контекст:** setki-21, moskit-api (Rust), Nuxt 4, кабинет дилера и админка.

---

## Текущее состояние (на момент плана)

- **Кабинет:** счётчики (заказы за месяц, оборот, закупка, прибыль), два графика (продажи и прибыль по дням), таблицы заказов и транзакций. API: `GET /api/v1/admin/dealers/:id/stats`, `.../chart`, orders, transactions.
- **Админка:** общая статистика (дилеры, заказы в работе, выручка за месяц, новые заказы за день), график продаж по дилеру при выборе.
- **Реализовано:** проактивные алерты в ответе `stats`: при балансе дилера ниже порога возвращается `alerts: [{ type: "low_balance", message: "...", balance }]`. Порог задаётся переменной окружения **LOW_BALANCE_THRESHOLD** (₽, по умолчанию 5000). В кабинете алерты отображаются блоком над статистикой; итерация по `(stats?.alerts || [])` для совместимости со старым API.

---

## Что сделать дальше (приоритеты)

### 1. Расширенная аналитика (отчёты)

- **По филиалам:** агрегаты продаж/прибыли по `branch_id` за период (для директора — разбивка по своим филиалам). Эндпоинт: например `GET /api/v1/admin/dealers/:id/stats/by_branch?start_date=&end_date=`.
- **По менеджерам:** агрегаты по пользователям дилера (менеджеры), если в заказах будет привязка к создателю/менеджеру (сейчас опционально).
- **Выбор периода в кабинете:** фильтры «месяц / квартал / год» или календарный диапазон для `stats` и `chart` (уже поддерживаются query-параметрами `start_date`, `end_date` — остаётся добавить UI).

### 2. Проактивные уведомления (расширение)

- **Порог баланса:** реализовано — задаётся через env **LOW_BALANCE_THRESHOLD** (по умолчанию 5000). Опционально: настраиваемый порог в настройках дилера в админке.
- **Дополнительные алерты:** «кредитный лимит почти исчерпан» (если postpaid и balance + credit_limit близки к 0), «нет заказов N дней» (опционально).
- **Канал уведомлений:** при желании — отправка алертов в Telegram/email дилеру или админу (интеграция с существующим сервисом уведомлений, если появится).

### 3. Визуализации в админке

- **Графики по дилерам:** сводный график выручки/прибыли по нескольким дилерам за период (для админа).
- **Дашборд «топ дилеров»:** таблица или карточки по обороту/прибыли за месяц.

### 4. Критерии успеха

- Директор видит алерты по балансу в кабинете и при необходимости — отчёт по филиалам.
- Админ может настроить порог «низкий баланс» и при необходимости получать сводную аналитику по сети.
- Все новые эндпоинты используют уже замороженные цены (`dealer_price_total`, `selling_price_total`, `potential_profit`) для исторической корректности.
