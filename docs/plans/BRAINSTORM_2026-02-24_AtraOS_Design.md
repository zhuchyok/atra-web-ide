# 🧠 BRAINSTORM: Проектирование Atra OS (Rust Kernel + Multi-tenancy + Domain AI)

**Дата:** 2026-02-24  
**Участники:** Виктория (TL), Игорь (Backend), Роман (DB), Дмитрий (ML)  
**Статус:** 🔍 EXPLORATION

---

## 1. Вводная задача

Создание промышленной ERP-системы "Atra OS" на базе Rust для масштабирования бизнеса москитных сеток (Setki 21) на несколько городов и дилеров.

**Ключевые требования:**

- Ядро на Rust (Axum).
- Мультиарендность (один бэкенд — много доменов дилеров).
- Гибкая матрица цен и работ.
- Автономный ИИ-эксперт на VDS для каждого дилера.
- Система статусов производства и монтажа.

## 2. Этап 1: Exploration (Начальные оценки)

### 👨‍💻 Игорь (Backend):

> "Переход на Rust — это правильный шаг. Мы будем использовать **Axum** для API и **SQLx** для асинхронной работы с БД. Основная сложность — реализация Middleware для Tenant Resolution. Нам нужно, чтобы каждый запрос 'знал', к какому дилеру он относится, без лишних запросов к БД на каждом шаге. Предлагаю использовать Redis для кэширования конфигов дилеров."

### 🗄️ Роман (Database):

> "Для масштабируемости я предлагаю схему 'Entity-Attribute-Value' (EAV) для цен, но в упрощенном виде. Таблица `price_matrix` будет связывать `dealer_id`, `work_type_id` и `price`. Это позволит дилерам добавлять свои услуги. Также нужна таблица `tenants` с привязкой доменов."

### 🤖 Дмитрий (ML):

> "По ИИ: на VDS мы развернем **Llama-3.2-1B** через `llama.cpp` или `candle`. Мы сделаем 'базовое обучение' на всех знаниях о сетках, а дилерский контекст (цены, адреса) будем подмешивать через системный промпт. Это даст скорость < 100мс на ответ."

## 4. Этап 3: Approaches (Варианты реализации)

### Подход А: "Монолитное ядро с плагинами"

- Весь код в одном Rust-бинарнике.
- Модули — это просто логические разделы кода.
- **Плюсы:** Легко деплоить, максимальная скорость.
- **Минусы:** Сложнее масштабировать разработку.

### Подход Б: "Микросервисная архитектура (Atra-Cloud)"

- Каждый модуль (Calc, AI, Order) — отдельный контейнер.
- Общение через gRPC или RabbitMQ.
- **Плюсы:** Можно вынести AI на отдельный сервер с GPU.
- **Минусы:** Оверхед на сеть, сложность настройки.

### Решение Команды:

> Выбираем **Подход А (Монолитное ядро)** на старте, но с использованием **Rust Workspace**. Это даст нам скорость монолита, но позволит в любой момент превратить модуль в отдельный микросервис без переписывания кода.

## 5. Этап 4: Design Synthesis (Финальный дизайн)

**Ядро (Kernel):**

- `TenantMiddleware`: Определяет `dealer_id` по домену.
- `AuthModule`: JWT с привязкой к `dealer_id`.

**Модуль Расчетов (Calc Engine):**

- Принимает `Request { dealer_id, items }`.
- Возвращает `Response { cost_price, dealer_price, client_price, margin }`.

**ИИ-Ассистент:**

- Локальный инстанс `llama.cpp` внутри Rust-процесса.
- База знаний в `pgvector` (на VDS).
