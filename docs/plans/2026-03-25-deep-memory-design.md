# Design: Deep Memory (Hierarchical Context Injection)

**Дата:** 2026-03-25  
**Статус:** Утверждено  
**Версия:** 1.0  
**Контекст:** Singularity 22.0: Wisdom Era

## 1. Проблема

Традиционный RAG (Retrieval-Augmented Generation) работает с изолированными фрагментами текста (чанками). При поиске теряются иерархические связи и архитектурный контекст. Виктория видит "что" написано, но не всегда понимает "почему" и как это связано с общими стандартами корпорации.

## 2. Цель

Внедрить механизм **Hierarchical Context Injection (Deep Memory)**, который автоматически обогащает каждый запрос не только релевантными данными, но и "Паспортом Домена" (Community Summary), обеспечивая системное видение задачи.

## 3. Архитектура решения

### 3.1. Двухслойный поиск (Hybrid Graph-Vector Search)

1. **Слой 1 (Vector):** Стандартный семантический поиск по `knowledge_nodes` (Top-K).
2. **Слой 2 (Hierarchical):** Для каждого найденного узла извлекается его `domain_id`. Система делает "прыжок" к корневому узлу этого домена.

### 3.2. Паспорт Домена (Domain Passport)

Специальный тип узла знаний (`metadata->>'type' = 'domain_summary'`), содержащий:

- Краткое описание области (SOP, архитектурные принципы).
- Текущий статус (из Heat Map v35).
- Критические зависимости и "Золотые стандарты".

### 3.3. Инъекция контекста (Contextual Zoom)

В промпт Victoria v3.5 вставляется структурированный блок:

```xml
<deep_memory>
  <domain name="Database">
    Архитектура: PostgreSQL + PgBouncer (6432).
    Статус: Оптимизация пула завершена (10/10).
  </domain>
  <relevant_nodes>
    [Контент найденных чанков...]
  </relevant_nodes>
</deep_memory>
```

## 4. Механизм Эволюции

- **Авто-обновление:** Сервис `knowledge_evolution` раз в сутки пересобирает "Паспорта Доменов" на основе новых данных.
- **Smart Trigger:** Deep Memory активируется только для сложных задач (#complex, reasoning) или при низком confidence score первичного поиска.

## 5. План реализации (High-level)

1. **БД:** Добавление связей в таблицу `domains` и создание первых "Паспортов" вручную.
2. **Core:** Модификация `_get_knowledge_context` в `ai_core.py` для поддержки иерархического обогащения.
3. **Evolution:** Настройка промпта для автоматической суммаризации доменов.
4. **QA:** Внедрение тестов на Faithfulness (соответствие ответа паспорту домена).

## 6. Ожидаемый результат

- Снижение галлюцинаций в архитектурных решениях на 40%.
- 100% консистентность ответов с текущими SOP корпорации.
- Полная прозрачность принятия решений (decision traceability).
