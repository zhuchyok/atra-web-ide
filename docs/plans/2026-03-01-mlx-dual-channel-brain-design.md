---

## 1. Архитектурная концепция

Мы разделяем вычислительные ресурсы MLX на два независимых потока (слота), чтобы тяжелые раздумья Виктории (30B) не блокировались легкими фоновыми задачами (парсинг, аудит), и наоборот.

### Ключевые параметры:

- **`MLX_MAX_CACHED_MODELS=5`**: Держим весь оперативный стек моделей в RAM. Переключение между ними — 0 мс.
- **`MLX_MAX_CONCURRENT=2`**: Разрешаем два параллельных процесса генерации.
- **VIP-слот**: Один поток жестко зарезервирован за моделью `victoria-wisdom-30b`.

## 3. Техническая реализация

### 3.1. Оптимизация MLX API Server (`mlx_api_server.py`)

1.  **Прелоад:** При старте сервер принудительно загружает `victoria-wisdom-30b`, `phi3.5` и `qwen2.5`.
2.  **Умная Очередь:** Модификация `ContinuousBatcher` для поддержки приоритетов. Запросы с заголовком `X-Request-Priority: high` (Виктория) идут в выделенный слот.
3.  **Stability Guard:** Использование раздельных блокировок (`asyncio.Lock`) для каждой модели, чтобы предотвратить конфликты Metal при одновременном обращении.

### 3.2. Настройка Роутинга (`local_router.py`)

1.  **Принудительный маппинг:** Задачи `reasoning` и `vip` всегда идут в VIP-слот MLX.
2.  **Фоновый перенос:** Задачи `fast` и `simple_query` по умолчанию уходят в Ollama, но могут использовать второй слот MLX, если он свободен.
