# План внедрения: Устойчивость MLX API Server (vLLM-Style)

## 🎯 Цель

Устранить падения MLX API Server (`RuntimeError: Unexpected message received: http.request`) и повысить общую надежность системы при сетевых сбоях на Mac Studio M4 Max, следуя мировым практикам (vLLM, Starlette).

## 🛠 Архитектурные изменения

### 1. Headers-Only Priority (Приоритет: Критично)

**Проблема:** Чтение тела запроса (`await request.body()`) в Middleware для определения VIP-статуса (модель Victoria) вызывает `RuntimeError`, если клиент отключается во время чтения потока.
**Решение:**

- Полностью удалить `await request.body()` из `rate_limit_middleware`.
- Определять VIP-статус **только** по заголовку `X-Request-Priority: high`.
- Обновить `local_router.py`, чтобы он гарантированно передавал этот заголовок для всех критических задач.

### 2. ASGI Middleware Safety (Приоритет: Высокий)

**Проблема:** `BaseHTTPMiddleware` в FastAPI/Starlette имеет известные проблемы с обработкой обрывов соединений.
**Решение:**

- Обернуть критические секции Middleware в `try...except (RuntimeError, Exception)`.
- Добавить явную проверку состояния соединения перед тяжелыми операциями.

### 3. Обновление зависимостей (Приоритет: Средний)

**Проблема:** Уязвимости и баги в старых версиях Starlette (CVE-2025-62727).
**Решение:** Обновить `starlette>=0.49.1` и `fastapi` в `requirements.txt`.

  - Логировать сетевые обрывы как `warning`, а не `error`, чтобы не засорять логи при нестабильном Wi-Fi.

## 🧪 Тест-план

1. **Тест VIP:** Запрос к Victoria 30B должен получать `VIP slot acquired` без чтения тела.
2. **Тест на обрыв:** Симуляция обрыва (Ctrl+C на клиенте во время запроса) не должна приводить к падению процесса сервера.
3. **Тест нагрузки:** Параллельные запросы (VIP + Обычный) должны корректно распределяться по семафорам.
