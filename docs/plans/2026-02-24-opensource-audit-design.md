## 2. Архитектура процесса

### Компоненты системы

```
Victoria Server (http://localhost:8010)
    ├── Enhanced Orchestrator
    │   ├── Extended Thinking (qwen3-coder:30b)
    │   └── Expert Delegation
    ├── Scout (индексация кодовой базы)
    └── Knowledge Base (best practices RAG)

Эксперты (через Enhanced):
    ├── Игорь (Backend Developer)
    ├── Анна (QA Engineer)
    ├── Дмитрий (ML/Performance)
    └── Ольга (Performance Engineer)
```

### Workflow для каждого проекта (45-60 мин)

#### Фаза 1: Подготовка (5 мин)

1. `git clone [repo] /Users/bikos/Downloads/[название]`
2. Создание контекста для Victoria:
   - Путь к проекту
   - Язык программирования
   - Тип проекта (библиотека/фреймворк/приложение)

#### Фаза 2: Автоматический анализ (15-20 мин)

Victoria через Extended Thinking анализирует:

**Чек-лист анализа:**

- [ ] Структура проекта (папки, модули, точки входа)
- [ ] README и документация (полнота, актуальность)
- [ ] Архитектурные паттерны
- [ ] Качество кода (именование, SOLID, DRY)
- [ ] Зависимости (актуальность, безопасность)
- [ ] Тесты (наличие, покрытие, типы)
- [ ] CI/CD (GitHub Actions, pre-commit hooks)
- [ ] Производительность (очевидные узкие места)
- [ ] Безопасность (secrets, input validation)
- [ ] Поддерживаемость (CONTRIBUTING, issue templates)

**Выход:** JSON с оценками по каждому пункту + топ-3 проблемные зоны

#### Фаза 3: Экспертная оценка (10-15 мин)

Victoria делегирует топ-3 зоны экспертам:

| Зона               | Эксперт       | Задача                           |
| ------------------ | ------------- | -------------------------------- |
| Архитектура/код    | Игорь         | Паттерны, рефакторинг, улучшения |
| Тесты/CI           | Анна          | Покрытие, качество тестов, CI/CD |
| Производительность | Дмитрий/Ольга | Узкие места, оптимизация         |

Каждый эксперт:

1. Получает контекст (проблемная зона + код)
2. Анализирует через локальную модель
3. Возвращает рекомендации (2-3 абзаца)

#### Фаза 4: Синтез отчёта (5-10 мин)

Victoria собирает:

- Автоматический анализ
- Экспертные рекомендации
- Общую оценку (1-10 баллов)
- Топ-5 рекомендаций для улучшения

**Выход:** `/Users/bikos/Downloads/[проект]/AUDIT_REPORT.md`

## 4. Критерии успеха теста

Система считается успешной, если:

1. **Автоматический анализ:**
   - Victoria корректно индексирует проект через Scout
   - Extended Thinking генерирует осмысленные выводы по чек-листу
   - Выявлены реальные проблемы (проверяются вручную)

2. **Делегирование экспертам:**
   - Оркестратор правильно назначает экспертов по зонам
   - Эксперты дают специфичные рекомендации (не общие слова)
   - Контекст корректно передаётся (код + описание проблемы)

3. **Синтез:**
   - Финальный отчёт структурирован и читаем
   - Нет противоречий между автоматикой и экспертами
   - Рекомендации конкретные и применимые

4. **Производительность:**
   - Каждый проект аудируется за 45-60 мин
   - Локальные модели работают стабильно (без вылетов)
   - Использование RAM в пределах нормы (Mac Studio)

5. **Качество:**
   - Минимум 70% выявленных проблем — реальные (не ложные срабатывания)
   - Рекомендации соответствуют best practices языка
   - Отчёт можно использовать для реального улучшения проекта

## 7. Риски и митигация

| Риск                                     | Вероятность | Митигация                                                 |
| ---------------------------------------- | ----------- | --------------------------------------------------------- |
| MLX/Ollama вылетает при больших проектах | Средняя     | Chunking анализа, recovery через system_auto_recovery.sh  |
| Эксперты дают общие рекомендации         | Средняя     | Уточнение промптов, передача конкретного кода в контексте |
| Scout не индексирует весь проект         | Низкая      | Fallback на прямое чтение файлов через Victoria           |
| Таймаут Extended Thinking                | Средняя     | Увеличение VICTORIA_EXTENDED_THINKING_TIMEOUT, chunking   |
| Недостаток контекста для больших файлов  | Высокая     | Приоритизация ключевых файлов, summary для больших        |
