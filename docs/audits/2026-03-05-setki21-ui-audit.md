## 2. Архитектурные наблюдения

### 2.1 Текущий стек (по документации)

**Frontend:**

- Nuxt 4 (Vue 3, TypeScript, Tailwind CSS)
- Pinia для state management
- SSG (Static Site Generation) для лендинга

**Backend:**

- **moskit-api** (Rust/Axum/SQLx) — порт 8080
- PostgreSQL (БД `moskit`)
- Nginx Proxy Manager маршрутизирует:
  - `/` → setki21-site (статика)
  - `/api`, `/health` → moskit-api:8080

**Deployment:**

- VDS: 45.10.43.248
- Домен: www.setki21.ru
- SSL через NPM

### 2.2 Известные проблемы из документации

По данным `SETKI21_API_RAZBOR.md` и `SETKI21_ADMIN_PRICING_VDS.md`:

1. **Требуется корректная настройка NPM:**
   - Custom Locations должны направлять `/api` и `/health` на `moskit-api:8080`
   - Если настройка некорректна, админка не получит доступ к API

2. **Миграции БД:**
   - Должна быть применена миграция `004_admin_setki21.sql`
   - Создан пользователь `admin@setki21.ru` с корректным паролем

3. **Тома Docker:**
   - `moskit_uploads` должен быть примонтирован для сохранения загрузок (логотипы)

## 4. Технические рекомендации

### 4.1 Отсутствие browser automation

**Проблема:**  
Текущие MCP-серверы (`user-ollama`, `user-mlx`, `user-VictoriaATRA`, `user-filesystem`) не предоставляют инструменты для браузерной автоматизации.

**Решение:**

1. **Playwright Integration:**
   - По документации, в проект `setki-21` уже интегрирован Playwright
   - Создать E2E тесты для админ-панели:
     ```typescript
     // tests/e2e/admin-dealers.spec.ts
     test("should show dealer tabs", async ({ page }) => {
       await page.goto("https://www.setki21.ru/admin/dealers");
       await page.fill('input[type="email"]', "admin@setki21.ru");
       await page.fill('input[type="password"]', "Bik6007OS");
       await page.click('button[type="submit"]');

       await page.click(".dealer-row:first-child");
       await expect(page.locator("text=Иерархия и Финансы")).toBeVisible();
       await expect(page.locator("text=Транзакции")).toBeVisible();
       await expect(page.locator("text=Пользователи")).toBeVisible();
     });
     ```

2. **MCP Browser Server:**
   - Добавить MCP-сервер с Puppeteer/Playwright
   - Обновить `.cursor/config` для подключения сервера
   - Использовать в следующих аудитах

### 4.2 Проблема timeout на /cabinet

**Возможные причины:**

1. **Redirect loop:** страница редиректит на login, который снова редиректит
2. **Heavy scripts:** Vue hydration + Chart.js загружаются слишком долго
3. **API timeout:** moskit-api не отвечает вовремя

**Диагностика:**

```bash
# Проверить статус moskit-api на VDS
ssh root@45.10.43.248 "docker ps | grep moskit-api"

# Проверить логи
ssh root@45.10.43.248 "docker logs moskit-api --tail 100"

# Проверить endpoint напрямую
curl -I https://www.setki21.ru/api/v1/health
```

**Решения:**

- Если API не работает → `docker-compose restart moskit-api`
- Если долго загружается → включить lazy loading для графиков
- Если redirect loop → проверить middleware в Nuxt (`~/middleware/auth.ts`)

---

### 4.3 Проверка NPM маршрутизации

Убедиться, что Nginx Proxy Manager корректно настроен:

**Ожидаемая конфигурация (из `npm_proxy_setki21.conf`):**

```nginx
# Host: www.setki21.ru
# Forward to: setki21-site:80

# Custom Locations:
location /api {
  proxy_pass http://moskit-api:8080;
}

location /health {
  proxy_pass http://moskit-api:8080;
}
```

**Проверка:**

```bash
# Главная (должна отдаваться статика)
curl -I https://www.setki21.ru/

# API (должен отвечать moskit-api)
curl https://www.setki21.ru/api/v1/health

# Админка (должна отдаваться статика)
curl -I https://www.setki21.ru/admin/dealers
```
