## 🔍 НАЙДЕННЫЕ ПРОБЛЕМЫ

### **ПРОБЛЕМА #1: ML фильтр может блокировать все сигналы** 🔴

**Критичность:** ВЫСОКАЯ  
**Файл:** `signal_live.py:2836-2866`

#### **Проблема:**

ML фильтр вызывается с `tp1=None, tp2=None`, что может привести к неправильным предсказаниям.

#### **Код:**

```python
ml_passed, ml_reason, _ml_prediction = await check_ml_filter(
    symbol=symbol,
    signal_type=signal_type,
    entry_price=signal_price,
    df=df,
    quality_score=quality_score,
    mtf_score=0.5,
    tp1=None,  # ❌ ПРОБЛЕМА: TP не рассчитан
    tp2=None,  # ❌ ПРОБЛЕМА: TP не рассчитан
    ...
)
```

#### **Решение:**

Рассчитывать TP1/TP2 перед вызовом ML фильтра.

## ✅ ДЕТАЛЬНЫЙ АНАЛИЗ ПРОБЛЕМ

### **ПРОБЛЕМА #1: ML фильтр с None TP1/TP2** 🔴

**Статус:** ⚠️ **НЕ КРИТИЧНО** (есть fallback)

#### **Анализ:**

В `check_ml_filter` есть fallback на дефолтные значения:

```python
'tp1': tp1 if tp1 else entry_price * 1.02,  # Дефолт 2%
'tp2': tp2 if tp2 else entry_price * 1.04,  # Дефолт 4%
```

**Вывод:** Проблема не критична, но лучше рассчитывать TP перед вызовом для более точных предсказаний.

---

### **ПРОБЛЕМА #2: Дублирование кода smart_rsi** 🟡

**Статус:** ✅ **НАЙДЕНО** (строки 2895-2915)

#### **Решение:**

Вынести в функцию:

```python
def set_smart_rsi_btc_alignment(df: pd.DataFrame, value: bool = True):
    """Устанавливает BTC alignment в smart_rsi context"""
    smart_ctx = df.attrs.get('smart_rsi')
    if isinstance(smart_ctx, dict):
        smart_ctx['btc_alignment'] = value
```
