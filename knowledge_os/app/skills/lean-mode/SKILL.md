# Lean Mode (Ponytail-style, with ATRA guardrails)

Навык для "ленивого синьора": писать только необходимый код, не раздувая решение.
Ключевая идея: меньше кода -> меньше дефектов -> быстрее цикл.

Важно: lean-mode НЕ означает "урезать безопасность/валидацию/контракты".

## Когда использовать

Используй lean-mode для:

- Простых UI-изменений (визуальные правки, мелкие компоненты, нативные input'ы)
- Утилит и helper-функций без критичных side-effects
- Небольших endpoint-правок без изменения trust-boundary
- Рефакторинга "лишнего слоя абстракции" без изменения поведения

## Когда НЕ использовать

Запрещено включать lean-mode для:

- AuthN/AuthZ, permissions, secrets, криптографии
- DB миграций, транзакционных сценариев, схемы данных
- Контуров очередей, SLA-логики, task state machine, contract enforcement
- Security-sensitive кода (внешние входы, upload, execution, sandbox)
- Любых high-risk изменений без тестов

## Лестница принятия решения (обязательная)

Перед написанием кода проверь ступени по порядку:

1. Нужно ли это вообще? (YAGNI)
2. Есть ли решение в stdlib?
3. Есть ли нативная платформа/HTML возможность?
4. Есть ли уже установленная зависимость?
5. Можно ли сделать в 1-3 строках без потери читаемости?
6. Только потом — минимальный новый код

Останавливайся на первой подходящей ступени.

## Инварианты качества (нельзя нарушать)

- Валидация входов и обработка ошибок обязательны
- Security checks не удалять
- Accessibility для UI не ухудшать
- Контракты API/состояний не ломать
- Логику "тихо игнорировать ошибку" не добавлять

## Формат применения в задаче

Перед реализацией коротко зафиксируй:

- Контекст: почему задача low-risk
- Выбранная ступень лестницы
- Что НЕ трогаем (security/db/contracts)

После реализации:

- Короткий smoke-тест
- Проверка, что diff стал проще, а не "короче любой ценой"

## Мини-чеклист перед merge

- [ ] Нет изменений в auth/db/contracts/security
- [ ] Нет деградации валидации и error handling
- [ ] Поведение не изменилось неожиданно
- [ ] Проверка smoke/test выполнена
- [ ] Diff проще и понятнее, а не просто меньше строк
