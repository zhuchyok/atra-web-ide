# 🎯 Руководство по автоматической оптимизации параметров

## 📋 Обзор системы

Автоматическая система оптимизации параметров стратегии предназначена для:

- **Периодического тестирования** производительности стратегии
- **Автоматической оптимизации** параметров на основе исторических данных
- **Применения лучших параметров** только при значительном улучшении
- **Ведения истории** всех оптимизаций для анализа трендов

## 🚀 Быстрый старт

### 1. Запуск системы управления

```bash
python3 start_auto_optimization.py
```

### 2. Выбор режима работы

- **Планировщик** - автоматическая работа по расписанию
- **Разовая оптимизация** - однократная оптимизация
- **Просмотр статистики** - анализ результатов

## ⏰ Расписание автоматической оптимизации

### Ежедневная оптимизация

- **Время**: 06:00 утра
- **Тип**: Быстрая оптимизация (30 испытаний на символ)
- **Цель**: Поддержание оптимальных параметров

### Еженедельная оптимизация

- **Время**: Воскресенье 08:00
- **Тип**: Полная оптимизация (100 испытаний на символ)
- **Цель**: Глубокий анализ и поиск лучших параметров

### Мониторинг производительности

- **Частота**: Каждые 4 часа
- **Действие**: Проверка без оптимизации
- **Триггер**: Автоматическая оптимизация при падении производительности ниже порога

## 🔧 Алгоритм работы

### 1. Анализ текущей производительности

```python
# Вычисление оценки на основе метрик:
score = (
    win_rate * 0.3 +           # 30% - процент успешных сделок
    profit_factor / 3 * 0.3 +  # 30% - соотношение прибыли к убыткам
    (1 - max_drawdown) * 0.2 + # 20% - защита от просадки
    sharpe_ratio / 2 * 0.2     # 20% - риск-скорректированная доходность
)
```

### 2. Оптимизация параметров

- **Символы**: Топ-50 монет по объему торгов (автоматически загружаются с Binance)
- **Параметры**: EMA, RSI, ATR, Take Profit, Stop Loss, Volume Ratio
- **Алгоритм**: Optuna с байесовской оптимизацией
- **Группировка**: Оптимизация выполняется группами по 10 монет для эффективности

### 3. Тестирование новых параметров

- Бэктест на исторических данных (4h timeframe)
- Сравнение с текущими параметрами
- Применение только при улучшении >5%

### 4. Применение параметров

- Сохранение в `optimized_parameters.json`
- Создание Python конфигурационного файла
- Резервное копирование в `optimization_history/`

## 📊 Мониторинг и статистика

### Файлы логов

- `auto_optimization.log` - основной лог системы
- `optimization_history/` - папка с историей оптимизаций

### Метрики отслеживания

- **Общая оценка производительности** (0-1)
- **Win Rate** - процент успешных сделок
- **Profit Factor** - соотношение прибыли к убыткам
- **Maximum Drawdown** - максимальная просадка
- **Sharpe Ratio** - риск-скорректированная доходность

### Пороговые значения

- **Минимальная оценка**: 0.6 (триггер экстренной оптимизации)
- **Улучшение для применения**: +5% от текущей оценки
- **Количество испытаний**: 25 (ежедневно) / 100 (еженедельно)
- **Анализ производительности**: Топ-20 монет для быстрой оценки

## ⚙️ Настройка системы

### Изменение расписания

Отредактируйте файл `auto_optimization_scheduler.py`:

```python
# Ежедневная оптимизация
schedule.every().day.at("06:00").do(self.run_optimization_cycle)

# Еженедельная оптимизация
schedule.every().sunday.at("08:00").do(self.run_full_optimization)

# Проверка производительности
schedule.every(4).hours.do(self.performance_check)
```

### Настройка параметров

В классе `AutoOptimizationScheduler`:

```python
self.performance_threshold = 0.6  # Порог производительности
self.config.optimization_trials = 25  # Количество испытаний
# Символы автоматически загружаются с Binance API
# Fallback список из 50 монет при ошибке загрузки
```

### Настройка метрик

В функции `analyze_current_performance`:

```python
score = (
```

## 🚨 Устранение неполадок

### Проблема: Ошибка импорта schedule

```bash
pip3 install schedule
```

### Проблема: Ошибка оптимизации

- Проверьте подключение к интернету
- Убедитесь в доступности Binance API
- Проверьте логи в `auto_optimization.log`

### Проблема: Низкая производительность

- Увеличьте количество испытаний
- Проверьте качество исторических данных
- Анализируйте тренды в истории оптимизаций

### Проблема: Слишком частые оптимизации

- Увеличьте порог производительности
- Уменьшите частоту проверок
- Настройте более строгие критерии применения
