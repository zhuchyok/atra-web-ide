# Отчет: Исправление проблемы со статистикой сигналов

## 🚨 Проблема

Команда `/signal_stats` показывала "У вас пока нет торговых данных" даже после принятия сигналов и открытия позиций.

## 🔍 Диагностика

### Анализ данных

Проверил файл `user_data.json` и обнаружил, что данные есть:

```json
"556251171": {
  "open_positions": [
    {
      "symbol": "ETHUSDT",
      "entry_price": null,
      "tp1": null,
      "tp2": null,
      "stage": "open",
      "risk_amount": 35.964,
      "risk_pct": 1.8,
      "leverage": 3,
      "side": "long"
    },
    // ... еще 2 позиции
  ],
  "accepted_signals": [
    {
      "symbol": "ETHUSDT",
      "entry_time": "2024-08-02T10:02"
    },
    // ... еще 2 сигнала
  ]
}
```

### Причина проблемы

Функция `signal_stats_cmd` загружала данные из `context.application.user_data`, а не из файла `user_data.json`. Это приводило к тому, что функция не видела актуальные данные пользователя.

### Логика до исправления:

```python
# Загружаем данные пользователя из файла
load_user_data(context)

if user_id not in context.application.user_data:
    context.application.user_data[user_id] = {}
user_data = context.application.user_data[user_id]
```

## ✅ Исправление

### Новая логика:

```python
# Загружаем данные пользователя напрямую из файла
import os
import json

user_data_file = "user_data.json"
user_data = {}

if os.path.isfile(user_data_file):
    try:
        with open(user_data_file, 'r', encoding='utf-8') as f:
            all_user_data = json.load(f)
            user_data = all_user_data.get(str(user_id), {})
    except Exception as e:
        print(f"Ошибка загрузки данных пользователя: {e}")
        user_data = {}
```
