## 🎯 ЦЕЛЬ

Автоматически добавлять новые монеты с базовыми параметрами, запускать оптимизацию и блокировать генерацию сигналов до завершения оптимизации.

---

## 📋 ОПИСАНИЕ СИСТЕМЫ

### **1. Менеджер параметров (`src/ai/symbol_params_manager.py`)**

**Основные функции:**

1. **`get_symbol_params(symbol)`** - получает параметры монеты
2. **`ensure_symbol_optimized(symbol)`** - обеспечивает наличие оптимизированных параметров
3. **`is_symbol_ready(symbol)`** - проверяет готовность монеты для генерации сигналов
4. **`_run_optimization(symbol)`** - запускает оптимизацию в фоне

**Статусы монет:**

- `pending` - ожидает оптимизации
- `optimizing` - в процессе оптимизации
- `optimized` - оптимизирована (готова)
- `failed` - ошибка оптимизации

### **2. Интеграция в `signal_live.py`**

**В функции `get_symbols()`:**

- Проверяет готовность каждой монеты
- Автоматически добавляет новые монеты с базовыми параметрами
- Запускает оптимизацию в фоне
- Возвращает только готовые монеты

**В функции `_generate_signal_impl()`:**

- Проверяет готовность монеты перед генерацией сигнала
- Блокирует генерацию для неоптимизированных монет

## 🔄 ПРОЦЕСС РАБОТЫ

### **Шаг 1: Обнаружение новой монеты**

```
1. get_symbols() получает список монет из API
2. Для каждой монеты вызывается ensure_symbol_optimized()
3. Если монеты нет в файле параметров:
   - Добавляется с базовыми параметрами
   - Статус: pending
   - Запускается оптимизация в фоне
```

### **Шаг 2: Оптимизация**

```
1. Создается lock-файл (optimization_lock_{symbol}.lock)
2. Статус меняется на: optimizing
3. Запускается скрипт optimize_intelligent_params.py
4. Оптимизация выполняется на 30 днях данных
5. После завершения:
   - Обновляется файл параметров
   - Статус меняется на: optimized
   - Lock-файл удаляется
```

### **Шаг 3: Генерация сигналов**

```
1. get_symbols() возвращает только готовые монеты (status=optimized)
2. _generate_signal_impl() проверяет готовность перед генерацией
3. Если монета не готова - сигнал не генерируется
```

## ⚠️ ВАЖНЫЕ ЗАМЕЧАНИЯ

### **1. Блокировка генерации сигналов:**

- Монеты без оптимизации **не генерируют сигналы**
- Это предотвращает использование неоптимизированных параметров

### **2. Оптимизация в фоне:**

- Оптимизация запускается асинхронно
- Не блокирует работу бота
- Можно запускать несколько оптимизаций параллельно

### **3. Lock-файлы:**

- Предотвращают одновременный запуск нескольких оптимизаций для одной монеты
- Автоматически удаляются после завершения

### **4. Обработка ошибок:**

- При ошибке оптимизации статус меняется на `failed`
- Монета может использовать базовые параметры (если настроено)
