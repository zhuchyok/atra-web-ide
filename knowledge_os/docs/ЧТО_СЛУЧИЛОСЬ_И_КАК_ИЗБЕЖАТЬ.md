## ⚠️ ПОЧЕМУ MERGE ПЕРЕЗАПИСАЛ ФАЙЛЫ?

### Причина:

На сервере были **незакоммиченные изменения** в `main.py` и `web/dashboard.py`.

При `git pull` Git попытался слить их с версией из GitHub, и в результате:

- ❌ Потерялись параметры `use_reloader=False, threaded=True` в `main.py`

### Решение:

**ВСЕГДА коммитьте ПЕРЕД pull!**

```bash
# ПРАВИЛЬНО:
git add -A
git commit -m "Changes"
git pull

# НЕПРАВИЛЬНО:
git pull  # ❌ Без коммита!
```

## 🛠️ АВТОМАТИЗАЦИЯ

### Создайте алиас для безопасного update:

```bash
# Добавьте в ~/.bashrc на сервере:
alias safe-update='git add -A && git commit -m "Auto commit before pull" && git pull origin worker_v2 && python3 verify_all_fixes.py'
```

Теперь просто:

```bash
safe-update
```

## 📞 ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК

### 1. Проверка показала проблемы:

```bash
python3 verify_all_fixes.py
# Если есть ❌:
```

**Решение:** Загрузите исправленные файлы с локального:

```bash
# На локальной машине:
scp main.py root@IP:/root/atra/
scp web/dashboard.py root@IP:/root/atra/web/

# На сервере:
python3 verify_all_fixes.py  # Проверить снова
```

### 2. Merge не завершается:

```bash
error: Terminal is dumb, but EDITOR unset
Not committing merge
```

**Решение:**

```bash
git commit --no-edit -m "Merge completed"
```

### 3. Конфликты при merge:

```bash
CONFLICT (content): Merge conflict in <файл>
```

**Решение:**

```bash
# Вариант A: Оставить нашу версию
git checkout --ours <файл>
git add <файл>

# Вариант B: Оставить версию с GitHub
git checkout --theirs <файл>
git add <файл>

# Завершить merge:
git commit --no-edit -m "Resolved conflicts"
```
