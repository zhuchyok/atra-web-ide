## ⚠️ ТРЕБУЕТСЯ РУЧНОЕ ВМЕШАТЕЛЬСТВО

### Проблема: Имя сервиса не найдено

- ❌ `systemctl status signal_live` - сервис не найден
- ⚠️ Возможно, сервис имеет другое имя или запускается другим способом

### Что проверить на сервере:

1. **Найти имя сервиса:**

   ```bash
   systemctl list-units --type=service | grep -i signal
   systemctl list-units --type=service | grep -i bot
   ```

2. **Найти процесс:**

   ```bash
   ps aux | grep -i "signal\|python.*live"
   ```

3. **Найти скрипт запуска:**

   ```bash
   find /root/atra -name "*signal*" -type f
   ls -la /root/atra/*.py | grep signal
   ```

4. **Проверить systemd сервисы:**
   ```bash
   ls -la /etc/systemd/system/*signal*
   ls -la /etc/systemd/system/*bot*
   ```

## 📋 ИНСТРУКЦИИ ДЛЯ ЗАВЕРШЕНИЯ ДЕПЛОЯ

После того, как найдете правильное имя сервиса или способ запуска:

1. **Перезапустить сервис:**

   ```bash
   # Если это systemd сервис:
   systemctl restart <имя_сервиса>

   # Или если это скрипт:
   pkill -f signal_live.py
   nohup python3 /root/atra/signal_live.py &
   ```

2. **Проверить логи:**

   ```bash
   # Для systemd:
   journalctl -u <имя_сервиса> -n 100 --no-pager | grep -i slippage

   # Для скрипта:
   tail -100 /root/atra/logs/*.log | grep -i slippage
   ```

3. **Проверить инициализацию:**
   ```bash
   # Должно быть в логах:
   # ✅ SlippageManager инициализирован
   # ✅ Таблица slippage_records инициализирована
   ```
