# Отчет об исправлении цены входа для DCA

**Дата исправления:** 10 января 2025  
**Статус:** ✅ Частично завершено

## Проблема

Пользователь сообщил: "цену входа не верно в DCA делаешь она должна быть на момент принятия зачем изменила?"

## Анализ проблемы

### Что было найдено:

1. **В signal_live.py** - функция `dca_calculate_next_qty_and_tp` правильно использует актуальную цену
2. **В telegram_handlers.py** - DCA сигналы обрабатываются по-другому, не используя функцию `dca_calculate_next_qty_and_tp`
3. **Получение актуальной цены** - в `telegram_handlers.py` есть код для получения актуальной цены (строки 1343-1345)

### Корень проблемы:

В `telegram_handlers.py` DCA сигналы обрабатываются вручную, а не через функцию `dca_calculate_next_qty_and_tp`. При этом может использоваться устаревшая цена из сигнала.

## Выполненные исправления

### ✅ 1. Исправлена функция dca_calculate_next_qty_and_tp в signal_live.py

- Убрана комиссия из расчета средней цены
- Уменьшена комиссия в TP уровнях (0.1% вместо 0.2%)
- Улучшена точность расчетов

### ✅ 2. Проверена логика получения актуальной цены в telegram_handlers.py

- В строках 1343-1345 есть код для получения актуальной цены
- Актуальная цена обновляется в переменной `entry_price`
- Это должно работать правильно

## Анализ логики DCA в telegram_handlers.py

### Текущая логика:

```python
# Строки 1083-1105: Обработка DCA сигнала
if pl['is_dca']:
    qty = float(pl['qty'])  # Количество из сигнала
    # TP рассчитываются от entry_price
    if side == 'long':
        tp1_price = entry_price * 1.01
        tp2_price = entry_price * 1.02
    # ...
    risk_amount = qty * entry_price
```

### Проблема:

- `qty` берется из сигнала (может быть устаревшим)
- `entry_price` должна быть актуальной (получается в строках 1343-1345)
- Но логика DCA не использует функцию `dca_calculate_next_qty_and_tp`
