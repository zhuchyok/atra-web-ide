# 🔴 КРИТИЧЕСКАЯ ПРОБЛЕМА: Автоматическое создание позиций из биржи

## 🎯 Проблема

Пользователь сообщил, что система открыла LONG позицию FFUSDT без сигнала, и выставила для неё TP/SL ордера.

## 🔍 Анализ

### Что происходит:

1. **Синхронизация позиций (main.py, строки 545-563):**
   - Система находит ВСЕ позиции на бирже через `fetch_positions()`
   - Для каждой позиции вызывает `upsert_active_position()`
   - Создает позицию в локальной БД, если её там нет
   - Выставляет TP/SL ордера (строки 584-673)

2. **Проблема:**
   - Система НЕ проверяет, была ли позиция открыта системой или вручную
   - Если на бирже есть позиция (откуда бы она ни взялась), система автоматически:
     - Создает её в локальной БД
     - Выставляет TP/SL ордера
     - Начинает отслеживать её

3. **Результат:**
   - LONG позиция FFUSDT на бирже (откуда-то взялась)
   - Синхронизация нашла её
   - Создала в локальной БД
   - Выставила TP/SL ордера (2 отложенных ордера)
   - Пользователь получил уведомления о позиции, которую не открывал

### Возможные причины LONG позиции:

1. **Ошибка при закрытии SHORT:**
   - Если SHORT закрывался без `reduceOnly=True`, могла открыться LONG
   - Но в коде `place_stop_loss_order()` и `place_take_profit_order()` используют `reduceOnly=True` ✅

2. **Ошибка в определении направления:**
   - В `main.py` строка 547: `hold_side = p.get('side') or p.get('info', {}).get('holdSide', '')`
   - Если `holdSide` определился неправильно, может быть создана неправильная позиция

3. **Ручное открытие:**
   - Пользователь утверждает, что не открывал позицию вручную
   - Но возможно, это было сделано случайно или другой системой

4. **Реверсивная операция:**
   - При закрытии SHORT может открыться LONG (если не используется `reduceOnly`)
   - Но система использует `reduceOnly` для TP/SL ✅

## 🔧 Решение

### Вариант 1: Проверка источника позиции (рекомендуется)

Добавить проверку: позиция должна быть создана из сигнала, а не просто найдена на бирже.

```python
# В main.py, строка 556:
# Проверяем, есть ли сигнал для этой позиции в signals_log
signal_data = await adb_local.get_signal_data(uid, symbol)
if not signal_data:
    logger.warning(
        "⚠️ [SYNC] Позиция %s найдена на бирже, но нет сигнала в БД. "
        "Пропускаем создание (позиция не из системы)",
        symbol
    )
    continue  # Не создаем позицию без сигнала

# Только если есть сигнал - создаем позицию
await adb_local.upsert_active_position(...)
```

### Вариант 2: Флаг "синхронизирована из биржи"

Добавить флаг `synced_from_exchange` в таблицу `active_positions`:

- `False` - позиция создана из сигнала (системная)
- `True` - позиция найдена на бирже и синхронизирована (не управляется системой)

### Вариант 3: Отключить автоматическое создание из биржи

Убрать автоматическое создание позиций из биржи:

- Только закрывать позиции, которых нет на бирже
- НЕ создавать позиции, которых нет в локальной БД

## 📋 План исправления

1. ✅ **Добавить проверку сигнала перед созданием позиции**
2. ✅ **Добавить логирование источника позиции**
3. ✅ **Исключить выставление TP/SL для позиций без сигнала**
4. ✅ **Добавить предупреждение пользователю о несинхронизированных позициях**

## 🚨 Критичность

**ВЫСОКАЯ** - система может создавать и управлять позициями, которые не были открыты через систему, что приводит к:

- Неожиданным уведомлениям
- Автоматическому выставлению TP/SL для ручных позиций
- Путанице в отслеживании позиций
