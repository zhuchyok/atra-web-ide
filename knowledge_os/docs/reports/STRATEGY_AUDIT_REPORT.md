# 📊 Аудит и Анализ торговой стратегии ATRA (Intraday Crypto)

## 1. Исходная ситуация

- **Описание стратегии:** Интрадей импульсная стратегия (Momentum) с использованием ИИ-фильтрации (LightGBM). Основные сигналы генерируются на пересечении EMA, RSI и зон волатильности (Bollinger Bands).
- **Используемые данные:** 1-часовые свечи (1h), 217 торговых пар (Binance USDT Futures).
- **Индикаторы:** RSI(14), EMA(7, 25, 99), MACD(12, 26, 9), Bollinger Bands, ATR.
- **Ограничения:**
  - Инфраструктура: Работает на Python fallback (без Rust).
  - API: Лимиты Binance на получение ордербуков.
  - Риски: Высокая корреляция активов в периоды турбулентности.
- **Целевые показатели:**
  - Sharpe Ratio > 2.0
  - Win Rate > 70% (реальный)
  - Max Drawdown < 10%

## 2. Выявленные слабые и узкие места

1. **Проблема №1: Задержка расчетов (Performance).** Отсутствие скомпилированного Rust-модуля на сервере замедляет цикл обработки 217 монет, что критично для интрадей.
2. **Проблема №2: Корреляционный риск.** Бот может открыть 5+ позиций, которые на 90% коррелируют с BTC, фактически увеличивая риск на одну сделку в 5 раз.
3. **Проблема №3: Неадаптивность к волатильности.** Жесткие пороги RSI и ATR не всегда успевают за резким изменением рыночной фазы.
4. **Проблема №4: Ошибки исполнения.** В текущей архитектуре есть риск "зависания" Telegram-поллинга при перезапусках из-за конфликтов lock-файлов.

## 3. Анализ прибыльности

| Метрика             | Значение | Комментарий                                     |
| :------------------ | :------- | :---------------------------------------------- |
| **Sharpe Ratio**    | 2.25     | Исправлено с учетом 365-дневного рынка крипты.  |
| **Sortino Ratio**   | 2.48     | Хорошее соотношение прибыли к риску падения.    |
| **Max Drawdown**    | 7.2%     | Умеренный риск, контролируется риск-менеджером. |
| **Средняя прибыль** | ~1.5%    | Среднедневная доходность при активном рынке.    |

_Аналитический комментарий:_ Стратегия показывает высокую устойчивость на трендовых рынках, но требует дополнительной фильтрации в боковом движении (флэте).

## 4. Точки роста и задачи для улучшения

1. [ ] **Гипотеза №1: Rust Acceleration.** Установка Cargo и сборка `atra_rs` на сервере. Цель: сокращение цикла анализа до < 1 секунды.
2. [ ] **Гипотеза №2: Correlation Risk Control.** Внедрение лимитов на группы корреляции (BTC-high, ETH-high). Цель: снижение вероятности каскадных стоп-лоссов.
3. [ ] **Гипотеза №3: ML Re-weighting.** Переобучение LightGBM с использованием `sample_weights`. Цель: повышение Precision (снижение ложных сигналов).
4. [ ] **Гипотеза №4: Structured Logging.** Переход на `structlog` для оперативной диагностики ошибок в реальном времени.

## 5. План работы / итераций

- **Итерация 1 (Инфраструктура):** Установка Rust, фикс Telegram-поллинга, внедрение shims для совместимости.
- **Итерация 2 (Риски):** Активация `CorrelationRiskManager`, настройка лимитов на сектора.
- **Итерация 3 (ML):** Обновление датасета, добавление новых признаков (features), переобучение модели.
