### **3. Группы корреляции**

**Логика группировки:**

```
1. Вычисляется корреляция к BTC, ETH, SOL
2. Определяется максимальная корреляция
3. Группа: БАЗА_УРОВЕНЬ (например, BTC_HIGH)
```

**Пороги корреляции:**

```
HIGH (>0.75): Активы движутся вместе с базой
MEDIUM (0.50-0.75): Средняя зависимость
LOW (0.25-0.50): Слабая зависимость
INDEPENDENT (<0.25): Независимые активы
```

**Лимиты по группам:**

```python
BTC_HIGH: 2 сигнала (самые связанные с BTC)
BTC_MEDIUM: 3 сигнала
BTC_LOW: 4 сигнала
BTC_INDEPENDENT: 4+ сигнала (много независимых)

ETH_HIGH: 2 сигнала (экосистема ETH)
ETH_MEDIUM: 3 сигнала
ETH_LOW: 4 сигнала
ETH_INDEPENDENT: 4+ сигнала

SOL_HIGH: 2 сигнала (экосистема SOL)
SOL_MEDIUM: 3 сигнала
SOL_LOW: 4 сигнала
SOL_INDEPENDENT: 4+ сигнала
```

## 🎯 **КАК РАБОТАЕТ**

### **Проверка корреляции:**

1. Генерируется сигнал для символа (например, LINKUSDT)
2. Вычисляется корреляция к BTC, ETH, SOL
3. Определяется максимальная корреляция (например, ETH=0.85)
4. Определяется группа (например, ETH_HIGH)
5. Проверяются активные сигналы в группе ETH_HIGH
6. Сравнивается с лимитом группы (макс. 2 сигнала)
7. Если лимит достигнут → сигнал блокируется
8. Если лимит не достигнут → сигнал разрешается

### **Примеры группировки:**

```
ETHUSDT → Высокая корреляция к BTC (0.90) → BTC_HIGH
LINKUSDT → Высокая корреляция к ETH (0.85) → ETH_HIGH
DOGEUSDT → Низкая корреляция к BTC (0.30) → BTC_LOW
RAYUSDT → Высокая корреляция к SOL (0.75) → SOL_HIGH
```

### **Сохранение истории:**

1. После успешной отправки сигнала
2. Вычисляется корреляция к BTC/ETH/SOL
3. Определяется группа
4. Данные сохраняются в таблицу `risk_signal_history`
5. Кэшируются в памяти для быстрого доступа

## 🛡️ **ЗАЩИТА ОТ ОШИБОК**

**Обработка ошибок:**

- ✅ Если CorrelationRiskManager недоступен → сигналы проходят без проверки
- ✅ Если ошибка БД → используется in-memory кэш
- ✅ Если ошибка проверки → сигнал разрешается (не блокируется)
