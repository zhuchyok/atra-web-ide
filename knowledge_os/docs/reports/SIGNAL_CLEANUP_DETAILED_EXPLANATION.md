# 🧹 SIGNAL CLEANUP - ПОДРОБНОЕ ОБЪЯСНЕНИЕ

## ❓ **ЧТО ЭТО ТАКОЕ:**

**Signal Cleanup** - это фоновая задача автоматической очистки старых/просроченных сигналов из базы данных.

---

## 🔍 **ЧТО ОНА ДЕЛАЕТ:**

### **Основные функции:**

#### **1. Очистка просроченных сигналов:**

```python
# Удаляет сигналы старше X дней из таблиц:
- signals (основная таблица сигналов)
- signals_log (лог всех сигналов)
- signal_accum_events (события накопления)
- active_signals (активные сигналы)
```

#### **2. Маркировка истекших:**

```python
# Сигналы старше 24-48 часов:
UPDATE signals
SET status = 'EXPIRED'
WHERE created_at < NOW() - INTERVAL '24 hours'
AND status = 'PENDING'
```

#### **3. Удаление завершенных:**

```python
# Сигналы со статусом TP1/TP2/SL старше 7 дней:
DELETE FROM signals
WHERE status IN ('TP1', 'TP2', 'SL', 'CLOSED')
AND created_at < NOW() - INTERVAL '7 days'
```

---

## ⚙️ **КАК РАБОТАЕТ:**

### **Периодичность:**

```python
while True:
    await cleanup_old_signals()
    await asyncio.sleep(3600)  # Каждый час
```

### **Что очищается:**

| Таблица                 | Условие удаления   | Период хранения |
| ----------------------- | ------------------ | --------------- |
| **signals**             | status = 'EXPIRED' | 7 дней          |
| **signals_log**         | Любые записи       | 30 дней         |
| **signal_accum_events** | Истек TTL          | По TTL          |
| **active_signals**      | status != 'ACTIVE' | 7 дней          |
| **app_cache**           | expires_at < NOW   | По expires      |

### **Логика:**

**В нашей системе сигналы - это РУЧНАЯ торговля:**

1. ✅ Бот присылает сигнал
2. ✅ Пользователь **САМ** принимает/отклоняет
3. ✅ Пользователь **САМ** закрывает позицию
4. ❌ Система **НЕ** закрывает автоматически

**Автоматическая очистка может:**

- ❌ Удалить сигналы, которые пользователь еще анализирует
- ❌ Потерять историю открытых позиций
- ❌ Конфликтовать с ручным управлением

---

## ✅ **НУЖНО ЛИ ВКЛЮЧАТЬ?**

### **Аргументы ЗА:**

1. ✅ **Чистая БД** - удаление старых данных
2. ✅ **Производительность** - меньше записей = быстрее запросы
3. ✅ **Освобождение места** - БД не растет бесконечно

### **Аргументы ПРОТИВ:**

1. ❌ **Потеря истории** - удаляет данные для анализа
2. ❌ **Конфликт с ручным управлением** - пользователь может держать позицию долго
3. ❌ **AI теряет данные** - меньше данных для обучения

## 💡 **АЛЬТЕРНАТИВНОЕ РЕШЕНИЕ:**

### **Если БД растет слишком быстро:**

#### **Вариант 1: Настроить retention_tasks (УЖЕ РАБОТАЕТ):**

```python
# В config.py или где задаются периоды:
RETENTION_SIGNALS_LOG_DAYS = 60  # Хранить 60 дней вместо 30
RETENTION_APP_CACHE_DAYS = 7     # Очищать кэш через 7 дней
```

#### **Вариант 2: Архивирование вместо удаления:**

```python
# Создать таблицу archived_signals
# Переносить туда старые сигналы
# Удалять только из архива через год
```

#### **Вариант 3: Выборочная очистка:**

```python
# Удалять только:
- REJECTED сигналы старше 7 дней
- EXPIRED сигналы старше 14 дней
- Кэш старше 24 часов

# НЕ удалять:
- ACCEPTED/OPEN сигналы (любого возраста)
- Завершенные сделки (для AI)
```

## 📊 **СРАВНЕНИЕ:**

### **Retention Tasks (АКТИВНО):**

```
Период: 30 дней
Что удаляет: ОЧЕНЬ старые данные
Частота: 1 раз в день
Риск: Низкий
Польза: Контроль размера БД
```

### **Signal Cleanup (ОТКЛЮЧЕНО):**

```
Период: 24-48 часов
Что удаляет: Даже свежие неприняные
Частота: Каждый час
Риск: ВЫСОКИЙ (потеря данных)
Польза: Чистая БД (но ценой потери истории)
```
