## 1. ИСХОДНАЯ СИТУАЦИЯ

### 📊 Описание стратегии

**Тип:** Интрадей-торговля на криптовалютном рынке (24/7)

**Основная стратегия:**

- **Enhanced Bollinger Bands** с автоматической оптимизацией параметров
- **Multi-timeframe анализ** (1h основной таймфрейм)
- **Breakout и Mean Reversion** паттерны с приоритетной системой
- **AI-оптимизированные TP/SL** на основе 50,508 накопленных паттернов
- **Корреляционный риск-менеджмент** (BTC/ETH/SOL сегментация)

**Режимы работы:**

- **Strict mode**: Высокое качество сигналов (порог score ≥ 55)
- **Soft mode**: Больше сигналов, умеренное качество (порог score ≥ 44)
- **Trade modes**: Spot и Futures (с ограничениями для SHORT в spot)

**Индикаторы:**

- Bollinger Bands (20, 2.0)
- EMA (12, 39, 50)
- RSI (14)
- MACD
- ADX
- Volume профиль
- ATR (15) для волатильности
- Stochastic
- Williams %R

### 📈 Используемые данные и параметры

**Источники данных:**

- **Основной:** Binance API (20 req/min)
- **Резервные:** Bybit (10 req/min), OKX (10 req/min)
- **Дополнительные:** CoinGecko (3 req/min), CryptoRank

**Биржа исполнения:**

- Bitget (Spot и Futures/Swap)
- Hedge mode для futures (holdSide параметр)

**Параметры риска:**

- **Максимум позиций:** 6 одновременно
- **Риск на сделку:** 1.85% (динамический)
- **Плечо:** 1.9x (динамическое, 1x-7x)
- **Портфельный риск:** 8% максимум
- **Минимальный нотионал:** 200 USDT на позицию

**TP/SL уровни:**

- **TP1:** 0.5% - 2.2% (AI-оптимизированный)
- **TP2:** 1.0% - 4.4% (AI-оптимизированный)
- **SL:** ATR-based, динамический

### 🚫 Ограничения

**API и инфраструктура:**

- ✅ Комиссии: Spot 0.10%, Futures 0.04%
- ✅ Rate limits: Безопасные лимиты соблюдаются
- ⚠️ Зависимость от публичных API (без ключей)
- ⚠️ Latency: 1-2 секунды на запрос данных
- ⚠️ Telegram доставка: 8.33% потерь (Flood control)

**Торговые ограничения:**

- ❌ SHORT недоступен в spot режиме
- ❌ Максимум 1 позиция на символ
- ⚠️ Минимальная капитализация: 100M USD
- ⚠️ Минимальный объем 24h: 20M USD

**Регуляторные:**

- KYC требования Bitget
- Ограничения на некоторые монеты по юрисдикции

### 🎯 Целевые показатели

**Прибыльность:**

- **Цель:** Sharpe Ratio > 1.5
- **Цель:** Sortino Ratio > 2.0
- **Цель:** Max Drawdown < 15%

## 2. ВЫЯВЛЕННЫЕ СЛАБЫЕ И УЗКИЕ МЕСТА

### ❌ Проблема №1: Недостаточное использование накопленных паттернов

**Описание:**

- Накоплено **50,508 паттернов** в `trading_patterns.json`
- AI оптимизатор TP/SL только недавно начал их использовать
- До интеграции использовалось только ~100 последних сделок (0.2% данных)

**Обоснование:**

```python
# ai_learning_data/learning_metrics.json
{
  "total_patterns": 1733886,
  "successful_patterns": 175857,
  "accuracy": 0.101  # Только 10.1% accuracy - низкая эффективность
}
```

**Влияние:**

- Потеря 30-40% потенциальной эффективности TP/SL
- Неоптимальные уровни выхода
- Избыточные просадки из-за неудачных TP

**Критичность:** 🔴 ВЫСОКАЯ

---

### ❌ Проблема №2: Низкая точность входов

**Описание:**

- Частые входы против первоначального направления
- Потери из-за преждевременных стопов
- Недостаточная фильтрация ложных сигналов

**Реализованные улучшения:**

- ✅ Проверка BTC тренда
- ✅ Минимум 3 из 4 подтверждений индикаторов
- ✅ RSI фильтр (LONG: RSI < 65, SHORT: RSI > 35)

**Остающиеся проблемы:**

- ⚠️ MTF подтверждение работает только в soft mode
- ⚠️ Нет фильтрации по времени суток (сессии)
- ⚠️ Отсутствует проверка ликвидности в реальном времени

**Критичность:** 🟡 СРЕДНЯЯ (частично решена)

---

**Описание:**


**Влияние:**

- Пользовательский опыт ухудшается

**Критичность:** 🟡 СРЕДНЯЯ

### ❌ Проблема №4: Упрощенный расчет метрик производительности

**Описание:**

- Sharpe/Sortino рассчитываются упрощенно в некоторых модулях
- Нет единого централизованного расчета
- Разные методы расчета в разных модулях

**Примеры несоответствий:**

```python
# capital_management.py - упрощенный расчет
volatility = max_drawdown / 100  # Неправильно!

# performance_tracker.py - корректный расчет
volatility = np.std(returns)  # Правильно
```

**Влияние:**

- Некорректная оценка рисков
- Неправильное сравнение стратегий
- Сложность анализа реальной производительности

**Критичность:** 🟡 СРЕДНЯЯ

```python
    Args:
        trades: Список сделок с PnL
        risk_free_rate: Безрисковая ставка (годовая, 2%)
    """
    if not trades:
        return {}

    # Извлекаем доходности (дневные)
    pnl_values = [t['pnl'] for t in trades]
    dates = [t['exit_time'] for t in trades]

    # Группируем по дням (крипторынок работает 24/7)
    df = pd.DataFrame({'date': dates, 'pnl': pnl_values})
    daily_pnl = df.groupby(df['date'].dt.date)['pnl'].sum()

    # Рассчитываем дневные доходности
    daily_returns = daily_pnl.pct_change().dropna()

    # Годовая доходность (365 дней для крипторынка)
    annual_return = daily_returns.mean() * 365

    # Волатильность (годовая)
    volatility = daily_returns.std() * np.sqrt(365)

    # Sharpe Ratio (для 24/7 рынка)
    sharpe_ratio = (annual_return - risk_free_rate) / volatility if volatility > 0 else 0

    # Sortino Ratio (только отрицательные доходности)
    negative_returns = daily_returns[daily_returns < 0]
    downside_vol = negative_returns.std() * np.sqrt(365) if len(negative_returns) > 0 else 0
    sortino_ratio = (annual_return - risk_free_rate) / downside_vol if downside_vol > 0 else 0

    # Max Drawdown
    cumulative = (1 + daily_returns).cumprod()
    rolling_max = cumulative.expanding().max()
    drawdown = (cumulative - rolling_max) / rolling_max
    max_drawdown = abs(drawdown.min()) * 100

    return {
        'sharpe_ratio': sharpe_ratio,
        'sortino_ratio': sortino_ratio,
        'max_drawdown_pct': max_drawdown,
        'annual_return_pct': annual_return * 100,
        'volatility_pct': volatility * 100
    }
```

```python
async def filter_symbols_by_liquidity(symbols: List[str], min_volume_24h: float = 20_000_000) -> List[str]:
    """
    Фильтрация символов по ликвидности и спреду

    Args:
        symbols: Список символов для фильтрации
        min_volume_24h: Минимальный объем 24h (USD)

    Returns:
        Отфильтрованный список символов
    """
    filtered = []

    for symbol in symbols:
        try:
            # Получаем данные с биржи
            ticker = await exchange.fetch_ticker(symbol)

            # Проверяем объем
            volume_24h = ticker['quoteVolume']  # В базовой валюте (USDT)
            if volume_24h < min_volume_24h:
                continue

            # Проверяем спред
            bid = ticker['bid']
            ask = ticker['ask']
            spread_pct = ((ask - bid) / bid) * 100

            if spread_pct > 2.0:  # Максимальный спред 2%
                continue

            filtered.append(symbol)

        except Exception as e:
            logger.warning(f"Ошибка проверки {symbol}: {e}")
            continue

    return filtered
```

### 📝 Адаптация индикаторов к волатильности

```python
def calculate_adaptive_tp_sl(atr: float, base_tp: float, base_sl: float, volatility_regime: str) -> Tuple[float, float]:
    """
    Адаптация TP/SL к волатильности

    Args:
        atr: Average True Range
        base_tp: Базовый TP (процент)
        base_sl: Базовый SL (процент)
        volatility_regime: 'LOW', 'NORMAL', 'HIGH', 'EXTREME'

    Returns:
        (tp, sl) адаптированные уровни
    """
    multipliers = {
        'LOW': {'tp': 0.8, 'sl': 0.9},      # Узкие уровни в низкой волатильности
        'NORMAL': {'tp': 1.0, 'sl': 1.0},    # Стандартные уровни
        'HIGH': {'tp': 1.3, 'sl': 1.2},      # Широкие уровни в высокой волатильности
        'EXTREME': {'tp': 1.5, 'sl': 1.5}    # Очень широкие уровни
    }

    mult = multipliers.get(volatility_regime, multipliers['NORMAL'])

    # Адаптируем к ATR
    atr_multiplier = atr / 100  # Нормализуем ATR
    tp = base_tp * mult['tp'] * (1 + atr_multiplier)
    sl = base_sl * mult['sl'] * (1 + atr_multiplier)

    return tp, sl
```
