## 📋 Проблема

Пользователь сообщил, что в статусе бота отображается некорректное количество сигналов за сегодня:

```
Статус бота:
Торговые часы: не установлены (торговля 24/7)
Режим: Строгий
Сигналов за сегодня: 0
```

## 🔍 Диагностика

### 1. Анализ файла сигналов

- Проверил файл `signals_log.csv` - файл существует и содержит данные
- В файле есть 3 записи сигналов:
  - `2025-07-28 20:45:28.297131+03:00` - BTCUSDT
  - `2025-07-30 09:15:53.552024+03:00` - TRXUSDT
  - `2025-07-30 09:20:57.371864+03:00` - TRXUSDT

### 2. Выявление корневой причины

**Проблема:** Ошибка `TypeError: Invalid comparison between dtype=datetime64[ns, UTC+03:00] and Timestamp`

**Причина:** Несовместимость timezone-aware и timezone-naive datetime объектов:

- В файле `signals_log.csv` время хранится с timezone (`UTC+03:00`)
- В коде использовался timezone-naive datetime для сравнения
- Pandas не может сравнивать объекты с разными timezone-атрибутами

### 3. Анализ кода

**Проблемный код в `status_cmd`:**

```python
df["entry_time"] = pd.to_datetime(df["entry_time"])
n_signals = (df["entry_time"] >= pd.Timestamp.now().normalize()).sum()
```

## 🛠️ Исправления

### Обновлена функция `status_cmd` в `telegram_bot.py`

**Изменения в подсчете сигналов:**

```python
# Исправляем проблему с timezone - приводим к UTC для корректного сравнения
today_start = pd.Timestamp.now().tz_localize(None).normalize()
# Убираем timezone из entry_time для корректного сравнения
df["entry_time_no_tz"] = df["entry_time"].dt.tz_localize(None)
n_signals = (df["entry_time_no_tz"] >= today_start).sum()
```

**Что было исправлено:**

1. ✅ Убираем timezone из текущего времени (`tz_localize(None)`)
2. ✅ Убираем timezone из времени сигналов (`dt.tz_localize(None)`)
3. ✅ Теперь сравнение происходит между timezone-naive объектами
