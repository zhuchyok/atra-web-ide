# Анализ проблемы с автоматическим закрытием позиций

## 🔍 Проблема

Пользователь сообщает, что новые сигналы не присылаются, и позиции не закрываются автоматически после:

- Достижения TP2
- Ручного закрытия
- Срабатывания стоп-лосса

## 📊 Анализ кода

### ✅ Что работает:

1. **Проверка TP1 и TP2** (`signal_live.py:10632-11332`)
   - Функция `check_take_profits()` проверяет достижение TP1 и TP2
   - При достижении TP2 позиция закрывается:
     ```python
     pos["stage"] = "tp2_reached"
     pos["status"] = "closed"
     pos["qty"] = 0.0
     pos["closed_at"] = datetime.now().isoformat()
     ```

2. **Проверка безубытка после TP1** (`signal_live.py:10768-10777`)
   - Система проверяет стоп-лосс только ПОСЛЕ достижения TP1
   - Если цена достигает безубытка, остаток позиции закрывается

### ❌ Что НЕ работает:

1. **Проверка стоп-лосса для открытых позиций**
   - В коде НЕТ проверки стоп-лосса для позиций со stage="open"
   - Проверка SL есть только для позиций со stage="tp1_reached"
   - **Это критическая проблема!**

2. **Генерация новых сигналов после закрытия позиций**
   - Логика генерации сигналов проверяет наличие открытых позиций
   - После закрытия позиции система должна генерировать новые сигналы
   - Но возможно есть проблема с синхронизацией данных

## 🔧 Необходимые исправления

### 1. Добавить проверку стоп-лосса для открытых позиций

Нужно добавить проверку SL для позиций со stage="open" в функцию `check_take_profits()`:

```python
# После проверки TP2, добавить проверку SL для открытых позиций
if pos.get("stage") == "open" and pos.get("sl") is not None:
    sl_price = pos.get("sl")
    sl_hit = False
    if side == "long" and current_low <= sl_price:
        sl_hit = True
    elif side == "short" and current_high >= sl_price:
        sl_hit = True

    if sl_hit:
        # Закрываем позицию по стоп-лоссу
        # ... (логика закрытия с расчетом убытка)
```

### 2. Проверить синхронизацию данных после закрытия

После закрытия позиции нужно убедиться, что:

- Позиция помечена как закрытая в `user_data["positions"]`
- Позиция удалена из `user_data["open_positions"]`
- Данные сохранены в БД
- Система знает, что может генерировать новые сигналы

### 3. Проверить логику генерации новых сигналов

В функции `check_and_send_signals()` нужно убедиться, что:

- После закрытия позиции система генерирует новые сигналы
- Нет блокировок на генерацию сигналов для закрытых позиций
- Данные пользователя загружаются корректно

## 📝 План исправлений

2. ✅ Добавить логику закрытия позиции при срабатывании SL
3. ✅ Улучшить синхронизацию данных после закрытия
4. ✅ Добавить логирование для отладки
5. ✅ Проверить генерацию новых сигналов после закрытия
