# 🤖 Автоматический анализ сигналов

## 🎯 Принцип работы

Система **полностью автоматически** анализирует качество сигналов без участия человека. Все метрики собираются автоматически, и система сама корректирует свою работу.

---

## 📊 Автоматические механизмы анализа

### 1. **LM-Judge** (анализ перед отправкой)

**Что делает:**

- Анализирует каждый сигнал перед отправкой в Telegram
- Проверяет соответствие техническим условиям
- Выдаёт вердикт: `PASS`, `WARN`, `FAIL`

**Где используется:**

- В каждом сигнале отображается вердикт Judge
- Система учитывает вердикты при обучении

**Пример:**

```
🧾 Judge: ✅ PASS • DOGEUSDT SELL — всё в норме
```

---

### 2. **PnL метрики** (автоматический сбор)

**Что делает:**

- Автоматически собирает PnL при закрытии каждой позиции
- Рассчитывает чистую прибыль с учётом комиссий
- Отслеживает крупные убытки (автоматические алерты при PnL < -10 USD)

**Где используется:**

- `risk_monitor` анализирует PnL каждые 24 часа
- `AdaptiveSignalSystem` использует PnL для оптимизации параметров
- Dashboard показывает статистику PnL

**Автоматические действия:**

- При крупных убытках система отправляет алерты
- Анализирует паттерны убыточных сделок
- Корректирует параметры для предотвращения повторения

---

### 3. **Win Rate** (автоматический расчёт)

**Что делает:**

- Автоматически рассчитывает процент успешных сигналов
- Отслеживает TP1/TP2/SL статистику
- Анализирует эффективность по символам и направлениям

**Где используется:**

- `AdaptiveSignalSystem` использует win rate для корректировки порогов
- `AdaptiveParameterController` оптимизирует параметры на основе win rate
- Dashboard показывает текущий win rate

**Автоматические действия:**

- Если win rate < 55%, система повышает порог score
- Если win rate > 65%, система может снизить порог для большего количества сигналов

---

### 4. **Traces и Audit Logs** (автоматический сбор ошибок)

**Что делает:**

- Автоматически собирает все ошибки из `agent_traces.log`
- Анализирует failed/timeout ордера из `order_audit_log`
- Создаёт "уроки" для каждого агента

**Где используется:**

- `FeedbackAggregator` собирает ошибки каждые 72 часа
- Создаёт guidance для агентов (`signal_live`, `auto_execution`, `risk_monitor`)
- Агенты используют guidance для улучшения своей работы

**Автоматические действия:**

- При повторяющихся ошибках система корректирует логику
- Обновляет параметры на основе накопленных ошибок

---

### 5. **AdaptiveSignalSystem** (автоматическая оптимизация)

**Что делает:**

- Анализирует результаты каждые 3 дня
- Автоматически корректирует порог score для генерации сигналов
- Оптимизирует веса индикаторов

**Где используется:**

- Запускается автоматически через cron
- Использует win rate и PnL для принятия решений

**Автоматические действия:**

- Если win rate < 55% → повышает порог score
- Если win rate > 65% → может снизить порог
- Корректирует веса индикаторов на основе статистики

---

### 6. **AdaptiveParameterController** (непрерывная оптимизация)

**Что делает:**

- Проверяет результаты каждые 1 час
- Оптимизирует параметры при наличии 50+ сделок
- Автоматически обновляет параметры

**Где используется:**

- Работает в фоновом режиме
- Использует PnL и win rate для оптимизации

**Автоматические действия:**

- Корректирует параметры SL, TP, confidence
- Оптимизирует размер позиций
- Адаптирует фильтры под текущие рыночные условия

## 🔄 Цикл автоматического обучения

```
1. Сигнал генерируется
   ↓
2. LM-Judge анализирует сигнал (PASS/WARN/FAIL)
   ↓
3. Сигнал отправляется в Telegram
   ↓
4. Позиция открывается и закрывается
   ↓
5. PnL автоматически собирается
   ↓
6. Win rate автоматически обновляется
   ↓
7. Traces и audit logs собирают ошибки
   ↓
8. FeedbackAggregator создаёт уроки (каждые 72 часа)
   ↓
9. AdaptiveSignalSystem оптимизирует параметры (каждые 3 дня)
   ↓
10. AdaptiveParameterController непрерывно корректирует (каждый час)
    ↓
11. Система улучшается автоматически
```

## 📈 Метрики, которые система отслеживает автоматически

### Финансовые метрики:

- **PnL** (чистая прибыль с учётом комиссий)
- **Win rate** (процент успешных сигналов)
- **Max drawdown** (максимальная просадка)
- **Daily loss** (дневной убыток)

### Операционные метрики:

- **Limit/Market ratio** (соотношение лимитных и маркет ордеров)
- **Order failures** (количество неудачных ордеров)
- **SL/TP placement** (успешность выставления защитных ордеров)
- **Execution latency** (время исполнения)

### Качественные метрики:

- **Judge verdicts** (процент PASS/WARN/FAIL)
- **Signal quality score** (средний score сигналов)
- **Pattern distribution** (распределение типов паттернов)
- **BTC alignment** (соответствие BTC тренду)

## 🛠 Автоматические корректировки

### При низком win rate (< 55%):

- Повышается порог score для генерации сигналов
- Ужесточаются фильтры качества
- Корректируются веса индикаторов

### При высоком win rate (> 65%):

- Может снижаться порог score (больше сигналов)
- Ослабляются фильтры (если это не влияет на качество)
- Оптимизируются параметры для максимизации прибыли

### При крупных убытках (PnL < -10 USD):

- Система отправляет алерты
- Анализирует паттерны убыточных сделок
- Корректирует параметры для предотвращения повторения

### При повторяющихся ошибках:

- Система создаёт "уроки" для агентов
- Корректирует логику на основе накопленных ошибок
- Обновляет параметры для предотвращения повторения

## 📁 Где хранятся данные

### Автоматические метрики:

- **PnL и Win Rate:** `trading.db` → таблицы `signals_log`, `trades`
- **Traces:** `logs/agent_traces.log`
- **Audit Logs:** `trading.db` → таблица `order_audit_log`
- **Guidance:** `configs/guidance/<agent>.json`
- **Prompts:** `configs/prompts/<agent>.yaml`

### Автоматические отчёты:

- **Performance Report:** `data/reports/performance_live_vs_backfill.json`
- **Metrics:** `metrics/*.prom` (Prometheus)
- **Dashboard:** веб-интерфейс на порту 8080

## 🚀 Автоматические скрипты

### Ежечасно:

- `AdaptiveParameterController` — непрерывная оптимизация параметров

### Каждые 24 часа:

- `risk_monitor` — анализ рисков и метрик
- `pm_daily_check.py` — проверка проекта

### Каждые 72 часа:

- `process_feedback.py` — сбор feedback и создание уроков

### Каждые 3 дня:

- `AdaptiveSignalSystem` — оптимизация порогов и весов

## ✅ Преимущества автоматического анализа

1. **Не требует участия человека** — система сама анализирует и корректирует
2. **Непрерывное обучение** — система улучшается с каждой сделкой
3. **Объективные метрики** — основаны на реальных результатах, а не на субъективных оценках
4. **Быстрая адаптация** — система быстро реагирует на изменения рынка
5. **Масштабируемость** — работает для любого количества сигналов и пользователей
