## 🎯 Что реализовано

### 1. ContextEngine - движок для умного выбора контекста

**Файл:** `observability/context_engine.py`

**Функциональность:**

- ✅ `select_context()` - умный выбор релевантного контекста на основе:
  - Текущей миссии агента
  - Истории действий (из trace)
  - Агент-специфичных источников данных
- ✅ `enrich_context()` - обогащение базового контекста дополнительными источниками
- ✅ Кэширование контекста с TTL для оптимизации производительности
- ✅ Поддержка источников: `db`, `file`, `memory`

### 2. Интеграция в агенты

**signal_live:**

- ✅ Автоматический выбор контекста при генерации сигнала
- ✅ Загрузка последних сигналов из БД
- ✅ Обогащение контекста данными о паттернах

**auto_execution:**

- ✅ Автоматический выбор контекста при исполнении ордера
- ✅ Загрузка активных позиций из БД
- ✅ Обогащение контекста данными о рисках

**risk_monitor:**

- ✅ Автоматический выбор контекста при сканировании рисков
- ✅ Загрузка метрик риска из файлов
- ✅ Обогащение контекста данными о защитных ордерах

### 3. Интеграция с PromptManager

**Улучшения:**

- ✅ `get_full_prompt()` теперь использует ContextEngine автоматически
- ✅ Автоматическое обогащение промпта контекстом из `context_sources`
- ✅ Оптимизация через кэширование

## 📊 Как это работает

### Пример использования:

```python
from observability.context_engine import get_context_engine

engine = get_context_engine()

# Умный выбор контекста
context = engine.select_context(
    agent="signal_live",
    mission="BTCUSDT:LONG",
    history=None,  # Можно передать историю из trace
)

# Результат:
# {
#     "mission": "BTCUSDT:LONG",
#     "agent": "signal_live",
#     "timestamp": "2025-11-13T...",
#     "recent_signals": [...],  # Последние сигналы из БД
#     ...
# }
```

### Агент-специфичный контекст:

**signal_live:**

- Последние 20 сигналов за 24 часа
- Статистика по символам

**auto_execution:**

- Активные позиции пользователя
- История ордеров

**risk_monitor:**

- Метрики риска из файлов
- Статус защитных ордеров

## 🚀 Преимущества

1. **Релевантность:** Агенты получают только нужный контекст
2. **Производительность:** Кэширование снижает нагрузку на БД
3. **Гибкость:** Легко добавлять новые источники контекста
4. **Автоматизация:** Не требует ручной настройки для каждого агента
5. **Адаптивность:** Контекст адаптируется к изменяющимся условиям

## 📈 Метрики

- **Кэш TTL:** 3600 секунд (1 час)
- **Источники контекста:** db, file, memory
