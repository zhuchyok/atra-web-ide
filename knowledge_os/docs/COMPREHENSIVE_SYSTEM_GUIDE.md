## **🔧 КРИТИЧЕСКИЕ ИСПРАВЛЕНИЯ**

### **1. 🚨 ДИНАМИЧЕСКИЕ ПАРАМЕТРЫ И CALLBACK_DATA**

#### **ПРОБЛЕМА:**

- Динамические параметры (риск, плечо, TP) рассчитывались в `signal_live.py`
- В `telegram_bot.py` эти параметры пересчитывались заново или использовались статические значения
- Это приводило к несоответствию между сигналом и принятием

#### **РЕШЕНИЕ:**

```python
# В signal_live.py - передаем все динамические параметры
short_leverage = f"{dynamic_leverage:.1f}" if dynamic_leverage else "1.0"
short_tp1 = f"{tp1_pct:.1f}"
short_tp2 = f"{tp2_pct:.1f}"
callback_data = f'accept|{symbol}|{short_time}|{short_price}|{side.lower()}|{short_risk}|{short_leverage}|{short_tp1}|{short_tp2}'

# В telegram_bot.py - парсим переданные параметры
risk_pct = float(data[5]) if len(data) > 5 else user_data.get("risk_pct", 2.0)
leverage = float(data[6]) if len(data) > 6 else user_data.get("leverage", 1)
tp1_pct = float(data[7]) if len(data) > 7 else 1.0
tp2_pct = float(data[8]) if len(data) > 8 else 2.0

# Используем переданные параметры напрямую
dynamic_risk_pct = risk_pct
dynamic_leverage = leverage
dynamic_tp1_pct = tp1_pct
dynamic_tp2_pct = tp2_pct
```

#### **СТАНДАРТ:**

- ✅ Все динамические параметры рассчитываются в `signal_live.py`
- ✅ Передаются через `callback_data` в `telegram_bot.py`
- ✅ В `telegram_bot.py` НЕ пересчитываем параметры заново
- ✅ Используем переданные значения напрямую

---

### **2. 🕐 ВРЕМЕННЫЕ РАМКИ РАСЧЕТОВ**

#### **ПРОБЛЕМА:**

- TP уровни рассчитывались на основе цены генерации сигнала
- Объем позиции рассчитывался на основе актуальной цены принятия
- Это приводило к несоответствию между ожидаемой и фактической прибылью

#### **РЕШЕНИЕ:**

```python
# В telegram_bot.py - все расчеты на момент принятия
# Получаем актуальную цену
ohlc = get_ohlc_binance_sync(symbol, interval="1m", limit=1)
current_price = ohlc[-1]["close"]

# Рассчитываем TP на основе актуальной цены
tp1 = current_price * (1 + dynamic_tp1_pct / 100)
tp2 = current_price * (1 + dynamic_tp2_pct / 100)

# Рассчитываем объем на основе актуальной цены
qty = risk_amount / current_price * dynamic_leverage
```

#### **СТАНДАРТ:**

- ✅ **Момент генерации:** динамические проценты, технический анализ
- ✅ **Момент принятия:** актуальная цена, объем, TP уровни, средняя цена DCA
- ✅ Все критические расчеты происходят на момент принятия

### **3. 💰 РАСЧЕТ СВОБОДНЫХ СРЕДСТВ**

#### **ПРОБЛЕМА:**

- Свободные средства рассчитывались неправильно
- Не учитывались все открытые позиции

#### **РЕШЕНИЕ:**

```python
# Правильный расчет свободных средств
open_positions = user_data.get("open_positions", [])
total_risk = sum(pos.get("risk_amount", 0) for pos in open_positions)
free_deposit = max(deposit - total_risk, 0)
```

#### **СТАНДАРТ:**

- ✅ Суммируем `risk_amount` из всех открытых позиций
- ✅ Свободные средства = депозит - общий риск
- ✅ Минимум 0 (не может быть отрицательным)

### **4. 🔄 DCA ЛОГИКА**

#### **ПРОБЛЕМА:**

- Неправильный расчет `new_qty` для DCA
- Неправильное обновление позиции после DCA

#### **РЕШЕНИЕ:**

```python
# Правильный расчет DCA
dca_risk_amount = free_deposit * dynamic_risk_pct / 100
new_qty = dca_risk_amount / current_price if current_price > 0 else 0

# Правильное обновление позиции
existing_position["qty"] = total_qty
existing_position["entry_price"] = avg_price_new
existing_position["risk_amount"] = existing_position.get("risk_amount", 0) + dca_risk_amount
existing_position["risk_pct"] = dynamic_risk_pct
existing_position["leverage"] = dynamic_leverage
```

#### **СТАНДАРТ:**

- ✅ `new_qty` рассчитывается на основе `dca_risk_amount` и актуальной цены
- ✅ Обновляем все параметры позиции после DCA
- ✅ Новая средняя цена рассчитывается корректно
