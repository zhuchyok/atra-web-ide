# 🔄 Инициализация существующих проектов

## 📋 Описание

Система автоматически создает `.cursorrules` не только для новых проектов, но и для существующих проектов, где их еще нет.

## ⚡ Автоматическая работа

После настройки автоматической инициализации (см. `docs/CURSOR_AUTO_INIT_SETUP.md`), система будет:

1. **При открытии проекта без `.cursorrules`** → автоматически создаст
2. **При открытии проекта с `.cursorrules`, но без универсальных правил** → автоматически добавит универсальные правила
3. **При открытии проекта с полными правилами** → пропустит (не будет перезаписывать)

## 🚀 Массовая инициализация всех существующих проектов

Если у вас много существующих проектов, можно инициализировать их все одной командой:

### Вариант 1: Все проекты в домашней директории

```bash
# Инициализировать все проекты в ~
./scripts/init-cursor-rules-all.sh ~
```

### Вариант 2: Проекты в конкретной директории

```bash
# Инициализировать все проекты в ~/projects
./scripts/init-cursor-rules-all.sh ~/projects

# Или в текущей директории
./scripts/init-cursor-rules-all.sh .
```

### Вариант 3: Проекты в рабочей директории

```bash
# Инициализировать все проекты в ~/Documents/GITHUB
./scripts/init-cursor-rules-all.sh ~/Documents/GITHUB
```

## 📊 Что делает скрипт массовой инициализации

1. **Рекурсивно ищет проекты** в указанной директории (максимальная глубина: 3 уровня)
2. **Определяет проекты** по признакам:
   - Наличие `.git/config`
   - Наличие `package.json`, `requirements.txt`, `pyproject.toml`, `Cargo.toml`, `go.mod`, `pom.xml`
   - Наличие `Makefile` или `README.md`
3. **Проверяет каждый проект**:
   - Если нет `.cursorrules` → создает
   - Если есть `.cursorrules` без универсальных правил → добавляет универсальные правила
   - Если есть полные правила → пропускает
4. **Выводит статистику**:
   - Сколько проектов найдено
   - Сколько инициализировано
   - Сколько пропущено (уже есть правила)
   - Сколько ошибок

## 🔍 Проверка работы

### Проверка одного проекта

```bash
# Перейдите в проект
cd ~/projects/my-project

# Проверьте наличие .cursorrules
ls -la .cursorrules

# Проверьте содержимое
head -20 .cursorrules
```

### Проверка всех проектов

```bash
# Найдите все проекты с .cursorrules
find ~/projects -name ".cursorrules" -type f

# Проверьте, содержат ли они универсальные правила
find ~/projects -name ".cursorrules" -type f -exec grep -l "КОМАНДА ЭКСПЕРТОВ" {} \;
```

## 🛠️ Устранение неполадок

### Проблема: Скрипт не находит проекты

**Решение:** Убедитесь, что проекты имеют признаки проекта (`.git`, `package.json`, `README.md` и т.д.)

### Проблема: Скрипт пропускает проекты

**Решение:** Это нормально, если проект уже имеет `.cursorrules` с универсальными правилами. Скрипт не перезаписывает существующие правила.

### Проблема: Ошибки при инициализации

**Решение:** Проверьте права доступа к директориям и файлам:

```bash
chmod +x scripts/init-cursor-rules.sh
chmod +x scripts/init-cursor-rules-all.sh
```
