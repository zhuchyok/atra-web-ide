# Система накопления DCA сигналов в неторговое время

## 📋 Описание

Реализована система автоматического накопления сигналов на усреднение (DCA) в неторговое время с их отправкой в начале торговой сессии с пересчетом всех параметров на актуальное время.

## ⚙️ Как это работает

### 1. **Накопление сигналов**

- Когда пользователь находится вне торговых часов, система проверяет наличие открытых позиций
- Если есть открытая позиция и генерируется сигнал на усреднение, он сохраняется в `pending_dca_signals`
- Сигналы группируются по символу и стороне (LONG/SHORT)
- Ведется подсчет количества пропущенных сигналов

### 2. **Обработка в начале торговой сессии**

- При первом сигнале в начале торговой сессии (в пределах 1 часа от начала) система обрабатывает накопленные DCA сигналы
- Для каждого накопленного сигнала:
  - Получаются актуальные OHLC данные
  - Пересчитываются все динамические параметры (риск, плечо, TP1, TP2)
  - Рассчитывается новая средняя цена и объем для усреднения
  - Формируется специальное сообщение с пересчитанными параметрами

### 3. **Отправка сигналов**

- Накопленные DCA сигналы отправляются с пометкой "НАКОПЛЕННЫЙ DCA СИГНАЛ"
- Включают информацию о количестве пропущенных сигналов
- Содержат пересчитанные параметры на актуальное время
- Имеют кнопку "⏰ Принять DCA" для быстрого принятия

## 🔧 Техническая реализация

### Функции в `signal_live.py`:

#### `save_pending_dca_signal(user_id, symbol, side, original_price, original_time, user_data)`

- Сохраняет DCA сигнал для отправки в начале торговой сессии
- Группирует сигналы по символу и стороне
- Ведет подсчет количества пропущенных сигналов

#### `process_pending_dca_signals(user_id, user_data)`

- Обрабатывает накопленные DCA сигналы
- Пересчитывает все параметры на актуальное время
- Отправляет сигналы пользователю

### Интеграция в основной цикл:

#### В `check_and_send_signals()`:

```python
# Проверяем торговые часы пользователя
if not check_user_trading_hours(user_data):
    # Проверяем, есть ли у пользователя открытая позиция для DCA
    if has_user_long or has_user_short:
        side = "long" if has_user_long else "short"
        save_pending_dca_signal(user_id, symbol, side, last['close'], now, user_data)
    continue
```

#### В `main_loop()`:

```python
# Проверяем, наступил ли новый день
now = get_msk_now()
if now.date() != current_day:
    current_day = now.date()
    # Сбрасываем флаг обработки DCA для всех пользователей
    for user_id, user_data in user_data_dict.items():
        if 'dca_processed_today' in user_data:
            del user_data['dca_processed_today']
```

## 🔄 Логика работы

### Сценарий 1: Неторговое время

1. Пользователь установил торговые часы 9-18 (МСК)
2. В 22:00 генерируется сигнал на усреднение BTCUSDT LONG
3. Система проверяет торговые часы → пользователь вне торговых часов
4. Система проверяет открытые позиции → есть позиция BTCUSDT LONG
5. Сигнал сохраняется в `pending_dca_signals`

### Сценарий 2: Начало торговой сессии

1. В 9:15 приходит первый сигнал дня
2. Система проверяет накопленные DCA сигналы
3. Находит сохраненный сигнал BTCUSDT LONG
4. Получает актуальные данные и пересчитывает параметры
5. Отправляет накопленный DCA сигнал с пересчитанными параметрами
6. Устанавливает флаг `dca_processed_today = True`

### Сценарий 3: Новый день

1. В полночь система проверяет дату
2. Если дата изменилась, сбрасывает флаг `dca_processed_today` для всех пользователей
3. Готовит систему к новому дню

## 📊 Преимущества системы

1. **Не теряются сигналы** - все DCA сигналы в неторговое время сохраняются
2. **Актуальные параметры** - все расчеты производятся на момент начала торговой сессии
3. **Автоматизация** - не требует ручного вмешательства
4. **Прозрачность** - пользователь видит количество пропущенных сигналов
5. **Безопасность** - система учитывает лимиты усреднений и риски

## 🛡️ Безопасность

- Система проверяет лимиты усреднений перед отправкой
- Учитываются динамические риски и плечи
- Проверяется существование позиции перед обработкой
- Обработка ошибок при получении данных
