# 📊 АНАЛИЗ QUALITY SCORE И РЕКОМЕНДАЦИИ

**Дата:** 2025-11-06  
**Задача:** Проанализировать Quality Score и найти способы улучшения

---

## 📊 КОМПОНЕНТЫ QUALITY SCORE

### Веса компонентов:

1. **Data Quality:** 30% (0.3)
2. **Trend Strength (ADX):** 25% (0.25)
3. **Volume Quality:** 20% (0.2)
4. **Volatility:** 15% (0.15)
5. **RSI Quality:** 10% (0.1)

**Минимальный порог:** 0.70 (70%)

---

## 🔍 АНАЛИЗ КОМПОНЕНТОВ

### 1. Data Quality (30%)

**Логика:**

```python
nan_ratio = nan_count / (len(df) * len(df.columns))
return max(0.0, 1.0 - nan_ratio * 2)
```

**Проблемы:**

- Штраф x2 за NaN может быть слишком строгим
- Не учитывает качество интерполяции

**Рекомендации:**

- Учитывать количество интерполированных значений
- Смягчить штраф для критических NaN

---

### 2. Trend Strength (ADX) (25%)

**Логика:**

```python
if last_adx > 50: return 1.0
elif last_adx > 30: return 0.8
elif last_adx > 20: return 0.6
else: return 0.3
```

**Проблемы:**

- ADX < 20 дает только 0.3 (30% от 25% = 7.5% к общему score)
- Это может быть слишком строго для флэтовых рынков

**Рекомендации:**

- Учитывать рыночный режим (BULL/BEAR/RANGE)
- В RANGE режиме снижать требования к ADX
- Минимальный ADX для RANGE: 0.4 вместо 0.3

---

### 3. Volume Quality (20%)

**Логика:**

```python
if volume_ratio > 2.0: return 1.0
elif volume_ratio > 1.5: return 0.9
elif volume_ratio > 1.2: return 0.8
elif volume_ratio > 1.0: return 0.6
else: return 0.3
```

**Проблемы:**

- Volume ratio < 1.0 дает только 0.3 (30% от 20% = 6% к общему score)
- Это может быть слишком строго для низковолатильных рынков

**Рекомендации:**

- Учитывать рыночный режим
- В LOW_VOL_RANGE режиме снижать требования к объему
- Минимальный volume_ratio для LOW_VOL: 0.8 вместо 0.3

---

### 4. Volatility (15%)

**Логика:**

```python
if 1.0 <= volatility <= 10.0: return 1.0
elif 0.5 <= volatility < 1.0 or 10.0 < volatility <= 15.0: return 0.7
elif volatility < 0.5 or volatility > 15.0: return 0.3
```

**Проблемы:**

- Volatility < 0.5% или > 15% дает только 0.3 (30% от 15% = 4.5% к общему score)
- Это может быть слишком строго для экстремальных рынков

**Рекомендации:**

- Учитывать рыночный режим
- В HIGH_VOL_RANGE режиме повышать требования к volatility
- В LOW_VOL_RANGE режиме снижать требования

---

### 5. RSI Quality (10%)

**Логика:**

```python
if signal_type == "BUY":
    if 40 <= rsi <= 60: return 1.0
    elif 30 <= rsi < 40 or 60 < rsi <= 70: return 0.7
    else: return 0.3
```

**Проблемы:**

- RSI < 30 или > 70 дает только 0.3 (30% от 10% = 3% к общему score)
- Это может быть слишком строго для экстремальных рынков

**Рекомендации:**

- Учитывать рыночный режим
- В BULL_TREND режиме разрешать более высокий RSI для BUY
- В BEAR_TREND режиме разрешать более низкий RSI для SELL

---

## 💡 РЕКОМЕНДАЦИИ ПО УЛУЧШЕНИЮ

### 1. Адаптивные веса по рыночному режиму

**Предложение:**

- В BULL_TREND: повысить вес Trend Strength (30%) и RSI Quality (15%)
- В BEAR_TREND: повысить вес Trend Strength (30%) и RSI Quality (15%)
- В RANGE: повысить вес Volume Quality (25%) и Volatility (20%)

---

### 2. Адаптивные пороги по рыночному режиму

**Предложение:**

- В BULL_TREND: снизить требования к ADX (min 15 вместо 20)
- В BEAR_TREND: снизить требования к ADX (min 15 вместо 20)
- В RANGE: снизить требования к Volume (min 0.8 вместо 1.0)

---

### 3. Улучшение Data Quality

**Предложение:**

- Учитывать качество интерполяции
- Смягчить штраф для критических NaN (x1.5 вместо x2)
