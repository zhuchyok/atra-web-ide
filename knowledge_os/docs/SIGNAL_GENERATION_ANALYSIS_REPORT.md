# Анализ проблемы с генерацией новых сигналов

## 🔍 Проблема

После закрытия позиций (TP2, ручное закрытие, стоп-лосс) система не генерирует новые сигналы.

## 📊 Анализ кода

### ✅ Что работает:

1. **Автоматическое закрытие позиций** (`signal_live.py:11180-11230`)
   - При достижении TP2 позиция помечается как закрытая
   - Обновляется список `open_positions`
   - Данные пользователя сохраняются

2. **Проверка открытых позиций** (`signal_live.py:7644-7652`)
   ```python
   if has_user_long or has_user_short:
       print(f"[DEBUG] {symbol}: Пользователь {user_id} имеет открытую позицию, пропускаем новые торговые сигналы")
       continue
   ```

### ❌ Возможные проблемы:

1. **Синхронизация данных**
   - После закрытия позиции данные могут не обновляться в реальном времени
   - Система может использовать кэшированные данные
   - Проблема с загрузкой обновленных данных пользователей

2. **Время обновления**
   - Система может не генерировать сигналы сразу после закрытия
   - Возможна задержка в обновлении данных
   - Проблема с циклом проверки сигналов

3. **Логика проверки позиций**
   - Система может неправильно определять наличие открытых позиций
   - Проблема с фильтрацией закрытых позиций
   - Ошибка в логике `has_user_long`/`has_user_short`

## 🔧 Диагностика

### 1. Проверить логику проверки открытых позиций

В функции `check_and_send_signals()` есть проверка:

```python
user_positions = [
    p for p in (_positions_all or [])
    if p.get("status", "open") == "open" and float(p.get("qty", 0)) > 0
]
has_user_long = any(
    pos.get("symbol") == symbol and pos.get("side", "long") == "long"
    for pos in user_positions
)
```

**Проблема может быть в том, что:**

- После закрытия позиции `status` не обновляется на "closed"
- `qty` не обнуляется
- Данные не синхронизируются между `positions` и `open_positions`

### 2. Проверить сохранение данных

После закрытия позиции:

```python
save_user_data_for_signals(user_data_dict)
```

**Проблема может быть в том, что:**

- Функция `save_user_data_for_signals()` не работает корректно
- Данные не сохраняются в БД
- При следующей загрузке используются старые данные

### 3. Проверить цикл генерации сигналов

Система генерирует сигналы в цикле каждые несколько минут. **Проблема может быть в том, что:**

- После закрытия позиции система не перезагружает данные пользователей
- Используются кэшированные данные
- Нет принудительного обновления данных

## 🚀 План исправлений

### 1. Добавить принудительное обновление данных

После закрытия позиции принудительно обновить данные пользователей:

```python
# После закрытия позиции
save_user_data_for_signals(user_data_dict)
# Принудительно перезагрузить данные
user_data_dict = load_user_data_for_signals()
```

### 2. Добавить логирование для отладки

Добавить подробное логирование:

```python
print(f"[DEBUG] {symbol}: Проверка позиций пользователя {user_id}")
print(f"[DEBUG] {symbol}: Открытые позиции: {len(user_positions)}")
print(f"[DEBUG] {symbol}: has_user_long: {has_user_long}")
print(f"[DEBUG] {symbol}: has_user_short: {has_user_short}")
```

### 3. Проверить синхронизацию данных

Убедиться, что после закрытия позиции:

- `status` = "closed"
- `qty` = 0.0
- Позиция удалена из `open_positions`
- Данные сохранены в БД

### 4. Добавить принудительную генерацию сигналов

После закрытия позиции принудительно запустить генерацию сигналов:

```python
# После закрытия позиции
await check_and_send_signals(signal_history)
```
