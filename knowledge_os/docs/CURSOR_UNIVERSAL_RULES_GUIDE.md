## 🔍 Как работают правила Cursor

### Местоположение файлов правил

Cursor ищет правила в следующем порядке приоритета:

1. **`.cursorrules` в корне проекта** (высший приоритет)
   - Применяются только к текущему проекту
   - Специфичные для проекта правила

2. **Глобальные настройки Cursor** (если поддерживаются)
   - Находятся в настройках пользователя
   - Применяются ко всем проектам

3. **Встроенные правила Cursor** (по умолчанию)
   - Базовые правила работы агента

### Формат файла `.cursorrules`

```yaml
---
description: "Описание правил"
alwaysApply: true # или false
---
# Ваши правила здесь в формате Markdown
```

```markdown
## 📋 ОБЩИЕ ПРИНЦИПЫ РАЗРАБОТКИ

### Code Quality Standards:

- Всегда использовать type hints
- Документировать все функции и классы
- Покрытие тестами > 80% для критического кода
- Следование стандартам кодирования проекта

### Security Requirements:

- Никогда не коммитить секреты
- Использовать environment variables
- Регулярно обновлять зависимости

### Performance Requirements:

- Оптимизировать latency sensitive код
- Использовать async/await для I/O операций
- Кэшировать часто используемые данные

## 🔄 STATELESS ARCHITECTURE

### Правила:

- ✅ ВСЕГДА передавать состояние через параметры
- ✅ ВСЕГДА возвращать новое состояние вместе с результатом
- ❌ НЕ использовать модульные переменные для накопления данных
- ❌ НЕ использовать `global` для управления состоянием

## 🔁 ОБРАБОТКА ОШИБОК

### Retry Logic:

- Использовать централизованную retry логику
- Exponential backoff для сетевых операций
- Graceful degradation для некритичных операций

## 🕐 ВРЕМЕННАЯ КОНСИСТЕНТНОСТЬ

### Правило:

- Всегда использовать UTC для временных меток
- Явно указывать timezone при работе с datetime
```

## 🚀 Применение правил к новым проектам

### Процесс настройки нового проекта:

1. **Создайте `.cursorrules` в корне нового проекта:**

```bash
# Скопируйте шаблон
cp ~/.cursor/project-template-rules.md /path/to/new-project/.cursorrules
```

2. **Отредактируйте `.cursorrules`:**
   - Заполните описание проекта
   - Укажите архитектуру
   - Добавьте специфичные правила
   - Включите универсальные правила (или ссылку на них)

3. **Проверьте работу:**
   - Откройте проект в Cursor
   - Задайте вопрос агенту
   - Убедитесь, что применяются правила команды экспертов

### Пример для Python проекта:

```markdown
---
description: "Python web application rules"
alwaysApply: true
---

# ПРАВИЛА ПРОЕКТА: Python Web App

## 🌍 УНИВЕРСАЛЬНЫЕ ПРАВИЛА

[Включите универсальные правила]

---
```

## 📚 Рекомендации

### 1. Храните универсальные правила в одном месте

Создайте репозиторий или файл с универсальными правилами, чтобы легко обновлять их для всех проектов.

### 2. Версионируйте правила

Используйте Git для версионирования правил:

```bash
# Создайте репозиторий для правил
git init ~/.cursor-rules
cd ~/.cursor-rules
# Добавьте universal-rules.md
git add universal-rules.md
git commit -m "Initial universal rules"
```

### 3. Регулярно обновляйте

Периодически пересматривайте и обновляйте универсальные правила на основе опыта работы.

### 4. Документируйте изменения

Ведите changelog для универсальных правил:

```markdown
# CHANGELOG

## 2024-01-15

- Добавлено правило о stateless архитектуре
- Обновлена матрица выбора экспертов

## 2024-01-10

- Первоначальная версия универсальных правил
```

## 💡 Примеры использования

### Пример 1: Быстрое создание правил для нового проекта

```bash
#!/bin/bash
# create-cursor-rules.sh

PROJECT_NAME=$1
PROJECT_PATH=$2

cat > "$PROJECT_PATH/.cursorrules" << EOF
---
description: "Rules for $PROJECT_NAME"
alwaysApply: true
---

# ПРАВИЛА ПРОЕКТА: $PROJECT_NAME

## 🌍 УНИВЕРСАЛЬНЫЕ ПРАВИЛА
[Включите универсальные правила из ~/.cursor/universal-rules.md]

## 🎯 СПЕЦИФИЧНЫЕ ПРАВИЛА
[Добавьте специфичные правила для проекта]
EOF

echo "✅ Создан .cursorrules для проекта $PROJECT_NAME"
```

### Пример 2: Скрипт для обновления универсальных правил во всех проектах

```bash
#!/bin/bash
# update-universal-rules.sh

UNIVERSAL_RULES="$HOME/.cursor/universal-rules.md"
PROJECTS_DIR="$HOME/projects"

for project in "$PROJECTS_DIR"/*; do
    if [ -d "$project" ] && [ -f "$project/.cursorrules" ]; then
        echo "Обновление правил в $project..."
        # Логика обновления
    fi
done
```
