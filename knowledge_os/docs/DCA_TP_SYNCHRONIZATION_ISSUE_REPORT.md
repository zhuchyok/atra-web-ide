# Отчет о проблеме с синхронизацией TP в DCA сигналах

**Дата:** 10 августа 2025
**Статус:** 🔍 Диагностика

## Проблема

В DCA сигнале показываются одни TP, а при принятии сигнала система использует другие TP. Это приводит к несоответствию между ожидаемыми и фактическими TP.

## Пример проблемы

### DCA сигнал показывает:

```
🎯 TP1: 0.8332 (+4.2%)
🚀 TP2: 0.8414 (+5.2%)
```

### Команда `/accept` в сигнале:

```
/accept ADAUSDT 2025-08-10T13:36 0.79 4.2 long 4.7 1
```

### Результат принятия сигнала:

```
✅ Позиция по ADAUSDT открыта!
🎯 TP1: 0.8098
🚀 TP2: 0.8178
```

## Диагностика

### 1. **Проблема с командой `/accept`**

Команда передает неправильные параметры:

- **Передается**: `4.2` (процент) вместо `633.0756` (количество)
- **Отсутствуют**: TP значения `0.8332` и `0.8414`

### 2. **Ожидаемая команда должна быть:**

```
/accept ADAUSDT 2025-08-10T13:36 0.79 633.0756 long 4.7 1 0.8332 0.8414
```

### 3. **Проблема в коде**

В `signal_live.py` команда формируется как:

```python
f"<code>/accept {symbol} {now.strftime('%Y-%m-%dT%H:%M')} {last['close']:.2f} {new_qty:.4f} long {risk_pct:.1f} {leverage} {tp1:.4f} {tp2:.4f}</code>\n"
```

Но в реальности передается:

```
/accept ADAUSDT 2025-08-10T13:36 0.79 4.2 long 4.7 1
```

## Возможные причины

### 1. **Кэширование кода**

Изменения в `signal_live.py` могли не примениться из-за кэширования.

### 2. **Проблема с переменными**

Переменные `new_qty`, `tp1`, `tp2` могут иметь неправильные значения.

### 3. **Проблема с форматированием**

Возможно, есть проблема с форматированием строки.

## Добавленные отладочные данные
