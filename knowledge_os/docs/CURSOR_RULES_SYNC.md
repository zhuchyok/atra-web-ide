# 🔄 Синхронизация универсальных правил Cursor

## 📋 Описание

Система синхронизации позволяет обновлять универсальные правила во всех проектах из единой базы `~/.cursor/universal-rules.md`.

## 🎯 Как это работает

### Единая база правил

- **Источник:** `~/.cursor/universal-rules.md` - единая база для всех проектов
- **Копии:** Каждый проект имеет свой `.cursorrules` с копией универсальных правил
- **Синхронизация:** Скрипт `sync-cursor-rules.sh` обновляет правила во всех проектах

### Автоматическое отслеживание изменений

Скрипт синхронизации:

1. Проверяет хеш универсальных правил
2. Сравнивает с последней синхронизацией
3. Обновляет только если правила изменились
4. Сохраняет специфичные правила проекта без изменений

## 🚀 Использование

### Синхронизация всех проектов

```bash
# Синхронизировать все проекты в домашней директории
./scripts/sync-cursor-rules.sh ~

# Синхронизировать проекты в конкретной директории
./scripts/sync-cursor-rules.sh ~/projects
./scripts/sync-cursor-rules.sh ~/Documents/GITHUB
```

### Принудительная синхронизация

Если правила не изменились, но вы хотите обновить все проекты:

```bash
# Скрипт спросит подтверждение
./scripts/sync-cursor-rules.sh ~
# Нажмите 'y' для принудительного обновления
```

## 📊 Что происходит при синхронизации

1. **Сканирование проектов** - находит все проекты с `.cursorrules`
2. **Извлечение специфичных правил** - сохраняет правила проекта (после "## 🎯 СПЕЦИФИЧНЫЕ")
3. **Обновление универсальных правил** - заменяет универсальные правила из `~/.cursor/universal-rules.md`
4. **Сохранение специфичных правил** - восстанавливает специфичные правила проекта
5. **Создание резервной копии** - перед обновлением создается `.cursorrules.backup.TIMESTAMP`

## 🔄 Автоматическая синхронизация

### Вариант 1: При изменении универсальных правил

Создайте alias для быстрой синхронизации:

```bash
# Добавьте в ~/.zshrc или ~/.bashrc
alias sync-cursor-rules='~/Documents/GITHUB/atra/atra/scripts/sync-cursor-rules.sh ~'
```

Теперь после изменения `~/.cursor/universal-rules.md`:

```bash
sync-cursor-rules
```

### Вариант 2: Периодическая синхронизация

Добавьте в cron для автоматической синхронизации:

```bash
# Синхронизация каждый день в 9:00
0 9 * * * /path/to/atra/scripts/sync-cursor-rules.sh ~ > /dev/null 2>&1
```

### Вариант 3: Git hook для автоматической синхронизации

Создайте hook, который синхронизирует правила при коммите изменений в универсальные правила:

```bash
# .git/hooks/post-commit
#!/bin/bash
if git diff-tree --name-only HEAD HEAD~1 | grep -q "docs/examples/universal-cursor-rules.md"; then
    ~/Documents/GITHUB/atra/atra/scripts/sync-cursor-rules.sh ~
fi
```

## 🛠️ Устранение неполадок

### Проблема: Специфичные правила исчезли после синхронизации

**Решение:** Скрипт создает резервные копии. Восстановите из `.cursorrules.backup.TIMESTAMP`:

```bash
# Найдите последнюю резервную копию
ls -lt .cursorrules.backup.* | head -1

# Восстановите
cp .cursorrules.backup.20241214_120000 .cursorrules
```

### Проблема: Синхронизация не находит проекты

**Решение:** Убедитесь, что проекты имеют признаки проекта (`.git`, `package.json`, `README.md` и т.д.)

### Проблема: Хеш не обновляется

**Решение:** Удалите кэш и синхронизируйте заново:

```bash
rm ~/.cursor/sync-cache.json
./scripts/sync-cursor-rules.sh ~
```
