### 🔍 **Найденная проблема:**

1. **DCA сигналы** - передавали `new_qty` и точные TP значения ✅ (уже было правильно)
2. **Обычные сигналы** - передавали `tp1_pct` (процент) вместо точных TP значений ❌
3. **Накопительные DCA сигналы** - передавали `tp1_pct` (процент) вместо точных TP значений ❌

### 📊 **Пример проблемы:**

**DCA сигнал показывал:**

```

🚀 TP2: 0.8414 (+5.2%)
```

**Но команда `/accept` передавала:**

```

```

**Вместо правильной:**

```

```

## Формат команд `/accept`

### **Новый формат для всех сигналов:**

```
/accept SYMBOL TIME PRICE QTY SIDE RISK LEVERAGE TP1 TP2
```

**Пример:**

```
/accept ADAUSDT 2025-08-10T13:36 0.79 633.0756 long 4.7 1 0.8332 0.8414
```

### **Параметры:**

1. `SYMBOL` - символ торговой пары
2. `TIME` - время сигнала (YYYY-MM-ddTHH:MM)
3. `PRICE` - цена входа
4. `QTY` - количество (для DCA) или TP1 (для обычных сигналов)
5. `SIDE` - сторона (long/short)
6. `RISK` - процент риска
7. `LEVERAGE` - плечо
8. `TP1` - точное значение TP1
9. `TP2` - точное значение TP2

## Логика работы

### 1. **Генерация сигнала**

1. Система рассчитывает точные TP значения
2. Формирует команду `/accept` с точными TP
3. Отображает TP в сигнале

### 2. **Принятие сигнала**

1. Пользователь копирует команду `/accept`
2. Система извлекает точные TP значения
3. Использует эти TP для создания позиции
4. Отображает те же TP в подтверждении
