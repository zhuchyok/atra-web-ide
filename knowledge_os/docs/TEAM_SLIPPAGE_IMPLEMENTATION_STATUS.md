## 🔄 КАК РАБОТАЕТ

### 1. Расчет проскальзывания при создании ордера:

```python
# В order_manager.py
slippage = slippage_manager.calculate_dynamic_slippage(
    symbol='SOLUSDT',
    volume_24h=500_000_000,  # 500M USD
    order_size_usd=1000,       # 1000 USD
    volatility=0.035           # 3.5%
)
# Результат: 0.0005 (0.05%) для высокой ликвидности

price = current_price * (1 + slippage)  # Для LONG
```

### 2. Запись реального проскальзывания:

```python
# После исполнения ордера
slippage_manager.record_slippage(
    symbol='SOLUSDT',
    side='buy',
    expected_price=141.00,
    actual_price=141.15,  # Фактическая цена исполнения
    volume_24h=500_000_000,
    order_size_usd=1000,
    volatility=0.035
)
# Записывается slippage_pct = 0.106% (0.00106)
```

### 3. Компенсация при следующей позиции:

```python
# В signal_live.py при расчете entry_amount_usdt
entry_amount_usdt = slippage_manager.get_adjusted_position_size(
    symbol='SOLUSDT',
    base_position_size=1000,  # Базовый размер
    volume_24h=500_000_000
)
# Если среднее проскальзывание >0.15%, размер уменьшается
```

## ✅ ЭТАП 2: Оптимизация исполнения (В ПРОЦЕССЕ)

### 1. ✅ H4.1: Выбор между market и limit ордерами

**Реализовано:**

- ✅ Метод `should_use_limit_order()` в SlippageManager
- ✅ Автоматический выбор типа ордера в `create_market_order()`
- ✅ Порог для limit ордера: 0.15% ожидаемого проскальзывания
- ✅ Limit цена: ±0.05% от текущей цены
- ✅ Учет исторических данных о проскальзывании
- ✅ Расчет потенциальной экономии

**Логика:**

- Если ожидаемое проскальзывание >0.15% → используем LIMIT
- Если среднее проскальзывание за последние 5 сделок >0.15% → используем LIMIT
- Иначе → используем MARKET с динамическим проскальзыванием

**Параметры:**

```python
limit_order_threshold: 0.0015  # 0.15%
limit_price_offset: 0.0005      # ±0.05% от текущей цены
```
