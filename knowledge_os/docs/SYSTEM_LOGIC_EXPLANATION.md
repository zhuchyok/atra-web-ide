## 🔄 ПОЛНЫЙ ЦИКЛ РАБОТЫ СИГНАЛА

### **ЭТАП 1: ГЕНЕРАЦИЯ СИГНАЛА** (`signal_live.py`)

#### 1.1 Получение данных

- Загружаются OHLCV данные через `SourcesHub`
- Проверяется валидность данных (NaN, бесконечности)
- Интерполяция при пропусках

#### 1.2 Расчет индикаторов

- **EMA** (7, 25, 50)
- **Bollinger Bands** (20, 2)
- **RSI** (14)
- **MACD**
- **Volume** (объемы, средние)
- **ATR** (волатильность)
- **ADX** (сила тренда)

#### 1.3 НОВАЯ ЛОГИКА ВХОДА (Pullback Entry) ⭐

**Включено:** `USE_PULLBACK_ENTRY=true`

**Как работает:**

1. **Анализ структуры рынка** (`MarketStructureAnalyzer`)
   - Определяет режим: тренд/флэт/волатильность
   - Определяет направление тренда (uptrend/downtrend)

2. **Поиск точек входа на откатах**
   - Ищет откат к уровням поддержки/сопротивления
   - Проверяет качество входа (`EntryQualityScorer`)
     - Расстояние от экстремума (ATR-based)
     - Паттерны свечей (Engulfing, Hammer, etc.)
     - Подтверждение объемом
     - Близость к уровням (POC, VAH/VAL)

3. **Адаптивная стратегия** (`USE_ADAPTIVE_STRATEGY=true`)
   - **Trend Following**: для трендового рынка
   - **Range Trading**: для флэта
   - **Breakout**: для пробоев
   - **Reversal**: для разворотов
   - Параметры входа адаптируются под режим

4. **Fallback на старую логику**
   - Если Pullback Entry не нашел точку входа
   - Используется EMA crossover (старая логика)

#### 1.4 Фильтрация сигналов

**Базовые фильтры:**

- ✅ **AI Score** (порог: 5.0-25.0 в зависимости от режима)
- ✅ **Volume Filter** (объем выше среднего)
- ✅ **Volatility Filter** (волатильность в диапазоне)
- ✅ **Anomaly Filter** (блокировка манипуляций: 0-4 кружка)
- ✅ **Liquidity Filter** (проверка ликвидности)

**Тренд-фильтры:**

- ✅ **BTC Trend** (выравнивание с BTC)
- ✅ **ETH Trend** (выравнивание с ETH)
- ✅ **SOL Trend** (выравнивание с SOL)

**НОВЫЕ ФИЛЬТРЫ** ⭐ (все включены):

- ✅ **Dominance Trend Filter** (`USE_DOMINANCE_TREND_FILTER=true`)
  - Анализ BTC доминирования
  - Торговля на сдвигах доминирования
  - Определение "altseason"

- ✅ **Interest Zone Filter** (`USE_INTEREST_ZONE_FILTER=true`)
  - Поиск зон накопления ликвидности
  - Анализ объемных кластеров
  - Работа от ключевых уровней

- ✅ **Fibonacci Zone Filter** (`USE_FIBONACCI_ZONE_FILTER=true`)
  - Расчет уровней Фибоначчи (23.6%, 38.2%, 50%, 61.8%)
  - Поиск отскоков от уровней
  - Подтверждение сигналов

- ✅ **Volume Imbalance Filter** (`USE_VOLUME_IMBALANCE_FILTER=true`)
  - Обнаружение дисбаланса объемов (buy/sell)
  - Сигналы на сильных дисбалансах
  - Фильтрация слабых сигналов

**Корреляция:**

- ✅ **Correlation Risk Manager**
  - Группировка по корреляции (BTC_HIGH, ETH_HIGH, SOL_HIGH)
  - Лимиты на одновременные сигналы в группе
  - Кулдаун между сигналами

#### 1.5 Расчет TP/SL

**Базовые TP/SL:**

- TP1: +1.5-2.0% (закрытие 50%)
- TP2: +3.0-4.0% (закрытие 50%)
- SL: -1.5-2.0%

**ДИНАМИЧЕСКИЕ TP/SL** ⭐ (`USE_DYNAMIC_TP_SL_FROM_ZONES=true`)

**Как работает:**

1. **Из Fibonacci зон:**
   - TP1 на уровне 38.2% или 50%
   - TP2 на уровне 61.8% или 78.6%
   - SL за уровнем 23.6%

2. **Из Interest Zones:**
   - TP1 на следующей зоне интереса
   - TP2 на дальней зоне
   - SL за зоной накопления

3. **Адаптация:**
   - Если зоны далеко → используем базовые TP/SL
   - Если зоны близко → корректируем под них

#### 1.6 Отправка сигнала

- Формируется сообщение в Telegram
- Сохраняется в `signals_log` (статус: PENDING)
- Сохраняется в `accepted_signals` (если принят)
- Проверяется режим пользователя (manual/auto)

### **ЭТАП 2: АВТО-ИСПОЛНЕНИЕ** (`auto_execution.py`)

#### 2.1 Проверка окружения

```python
if ATRA_ENV != "prod":
    # БЛОКИРОВКА: DEV/TEST не открывают позиции автоматически
    return False
```

#### 2.2 Проверка режима пользователя

- Читается `user_settings.trade_mode` из БД
- `manual` → только уведомление, позиция не открывается
- `auto` → продолжается исполнение

#### 2.3 Валидация позиции

- Проверка размера позиции (`PositionSizeValidator`)
- Проверка баланса пользователя
- Проверка лимитов риска

#### 2.4 Открытие позиции на бирже

- Создается ордер через `ExchangeAdapter`
- Используется Bitget API (futures)
- Логирование в `order_audit_log`

#### 2.5 Установка TP1/TP2/SL

- **TP1** (50% позиции): `create_plan_order(plan_type="pos_profit")`
- **TP2** (50% позиции): `create_plan_order(plan_type="pos_profit")`
- **SL** (100% позиции): `create_plan_order(plan_type="pos_loss")`

**Fallback:**

- Если `pos_profit` не работает → обычный `reduce_only` limit order

#### 2.6 Обновление БД

- `signals_log`: PENDING → OPEN
- `active_positions`: создается запись
- `accepted_signals`: обновляется статус

### **ЭТАП 3: МОНИТОРИНГ ЦЕН** (`price_monitor_system.py`)

#### 3.1 Проверка TP1

- Каждые 30 секунд проверяется цена
- Если цена достигла TP1:
  1. Закрывается 50% позиции
  2. **SL переносится в безубыток** ⭐
     - Отменяется старый SL ордер
     - Устанавливается новый SL = entry_price + комиссия
     - Обновляется в БД и на бирже
  3. Обновляется `trailing_stop_manager` (tp1_price сохраняется)

#### 3.2 Trailing Stop к TP1 ⭐

**Включено:** `tp1_trailing_enabled=true`

**Как работает:**

1. После установки TP1 начинается trailing
2. Когда цена проходит 50% пути к TP1:
   - SL начинает подтягиваться
   - Формула: `new_sl = entry + (tp1 - entry) * progress * ratio`
   - `progress` = текущий прогресс к TP1 (0.0-1.0)
   - `ratio` = 0.5 (консервативный)
3. При движении SL:
   - Отменяется старый SL ордер на бирже
   - Устанавливается новый SL
   - Обновляется в БД

#### 3.3 Проверка TP2

- Если цена достигла TP2:
  1. Закрывается оставшиеся 50% позиции
  2. Позиция полностью закрыта
  3. Обновляется БД: OPEN → CLOSED

#### 3.4 Проверка SL

- Если цена достигла SL:
  1. Закрывается вся позиция
  2. Обновляется БД: OPEN → CLOSED
  3. Отправляется уведомление пользователю

## ⚠️ ВАЖНЫЕ МОМЕНТЫ

1. **DEV бот НЕ открывает позиции автоматически**
   - Даже если `user.trade_mode='auto'`
   - Проверка: `if ATRA_ENV != "prod": return False`

2. **TP1 может закрыть всю позицию**
   - Проблема Bitget API: `pos_profit` иногда игнорирует `size`
   - Решение: fallback на обычный limit order

3. **Trailing Stop работает только после TP1**
   - До TP1 используется обычный SL
   - После TP1 начинается trailing к TP1

4. **Все фильтры включены по умолчанию**
   - Можно отключить через `config.py` или env переменные
   - Но рекомендуется оставить включенными

5. **Логика одинаковая для PROD и DEV**
   - Разница только в авто-исполнении
   - Сигналы генерируются одинаково
