# 🔴 ПРОБЛЕМА: TP1 закрывает всю позицию вместо 50%

## 📋 Описание проблемы

Пользователь сообщил, что TP1 не выставляется правильно - вместо частичного закрытия (50%) выставляется ордер на закрытие всей позиции.

## 🔍 Анализ

### Текущая реализация:

1. **auto_execution.py** (строка 538):

   ```python
   tp1_amount = _normalize_amount(amount * 0.5)  # 50% от позиции
   ```

2. **exchange_adapter.py** (строка 563):

   ```python
   "size": str(size_precise),  # Передается 50% размера
   ```

3. **Bitget API**:
   - Используется `pos_profit` план-ордер
   - Параметр `size` передается в запросе

### Проблема:

**Bitget `pos_profit` может игнорировать параметр `size` и всегда закрывать всю позицию.**

## ⚠️ Возможные причины:

1. **Bitget API ограничение**: `pos_profit` может не поддерживать частичное закрытие через `size`
2. **Неправильный формат**: Может требоваться другой параметр или метод API
3. **V1 vs V2 API**: Разные версии API могут работать по-разному

## 🔧 Решение:

### Вариант 1: Использовать обычный план-ордер вместо `pos_profit`

Если `pos_profit` не поддерживает частичное закрытие, можно использовать обычный план-ордер с `reduce_only=True`:

```python
# Вместо pos_profit использовать обычный план-ордер
plan_type = "normal_plan"  # или другой тип
# size будет работать корректно
```

### Вариант 2: Проверить документацию Bitget

Нужно проверить официальную документацию Bitget API:

- Поддерживает ли `pos_profit` частичное закрытие?
- Есть ли другой метод для частичного TP1?
- Какие параметры требуются для частичного закрытия?

### Вариант 3: Использовать два отдельных ордера

Вместо одного TP1 на 50%, можно выставить два TP1 ордера:

- TP1a: 25% позиции
- TP1b: 25% позиции
- Итого: 50% закрывается
