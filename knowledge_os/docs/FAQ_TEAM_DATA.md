# ❓ FAQ: Вопросы про `.team_data`

**Дата:** 2025-12-14  
**Статус:** ✅ **АКТУАЛЬНО**

---

## ❓ ЧАСТЫЕ ВОПРОСЫ:

### **Q1: Что делать, если вижу сообщение про `.team_data`?**

**A:** Это **нормально**! Сообщение информационное, не ошибка.

**Варианты:**

1. **Игнорировать** (рекомендуется) — команда работает без `.team_data`
2. **Настроить синхронизацию** — если нужна синхронизация между проектами
3. **Скопировать данные** — если нужны базы знаний в отдельной директории

**См. `docs/TEAM_DATA_EXPLANATION.md` для подробностей.**

---

### **Q2: Нужен ли `.team_data` для работы команды?**

**A:** **НЕТ!** Для работы команды достаточно только `.cursorrules`.

`.team_data` нужен **ТОЛЬКО** для:

- Синхронизации данных между проектами
- Централизованного хранения баз знаний
- Автоматического обновления через Git

---

### **Q3: Как убрать сообщение про `.team_data`?**

**A:** Есть несколько вариантов:

**Вариант 1: Игнорировать (рекомендуется)**

```bash
# Просто продолжайте работать - всё работает!
```

**Вариант 2: Создать пустую директорию**

```bash
mkdir -p .team_data
touch .team_data/.gitkeep
```

**Вариант 3: Настроить полную синхронизацию**

```bash
bash scripts/copy_team_to_new_project.sh /path/to/new-project
```

---

### **Q4: Как настроить синхронизацию между проектами?**

**A:** См. `docs/STEP_BY_STEP_NEW_PROJECT_SETUP.md` раздел "ПОЛНЫЙ СПОСОБ".

**Кратко:**

```bash
# 1. Скопировать скрипты
cp /path/to/atra/scripts/sync_team_data.py /path/to/new-project/scripts/
cp /path/to/atra/scripts/setup_team_sync.sh /path/to/new-project/scripts/

# 2. Настроить
bash scripts/setup_team_sync.sh

# 3. Или использовать автоматический скрипт
bash scripts/copy_team_to_new_project.sh /path/to/new-project
```

---

### **Q5: Можно ли использовать команду без `.team_data`?**

**A:** **ДА!** Это **рекомендуемый** вариант для начала.

**Минимальная настройка:**

```bash
cp /path/to/atra/.cursorrules /path/to/new-project/.cursorrules
```

**Готово!** Команда работает.

---

### **Q6: В чем разница между `.cursorrules` и `.team_data`?**

**A:**

| `.cursorrules`         | `.team_data`                   |
| ---------------------- | ------------------------------ |
| ✅ **ОБЯЗАТЕЛЬНО**     | ⚠️ **ОПЦИОНАЛЬНО**             |
| Правила работы команды | Данные команды (базы знаний)   |
| Активация экспертов    | Синхронизация между проектами  |
| Один файл              | Директория с файлами           |
| Достаточно для работы  | Нужен только для синхронизации |

### **Q8: Нужен ли Git для `.team_data`?**

**A:** **НЕТ!** Git нужен **ТОЛЬКО** для синхронизации между проектами.

**Варианты:**

- **Без Git:** Просто скопируйте `.team_data` из проекта ATRA
- **С Git:** Настройте центральный репозиторий для синхронизации

### **Q9: Можно ли использовать команду в нескольких проектах?**

**A:** **ДА!** Есть два способа:

**Способ 1: Без синхронизации (проще)**

```bash

cp /path/to/atra/.cursorrules /path/to/project1/.cursorrules
cp /path/to/atra/.cursorrules /path/to/project2/.cursorrules
```

**Способ 2: С синхронизацией (для общих данных)**

```bash
# Настроить центральный репозиторий
# См. docs/TEAM_DATA_SYNC_SYSTEM.md
```

### **Q10: Что делать, если команда не активируется?**

**A:** Проверьте:

1. **Файл `.cursorrules`** в корне проекта:

   ```bash
   ls -la .cursorrules
   ```

2. **Перезапустите Cursor IDE**

3. **Откройте новый чат** (не продолжайте старый)

4. **Проверьте формат запроса:**
   - ✅ Правильно: "Какие эксперты должны обсудить создание сайта?"
   - ❌ Неправильно: "Что ты думаешь о сайте?"

**См. `docs/HOW_TO_USE_EXPERTS_IN_NEW_PROJECT.md` для подробностей.**
