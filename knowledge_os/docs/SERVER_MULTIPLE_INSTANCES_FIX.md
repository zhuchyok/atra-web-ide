# 🔧 ИСПРАВЛЕНИЕ ПРОБЛЕМЫ МНОЖЕСТВЕННЫХ ЭКЗЕМПЛЯРОВ НА СЕРВЕРЕ

## 🚨 **ПРОБЛЕМА**

На сервере могут запускаться несколько экземпляров системы ATRA одновременно, что приводит к:

- Блокировкам базы данных (`database is locked`)
- Нестабильной работе системы
- Ошибкам `talib` и другим проблемам
- Зависанию системы

## ✅ **РЕШЕНИЕ**

Созданы инструменты для предотвращения множественных запусков:

### 1. **Скрипт проверки процессов** (`check_processes.py`)

- Находит все запущенные процессы ATRA
- Показывает информацию о процессах
- Может остановить все процессы
- Проверяет блокировки базы данных

### 2. **Безопасный запуск** (`safe_start.py`)

- Проверяет существующие процессы
- Останавливает лишние экземпляры
- Проверяет базу данных
- Запускает систему с правильными настройками

### 3. **Улучшенный systemd сервис** (`atra_improved.service`)

- Предотвращает множественные запуски
- Автоматически проверяет процессы перед запуском
- Использует безопасный запуск

## 🛠️ **ИНСТРУКЦИИ ДЛЯ СЕРВЕРА**

### **1. Проверка текущего состояния:**

```bash
# Проверяем процессы
python3 check_processes.py

# Проверяем блокировки базы данных
lsof trading.db
```

### **2. Остановка всех процессов:**

```bash
# Останавливаем все процессы ATRA
python3 check_processes.py
# Выберите "y" когда спросит об остановке

# Или принудительно
pkill -f "main.py"
```

### **3. Безопасный запуск:**

```bash
# Запускаем систему безопасно
python3 safe_start.py
```

### **4. Настройка systemd (для автозапуска):**

```bash
# Копируем улучшенный сервис
sudo cp atra_improved.service /etc/systemd/system/

# Перезагружаем systemd
sudo systemctl daemon-reload

# Останавливаем старый сервис
sudo systemctl stop atra.service

# Запускаем новый сервис
sudo systemctl start atra_improved.service

# Включаем автозапуск
sudo systemctl enable atra_improved.service

# Проверяем статус
sudo systemctl status atra_improved.service
```

## 🔍 **ДИАГНОСТИКА ПРОБЛЕМ**

### **Признаки множественных экземпляров:**

- Ошибки `database is locked`
- Высокое использование CPU/RAM
- Нестабильная работа системы
- Ошибки `talib` или других модулей

### **Проверка:**

```bash
# Количество процессов
ps aux | grep main.py | grep -v grep | wc -l

# Должно быть: 1 (или 0 если не запущено)
# Если больше 1 - проблема!

# Проверка блокировок базы данных
lsof trading.db | wc -l
# Должно быть: 0 (или небольшое число)
# Если много - проблема!
```

```bash

```

### **2. Регулярно проверяйте процессы:**

```bash
python3 check_processes.py
```

### **3. Используйте systemd для автозапуска:**

- Предотвращает множественные запуски
- Автоматически перезапускает при сбоях
- Правильно управляет ресурсами

```bash
# Проверка статуса сервиса
sudo systemctl status atra_improved.service

# Просмотр логов
sudo journalctl -u atra_improved.service -f

# Проверка процессов
python3 check_processes.py
```
