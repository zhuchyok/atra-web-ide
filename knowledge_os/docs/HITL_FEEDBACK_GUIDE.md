# 📝 Руководство по кнопкам обратной связи (HITL)

## 🎯 Для чего нужны кнопки?

Кнопки **"👍 Подтверждаю"**, **"👎 Ошибка"** и **"🛠 Комментарий"** — это система **Human-in-the-Loop (HITL) feedback**, которая позволяет системе **обучаться на ваших оценках** сигналов.

### Как это работает:

1. **Вы оцениваете сигнал** → нажимаете кнопку
2. **Система сохраняет ваш фидбек** → в таблицу `signal_feedback` в БД
3. **Агент `FeedbackAggregator`** → собирает все фидбеки и создаёт "уроки"
4. **Агент `signal_live`** → использует эти уроки для улучшения будущих сигналов

---

## 🔘 Описание кнопок

### 1. **👍 Подтверждаю** (`confirm`)

**Когда использовать:**

- Сигнал выглядит правильным
- Вход, TP, SL рассчитаны корректно
- Технический анализ соответствует вашей оценке

**Что происходит:**

- Система записывает: "сигнал подтверждён пользователем"
- Это **положительный пример** для обучения
- Помогает системе понять, какие паттерны работают

**Пример использования:**

```
Сигнал: DOGEUSDT SHORT @ 0.17071
→ Вы видите, что RSI перекуплен, MACD медвежий, BTC тренд вниз
→ Нажимаете "👍 Подтверждаю"
→ Система запоминает: "такие условия → хороший сигнал"
```

---

### 2. **👎 Ошибка** (`reject`)

**Когда использовать:**

- Сигнал явно неправильный
- Направление не соответствует рынку
- TP/SL рассчитаны некорректно
- Технический анализ неверный

**Что происходит:**

- Система записывает: "сигнал помечен как ошибочный"
- Это **отрицательный пример** для обучения
- Система анализирует, что пошло не так, и корректирует логику

**Пример использования:**

```
Сигнал: BTCUSDT LONG @ 45000
→ Вы видите, что цена уже на максимуме, RSI > 80
→ Нажимаете "👎 Ошибка"
→ Система запоминает: "такие условия → плохой сигнал, нужно фильтровать"
```

**Важно:** После нажатия "👎 Ошибка" система отправит вам сообщение:

```
🚨 Зафиксировано: сигнал помечен как ошибочный.
Команда проверит детали.
```

---

### 3. **🛠 Комментарий** (`comment`)

**Когда использовать:**

- Нужно указать конкретную проблему
- Хотите объяснить, что не так (или что хорошо)
- Нужно уточнить детали

**Что происходит:**

1. Нажимаете **"🛠 Комментарий"**
2. Система просит: _"Напишите комментарий следующим сообщением"_
3. Вы пишете текст (например: _"SL слишком узкий"_ или _"TP1 уже достигнут"_)
4. Комментарий сохраняется вместе с фидбеком

**Пример использования:**

```
Сигнал: ETHUSDT SHORT @ 2500
→ Вы видите, что сигнал правильный, но SL = 2% слишком узкий
→ Нажимаете "🛠 Комментарий"
→ Пишете: "SL слишком узкий, нужно минимум 3%"
→ Система запоминает: "для ETHUSDT нужен SL >= 3%"
```

**Формат комментария:**

- Можете писать свободным текстом
- Примеры: _"SL узкий"_, _"TP1 уже пройден"_, _"Объём низкий"_, _"BTC тренд не учтён"_
- Комментарий сохраняется в БД и используется для анализа

## 🔄 Как система использует ваш фидбек

### Шаг 1: Сбор фидбека

```
Вы нажимаете кнопку
    ↓
Сохранение в таблицу signal_feedback
    ↓
Связь с конкретным сигналом (signal_key, symbol, direction)
```

### Шаг 2: Агрегация (каждые 72 часа)

```
Скрипт: scripts/process_feedback.py
    ↓
FeedbackAggregator собирает все фидбеки
    ↓
Создаёт "уроки" (lessons) для агента signal_live
```

### Шаг 3: Применение уроков

```
Агент signal_live загружает уроки
    ↓
Использует их для:
  - Фильтрации похожих сигналов
  - Корректировки параметров (SL, TP, confidence)
  - Улучшения технического анализа
```

### Пример урока:

```json
{
  "agent": "signal_live",
  "issue": "hitl_reject",
  "count": 5,
  "recommendation": "Проверить RSI > 80 перед генерацией LONG сигналов",
  "samples": [
    {
      "symbol": "BTCUSDT",
      "direction": "LONG",
      "comment": "RSI перекуплен",
      "created_at": "2025-11-12 10:30:00"
    }
  ]
}
```

## ⚙️ Технические детали

### Таблица `signal_feedback`:

```sql
CREATE TABLE signal_feedback (
    id INTEGER PRIMARY KEY,
    signal_key TEXT,           -- Связь с сигналом
    symbol TEXT NOT NULL,
    direction TEXT,
    user_id INTEGER NOT NULL,
    chat_id INTEGER,
    message_id INTEGER,
    feedback_type TEXT NOT NULL,  -- 'confirm', 'reject', 'comment'
    comment TEXT,                 -- Ваш комментарий (если был)
    metadata TEXT,                -- Дополнительные данные
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### Обработка кнопок:

- **Файл:** `telegram_handlers.py` → `handle_feedback_button()`
- **Сохранение:** `acceptance_database.py` → `record_feedback()`
- **Агрегация:** `observability/feedback.py` → `FeedbackAggregator`

## 🎓 Рекомендации по использованию

### ✅ Делайте:

- **Оценивайте сигналы регулярно** — чем больше фидбека, тем лучше система обучается
- **Используйте "Комментарий"** для конкретных проблем — это помогает точнее корректировать логику
- **Отмечайте "Ошибка"** для явно неправильных сигналов — это защищает от повторения

### ❌ Не делайте:

- **Не нажимайте кнопки случайно** — это искажает обучение
- **Не игнорируйте плохие сигналы** — лучше отметить "Ошибка", чтобы система исправилась

## 🚀 Автоматическая обработка

### Скрипт обработки фидбека:

```bash
# Запускается автоматически (через cron) или вручную:
python scripts/process_feedback.py --db trading.db --lookback-hours 72
```

### Что делает скрипт:

1. Собирает фидбеки за последние 72 часа
2. Агрегирует их в "уроки"
3. Сохраняет в `configs/guidance/signal_live.json`
4. Экспортирует в `configs/prompts/signal_live.yaml` и `docs/guidance/signal_live.md`

## ❓ FAQ

**Q: Нужно ли нажимать кнопки на каждый сигнал?**  
A: Нет, только если есть что отметить (хороший или плохой сигнал).

**Q: Что если я случайно нажал не ту кнопку?**  
A: Можно отправить комментарий с уточнением, система учтёт оба фидбека.

**Q: Как быстро система применит мой фидбек?**  
A: Обычно через 1-3 дня после обработки скриптом `process_feedback.py`.

**Q: Видят ли другие пользователи мой фидбек?**  
A: Нет, фидбек привязан к вашему `user_id` и используется только для обучения системы.

**Q: Можно ли удалить свой фидбек?**  
A: Технически можно через SQL, но лучше отправить новый фидбек с уточнением.
