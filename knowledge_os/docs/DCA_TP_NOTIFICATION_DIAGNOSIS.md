# Диагностика проблемы с уведомлениями TP для DCA позиций

**Дата:** 5 октября 2025
**Статус:** 🔍 Детальная диагностика

## 🐛 Проблема

Пользователь сообщил:

> "был сигнал дца для TUTUSDT
> я усреднился по данному сигналу
> тп1 и тп2 были достигнуты и позиция закрылась
> но уведомления о тп1 и тп2 не приходили"

### Сигнал DCA:

```
📈 DCA позиция добавлена!

🔸 Символ: TUTUSDT
🔸 DCA #3
🔸 Цена входа: 0.10
🔸 Количество: 1308.768751
🔸 Плечо: 5.0x
🔸 Риск: 130.00
🔸 Сумма входа: 130
🔸 Средняя цена: 0.10
🔸 TP1: 0.10 (+0.81% / +4.05% с плечом)
🔸 TP2: 0.10 (+0.98% / +4.89% с плечом)
```

### Результат:

- ✅ Позиция закрылась по TP1 и TP2
- ❌ Уведомления о достижении TP1 и TP2 НЕ пришли

## 🔍 Первичная диагностика

### ✅ Обновление TP1 и TP2 работает ПРАВИЛЬНО

**Файл:** `telegram_handlers.py`, строки 1977-1980

```python
# Обновляем TP во всех открытых позициях символа
for p in symbol_positions:
    p['tp1'] = tp1_price_new
    p['tp2'] = tp2_price_new
```

Система **ДЕЙСТВИТЕЛЬНО обновляет TP1 и TP2** в позициях после DCA! Это означает, что проблема в другом месте.

## 🔍 Возможные причины

### 1. ❓ Проблема с сохранением данных

**Проверить:**

- Сохраняются ли обновленные TP1 и TP2 в БД после обновления?
- Синхронизируются ли данные между `user_data` и БД?

**Код сохранения (строка 1991):**

```python
db.save_user_data(user_id, user_data)
```

**Возможная проблема:**

- Данные могут не сохраняться из-за ошибки
- Данные могут сохраняться, но не синхронизироваться между процессами

### 2. ❓ Проблема с флагом `tp1_notified`

**Проверить:**

- Сбрасывается ли флаг `tp1_notified` после обновления TP1?
- Проверяет ли `check_take_profits()` флаг `tp1_notified` для DCA позиций?

**Код проверки TP1 в `signal_live.py` (строки 10747-10752):**

```python
if (
    tp1_reached
    and pos.get("stage") == "open"
    and not bool(pos.get("tp1_notified"))
):
```

**Возможная проблема:**

- После обновления TP1 флаг `tp1_notified` остается `True` от предыдущего TP1
- Система не отправляет уведомление, так как считает, что TP1 уже был достигнут

### 3. ❓ Проблема с stage позиции

**Проверить:**

- Сбрасывается ли `stage` позиции на `"open"` после обновления TP1 и TP2?
- Проверяет ли `check_take_profits()` stage для DCA позиций?

**Код проверки TP1 в `signal_live.py` (строки 10747-10752):**

```python
if (
    tp1_reached
    and pos.get("stage") == "open"  # Проверка stage
    and not bool(pos.get("tp1_notified"))
):
```

**Возможная проблема:**

- После обновления TP1 stage остается `"tp1_reached"` или другим значением
- Система не отправляет уведомление, так как считает, что TP1 уже был достигнут

### 4. ❓ Проблема с синхронизацией между процессами

**Проверить:**

- Синхронизируются ли данные между `telegram_handlers.py` (обновление TP) и `signal_live.py` (проверка TP)?
- Загружаются ли обновленные TP из БД в `signal_live.py`?

**Код загрузки данных в `signal_live.py` (строка 10470):**

```python
user_data_dict = load_user_data_for_signals()
```

**Возможная проблема:**

- Данные обновляются в `telegram_handlers.py`, но не синхронизируются с `signal_live.py`
- `signal_live.py` продолжает использовать старые TP из кэша
