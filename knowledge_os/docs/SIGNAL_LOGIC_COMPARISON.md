## 📊 ОБЩИЙ ОБЗОР

### Торговый сигнал (эталон)

- **Функция проверки**: `should_send_signal(df, i, side, price, user_id, symbol)`
- **Использование**: Для новых торговых сигналов
- **Цель**: Предотвращение спама и проверка актуальности

### DCA сигнал

- **Функция проверки**: `should_send_dca_signal(symbol, user_id, side, price)`
- **Использование**: Для DCA сигналов (усреднение позиций)
- **Цель**: Предотвращение точных дубликатов с коротким таймаутом

## 🎯 КЛЮЧЕВЫЕ РАЗЛИЧИЯ

### 1. **Строгость проверки**

- **Торговый сигнал**: 4 комплексные проверки
- **DCA сигнал**: 1 простая проверка

### 2. **Временные рамки**

- **Торговый сигнал**: 5 минут таймаут
- **DCA сигнал**: 30 секунд таймаут

### 3. **Точность**

- **Торговый сигнал**: Динамический tolerance (0.5-2%)
- **DCA сигнал**: Фиксированный tolerance (0.1%)

### 4. **Цель**

- **Торговый сигнал**: Предотвращение спама и проверка качества
- **DCA сигнал**: Только предотвращение точных дубликатов

### 5. **Кнопки**

- **Торговый сигнал**: Без кнопок
- **DCA сигнал**: С кнопками принятия

### 6. **Задержки**

- **Торговый сигнал**: Без задержек
- **DCA сигнал**: 3 секунды между сообщениями

## ✅ ЗАКЛЮЧЕНИЕ

Логика DCA сигналов **правильно отличается** от логики торговых сигналов:

1. **DCA сигналы более мягкие** - это правильно, так как цель усреднение
2. **Короткий таймаут** - позволяет чаще усредняться
3. **Высокая точность** - предотвращает только точные дубликаты
4. **Кнопки принятия** - для удобства пользователя
5. **Задержки** - для предотвращения flood control
