# 🔧 ИСПРАВЛЕНИЕ ПРОБЛЕМЫ С НЕСООТВЕТСТВИЕМ ПЛЕЧА

## 🎯 ПРОБЛЕМА

В сигнале отображалось одно плечо, а после принятия использовалось другое:

### Пример проблемы:

```
🟢 НОВЫЙ ТОРГОВЫЙ СИГНАЛ
📊 Символ: ENAUSDT
⚠️ Риск: 4.64% | ⚡ Плечо: x6  ← В сигнале показывается x6
```

```
✅ Сигнал принят!
Используемое плечо: x3  ← После принятия используется x3
```

## 🔍 АНАЛИЗ ПРОБЛЕМЫ

### **Причина несоответствия:**

1. **В сигнале** плечо рассчитывается динамически в `signal_live.py`:

   ```python
   dynamic_leverage = get_dynamic_leverage(df, current_index, base_leverage)
   ```

   - Учитывает волатильность, тренд, базовое плечо пользователя
   - Может давать значения от 0.5 до 20

2. **В команде `/accept`** плечо может переопределяться:

   ```python
   if dynamic_leverage is not None:
       leverage = dynamic_leverage  # Используем переданное
   elif trade_mode == "futures":
       leverage = user_data.get("leverage", 1)  # Или из настроек
       if leverage <= 1:
           leverage = calculate_user_leverage(...)  # Или пересчитываем
   ```

3. **Проблема**: Логика переопределения плеча работала некорректно

## ✅ ИСПРАВЛЕНИЕ

### **1. Улучшена логика определения плеча**

Добавлена четкая логика приоритетов:

```python
# Правильное определение плеча для фьючерсов
if dynamic_leverage is not None:
    # Если динамическое плечо передано в команде, используем его
    leverage = dynamic_leverage
    print(f"[DEBUG] Используем переданное динамическое плечо: {leverage}")
elif trade_mode == "futures":
    # Используем динамическое плечо из настроек пользователя
    leverage = user_data.get("leverage", 1)
    # Если плечо не установлено или меньше 2, пересчитываем его
    if leverage <= 1:
        deposit = user_data.get("deposit", 0)
        filter_mode = user_data.get("filter_mode", "enhanced_bollinger")
        leverage = calculate_user_leverage(deposit, "futures", filter_mode)
        print(f"[DEBUG] Пересчитали плечо: {leverage}")
else:
    leverage = 1  # Для SPOT всегда 1x
```

### **2. Добавлено логирование**

Добавлены отладочные сообщения для отслеживания:

- Какое плечо передано в команде
- Какое плечо используется после обработки
- Когда происходит пересчет плеча

### **3. Приоритеты плеча**

Теперь система использует четкие приоритеты:

1. **Высший приоритет**: Динамическое плечо из сигнала (если передано)
2. **Средний приоритет**: Плечо из настроек пользователя
3. **Низший приоритет**: Автоматический расчет на основе депозита и режима
