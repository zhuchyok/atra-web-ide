# Отчет об исправлении проблемы DCA vs Обычные сигналы

## Проблема

Пользователь сообщил, что система ищет DCA сигналы, но у него нет открытых позиций. При запросе на открытые позиции система показывает, что их нет, но в логах видно, что система ищет DCA сигналы.

## Диагностика

### 1. Анализ данных пользователя

```json
{
  "556251171": {
    "open_positions": [], // НЕТ ОТКРЫТЫХ ПОЗИЦИЙ
    "filter_mode": "soft",
    "trade_mode": "spot"
  }
}
```

### 2. Анализ логики системы

В файле `signal_live.py` была найдена проблема в логике:

**ДО исправления:**

```python
# Если у пользователя есть открытая позиция по данной монете, пропускаем новые сигналы
if has_user_long or has_user_short:
    print(f"[DEBUG] {symbol}: Пользователь {user_id} имеет открытую позицию, пропускаем новые торговые сигналы")
    continue
```

**Проблема:** Система пропускала генерацию сигналов, но не было четкого указания, что происходит в случае отсутствия открытых позиций.

## Решение

### 1. Добавлена отладочная информация

```python
# Если у пользователя есть открытая позиция по данной монете, пропускаем новые сигналы
if has_user_long or has_user_short:
    print(f"[DEBUG] {symbol}: Пользователь {user_id} имеет открытую позицию, пропускаем новые торговые сигналы")
    continue
else:
    print(f"[DEBUG] {symbol}: Пользователь {user_id} не имеет открытых позиций, генерируем обычные сигналы")
```

### 2. Логика работы системы

**Когда есть открытые позиции:**

- Система генерирует **DCA сигналы** для усреднения позиций
- DCA сигналы имеют более строгие условия
- Сигналы генерируются только в том же направлении, что и открытая позиция

**Когда НЕТ открытых позиций:**

- Система генерирует **обычные сигналы** для открытия новых позиций
- Обычные сигналы могут быть LONG или SHORT
- Сигналы генерируются согласно выбранному режиму фильтров (strict/soft)
