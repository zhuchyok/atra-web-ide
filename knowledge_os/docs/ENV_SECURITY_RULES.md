## 📁 СТРУКТУРА ФАЙЛОВ

### 1. `.env` (РЕАЛЬНЫЕ КЛЮЧИ) ✅

- **Статус:** В `.gitignore` - НЕ коммитится
- **Назначение:** Хранить реальные API ключи и секреты
- **Содержимое:** Реальные значения всех ключей
- **Безопасность:** ✅ Защищен от коммита

### 2. `env` (ШАБЛОН) ✅

- **Статус:** Может быть закоммичен (без реальных ключей)
- **Назначение:** Шаблон конфигурации
- **Содержимое:** Все переменные с пустыми значениями или примерами
- **Безопасность:** ✅ Не содержит реальных ключей

### 3. `env.prod` / `env.dev` (ШАБЛОНЫ) ✅

- **Статус:** Могут быть закоммичены (без реальных ключей)
- **Назначение:** Шаблоны для разных окружений
- **Содержимое:** Настройки без реальных ключей
- **Безопасность:** ✅ Не содержат реальных ключей

## 🔧 ПРАВИЛЬНАЯ НАСТРОЙКА

### Шаг 1: Создайте `.env` файл

```bash
# Скопируйте шаблон
cp env .env

# Или создайте вручную
touch .env
```

### Шаг 2: Добавьте реальные ключи в `.env`

```bash
# Отредактируйте .env
nano .env

# Добавьте реальные значения:
BITGET_API_KEY=your_real_api_key_here
BITGET_SECRET_KEY=your_real_secret_key_here
BITGET_PASSPHRASE=your_real_passphrase_here
TELEGRAM_TOKEN=your_real_telegram_token_here
```

### Шаг 3: Убедитесь, что `.env` в `.gitignore`

```bash
# Проверьте .gitignore
grep "\.env" .gitignore

# Должно быть:
# *.env
# env
```

## 🔍 ПРОВЕРКА БЕЗОПАСНОСТИ

### Перед коммитом проверьте:

```bash
# 1. Проверьте, что .env в .gitignore
grep "\.env\|^env$" .gitignore

# 2. Проверьте, что в env нет реальных ключей
grep -E "BITGET_API_KEY=|TELEGRAM_TOKEN=" env | grep -v "^#"

# 3. Проверьте статус git
git status

# Убедитесь, что .env НЕ в списке измененных файлов
```

## 📝 ПРИОРИТЕТ ЗАГРУЗКИ ПЕРЕМЕННЫХ

Система загружает переменные в следующем порядке:

1. **`.env`** (приоритет) - реальные ключи
2. `ATRA_ENV_FILE` (переменная окружения)
3. `env.prod` / `env.dev` (в зависимости от `ATRA_ENV`)
4. `env` (шаблон, fallback)

Это означает, что `.env` всегда имеет приоритет над другими файлами.
