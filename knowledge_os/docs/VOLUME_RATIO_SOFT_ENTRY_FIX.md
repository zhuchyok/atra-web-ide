# 🔧 ИСПРАВЛЕНИЕ: VOLUME_RATIO БЛОКИРУЕТ СИГНАЛЫ В SOFT РЕЖИМЕ

## 📋 ПРОБЛЕМА

**Симптомы:**

- `soft_entry_signal` возвращает сигналы
- Но все сигналы блокируются из-за `volume_ratio < 0.8`
- На недельных данных BNBUSDT: `volume_ratio = 0.23-0.35`

**Текущая логика:**

```python
# src/signals/core.py, строка 388, 401
volume_ratio > 0.8,  # Минимальный объем (ослаблено)
```

**Проблема:**

- На недельных данных объем часто ниже среднего
- Порог 0.8 слишком строгий для soft режима
- Блокирует все сигналы, даже при сильных других индикаторах

---

## 💡 ВАРИАНТЫ РЕШЕНИЯ

### ✅ ВАРИАНТ 1: Снизить порог для soft режима (РЕКОМЕНДУЕТСЯ)

**Идея:** Снизить порог `volume_ratio` для soft режима до 0.3-0.5

**Плюсы:**

- Простое решение
- Сохраняет защиту от экстремально низкого объема
- Позволяет сигналам проходить при умеренном объеме

**Минусы:**

- Может пропустить сигналы с очень низким объемом (риск ликвидности)

**Реализация:**

```python
# В soft_entry_signal
volume_ratio > 0.3,  # Минимальный объем (ослаблено для soft режима)
```

**Параметры для подбора:**

- `0.3` - очень мягкий (может пропустить слабые сигналы)
- `0.4` - умеренный (баланс между качеством и количеством)
- `0.5` - более строгий (лучше качество, меньше сигналов)

---

### ✅ ВАРИАНТ 2: Адаптивный порог по таймфрейму

**Идея:** Использовать разные пороги в зависимости от таймфрейма

**Плюсы:**

- Учитывает специфику разных таймфреймов
- Более точная фильтрация

**Минусы:**

- Требует определения таймфрейма
- Более сложная логика

**Реализация:**

```python
# Определяем таймфрейм по количеству свечей за период
if timeframe == '1w' or timeframe == '1d':
    volume_threshold = 0.3  # Для долгосрочных таймфреймов
elif timeframe == '1h' or timeframe == '4h':
    volume_threshold = 0.5  # Для средних таймфреймов
else:
    volume_threshold = 0.8  # Для краткосрочных таймфреймов

volume_ratio > volume_threshold,
```

---

### ✅ ВАРИАНТ 3: Относительный порог (процентиль)

**Идея:** Использовать процентиль вместо фиксированного значения

**Плюсы:**

- Адаптируется к рыночным условиям
- Учитывает историческое распределение volume_ratio

**Минусы:**

- Требует расчета процентилей
- Более сложная реализация

**Реализация:**

```python
# Рассчитываем 25-й процентиль volume_ratio за последние 100 свечей
volume_ratio_percentile = df['volume_ratio'].rolling(100).quantile(0.25).iloc[i]
volume_threshold = max(0.2, volume_ratio_percentile)  # Минимум 0.2

volume_ratio > volume_threshold,
```

---

### ✅ ВАРИАНТ 4: Взвешенный подход (компенсация сильными индикаторами)

**Идея:** Если другие индикаторы сильные, можно ослабить требование к volume_ratio

**Плюсы:**

- Учитывает общую силу сигнала
- Более гибкая фильтрация

**Минусы:**

- Сложная логика взвешивания
- Требует калибровки весов

**Реализация:**

```python
# Рассчитываем силу других индикаторов
indicator_strength = (
    (trend_strength > 0.5) * 0.3 +
    (momentum > 0) * 0.2 +
    (rsi < 40) * 0.2 +
    (volatility > 1.0) * 0.3
)

# Адаптивный порог volume_ratio
if indicator_strength > 0.7:
    volume_threshold = 0.3  # Сильные индикаторы - снижаем порог
elif indicator_strength > 0.5:
    volume_threshold = 0.5  # Средние индикаторы - умеренный порог
else:
    volume_threshold = 0.8  # Слабые индикаторы - строгий порог

volume_ratio > volume_threshold,
```

**Минусы:**

- Высокий риск ликвидности
- Может пропустить слабые сигналы
