# Отчет об исправлении отображения открытых позиций в signal_stats

## Проблема

В команде `/signal_stats` открытые позиции показывали пустые данные или некорректно отображались значения.

## Причина проблемы

1. **Неправильное форматирование чисел** - код пытался форматировать `entry_price`, `tp1`, `tp2` как числа с 6 знаками после запятой, но если эти значения равны 0 или None, то форматирование не работало
2. **Отсутствие проверки на пустые значения** - если позиция не имела установленной цены входа (`entry_price`), то показывалось 0.000000
3. **Неполная информация** - не отображались объем, стадия и плечо позиций

## Внесенные изменения

### 1. Добавлено безопасное форматирование

**Было:**

```python
entry_price = pos.get("entry_price", 0)
tp1 = pos.get("tp1", 0)
tp2 = pos.get("tp2", 0)

try:
    msg += (
        f"{side_emoji} <code>{symbol}</code> {side.upper()}\n"
        f"💰 Вход: <code>{entry_price:.6f}</code>\n"
        f"🎯 TP1: <code>{tp1:.6f}</code> | 🚀 TP2: <code>{tp2:.6f}</code>\n\n"
    )
except (ValueError, TypeError):
    # Безопасное форматирование
```

**Стало:**

```python
entry_price = pos.get("entry_price")
tp1 = pos.get("tp1")
tp2 = pos.get("tp2")
qty = pos.get("qty", 0)
stage = pos.get("stage", "open")
pos_leverage = pos.get("leverage")

pos_str = f"{side_emoji} <code>{symbol}</code> {side.upper()}\n"

# Безопасное форматирование цены входа
if entry_price is not None and entry_price > 0:
    pos_str += f"💰 Вход: <code>{entry_price:.6f}</code>\n"
else:
    pos_str += f"💰 Вход: <code>Ожидает входа</code>\n"

# Безопасное форматирование TP1
if tp1 is not None and tp1 > 0:
    pos_str += f"🎯 TP1: <code>{tp1:.6f}</code>"
else:
    pos_str += f"🎯 TP1: <code>Не установлен</code>"

# Безопасное форматирование TP2
if tp2 is not None and tp2 > 0:
    pos_str += f" | 🚀 TP2: <code>{tp2:.6f}</code>\n"
else:
    pos_str += f" | 🚀 TP2: <code>Не установлен</code>\n"

# Безопасное форматирование объема
if qty and qty > 0:
    pos_str += f"📊 Объём: <code>{qty:.4f}</code>"
else:
    pos_str += f"📊 Объём: <code>Не установлен</code>"

pos_str += f" | Стадия: <code>{stage}</code>"

if pos_leverage:
    pos_str += f" | Плечо: x<code>{pos_leverage}</code>"

msg += pos_str + "\n\n"
```

### 2. Добавлена дополнительная информация

**Новые поля:**

- **Объем (`qty`)** - показывает количество торговых единиц
- **Стадия (`stage`)** - показывает текущую стадию позиции (open, closed и т.д.)
- **Плечо (`leverage`)** - показывает используемое плечо для фьючерсов

### 3. Улучшена обработка ошибок

Убрана сложная логика с `try/except` и заменена на простые проверки условий, что делает код более читаемым и надежным.

## Результат

### Пример отображения открытых позиций в signal_stats:

**Позиция с полными данными:**

```
🟢 BTCUSDT LONG
💰 Вход: 45000.000000
🎯 TP1: 46000.000000 | 🚀 TP2: 47000.000000
📊 Объём: 0.0010 | Стадия: open | Плечо: x1.5
```

**Позиция с неполными данными:**

```
🔴 ETHUSDT SHORT
💰 Вход: Ожидает входа
🎯 TP1: Не установлен | 🚀 TP2: Не установлен
📊 Объём: Не установлен | Стадия: open | Плечо: x2.0
```

**Позиция без плеча:**

```
🟢 SOLUSDT LONG
💰 Вход: 100.000000
🎯 TP1: 105.000000 | 🚀 TP2: 110.000000
📊 Объём: 1.0000 | Стадия: open
```

## Преимущества исправления

1. **Корректное отображение** - все позиции теперь отображаются правильно
2. **Информативность** - пользователь видит статус каждой позиции (ожидает входа, не установлен и т.д.)
3. **Полнота данных** - добавлены объем, стадия и плечо для лучшего понимания позиций
4. **Устойчивость к ошибкам** - код не падает при некорректных данных
5. **Читаемость** - четкое разделение между установленными и неустановленными значениями

## Тестирование

Функция была протестирована с различными сценариями:

- Позиции с полными данными
- Позиции с частичными данными (без цены входа, TP, объема)
- Позиции без плеча
- Отсутствие открытых позиций

Все сценарии работают корректно и отображают понятную информацию пользователю.
