## ✅ ПРОБЛЕМА 1: Неправильный источник данных для TP/SL (ИСПРАВЛЕНО)

**Проблема:**

- В `price_monitor_system.py` и `telegram_handlers.py` мы пытались получить `tp1_price`, `tp2_price`, `sl_price`, `trade_mode` из таблицы `active_positions`
- Но в `active_positions` этих полей НЕТ!
- Данные хранятся в таблице `accepted_signals` (там есть `tp1_price`, `tp2_price`, `sl_price`)

**Решение:**

- ✅ Изменены запросы в `price_monitor_system.py` для получения данных из `accepted_signals` через `signal_key`
- ✅ Изменены запросы в `telegram_handlers.py` для получения данных из `accepted_signals` через `signal_key`
- ✅ `trade_mode` получается из `signals_log` (если есть) или используется значение по умолчанию 'futures'

## ✅ ПРОБЛЕМА 2: Нет интеграции закрытия по Stop Loss (ИСПРАВЛЕНО)

**Проблема:**

- В коде есть проверка SL в `main.py`, но не было интеграции с `TradeTracker` для записи сделок при закрытии по SL
- Нужно было добавить запись в `trades` при срабатывании SL

**Решение:**

- ✅ Найдена функция закрытия по SL в `main.py` (строка 833-839, 900-905)
- ✅ Добавлена интеграция с `TradeTracker` в блоке успешного закрытия маркет-ордером
- ✅ Записываются сделки для всех типов закрытия: SL, TP1, TP2
- ✅ Данные получаются из `signals_log` и `accepted_signals` аналогично TP1/TP2

**Реализация:**

- При закрытии позиции (SL, TP1, TP2) в `main.py` добавлен блок записи в TradeTracker
- Определение `exit_reason` из `close_reason` (SL/TP1/TP2/MANUAL)
- Получение данных позиции из `signals_log`
- Получение TP/SL цен из `accepted_signals`
- Запись полной информации о сделке в таблицу `trades`

## ✅ ПРОБЛЕМА 3: В `active_positions` нет поля `trade_mode` (ОБХОДНОЙ ПУТЬ РЕАЛИЗОВАН)
